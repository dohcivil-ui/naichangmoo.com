# อ่านเส้นในแบบให้เป็นรูปทรงที่เชื่อถือได้

## กฎเดียวที่ต้องจำ

**ในแบบก่อสร้างไม่มี "พิกเซลดำ" มีแต่ของสามชนิดที่หน้าตาเหมือนกันแต่ความหมายคนละเรื่อง**
โค้ดที่มองมันเป็นสิ่งเดียวกันจะได้พื้นที่ผิดเสมอ และผิดแบบเงียบ ๆ ที่ตรวจไม่เจอจากตัวเลข

| ชนิด | หน้าตาในแบบ | ต้องทำอย่างไร |
|---|---|---|
| **ผิวผนัง** | เส้นตรงยาวหลายเมตร มีคู่ขนานห่างกันเท่าความหนาผนัง ระหว่างคู่มักมีลายขีด | **กั้น** — ขอบของห้องต้องแนบเส้นนี้พอดี |
| **หน้าเสา** | สั้นกว่าผนังมาก แต่เป็นโครงสร้าง มักฝังอยู่ในแนวผนังหรือยื่นเข้ามาในห้อง | **กั้น** — ขอบต้องเดินอ้อมเข้าไปกอด ไม่ตัดมุมข้าม |
| **สัญลักษณ์** | กรอบป้ายชนิดพื้นและฝ้า ตัวอักษรชื่อห้อง สามเหลี่ยมบอกระดับ วงโค้งบานสวิงประตู รูปสุขภัณฑ์ เส้นบอกระยะ | **มองข้าม** — ต้องไม่กั้นและต้องไม่กินพื้นที่ |

## เมื่อเจ้าของงานขีดเส้นไกด์ให้ อ่านมันเป็นข้อกำหนดของรูปทรงทั้งรูป

**นี่คือบทเรียนที่แพงที่สุดของ 2026-09-04** เจ้าของงานส่งภาพที่ขีดเส้นน้ำเงินทับผลลัพธ์
มาให้แปดรอบ แต่ละรอบเขาชี้จุดที่ยังผิด แล้วเราก็ไล่แก้จุดนั้น ทำให้เสียเวลาแปดรอบ
ทั้งที่มันคือความผิดพลาด **สองอย่าง** ที่โผล่ออกมาเป็นอาการหลายจุด

| อาการที่เขาชี้ทีละครั้ง | ความผิดพลาดจริง |
|---|---|
| สัญลักษณ์กินพื้นที่ · ประตูทำให้สีทะลุ · กรอบป้ายดันขอบ · วงสวิงทำให้ขอบอ้อม | **แยกชนิดของเส้นไม่ออก** แก้ครั้งเดียวด้วยการคัดเส้นก่อนไล่สี |
| ขอบไม่แนบผนัง · มุมเสาเพี้ยน · เส้นลากเฉียง · ไฮไลท์กินเสา | **ขอบอยู่ผิดที่และผิดชนิด** แก้ครั้งเดียวด้วยการไล่ขอบแบบเหลี่ยมล้วนแล้วดันไปนั่งกึ่งกลางเส้น |

**วิธีที่ถูก** เอาเส้นไกด์มาถามว่า *รูปทรงนี้ถูกนิยามด้วยกฎอะไร* แล้วหากฎที่อธิบายทุกด้าน
พร้อมกัน · สำหรับผังพื้น กฎคือ **"สี่เหลี่ยมมุมฉาก ขอบอยู่บนกึ่งกลางเส้นผนัง หักเป็นขั้นอ้อมเสา"**
ซึ่งอธิบายทุกอาการข้างบนได้หมดในประโยคเดียว

**อย่าไล่แก้ทีละจุดที่เขาชี้** เพราะแต่ละจุดคือ*อาการ* ไม่ใช่*โรค* และการแก้ทีละอาการ
มักสร้างอาการใหม่ เช่น กติกาเสาที่เพิ่มเข้าไปกลายเป็นเสาปลอมทุกบานประตูในรอบถัดมา

## สิ่งที่ผิดมาแล้วจริง อย่าเดินซ้ำ

### หนึ่ง — ไล่สีบนพิกเซลดิบ แล้วสีทะลุออกทั้งชั้น
2026-09-01 คลิกห้องที่มีช่องประตู ได้ 266 ตร.ม. จากห้องที่จริง ๆ ราว 20 ตร.ม.
2026-09-04 เกิดซ้ำ ได้ 265.13 ตร.ม. จากห้องราว 7 ตร.ม. · **เพดานสัดส่วนพื้นที่จับไม่ได้**
เพราะหน้ากระดาษ A3 ใหญ่พอที่ 265 ตร.ม. ยังไม่ถึงหนึ่งในสี่ของหน้า
→ ช่องเปิดต้องถูกเชื่อมก่อนไล่สี ไม่ใช่ไล่ไปก่อนแล้วค่อยตรวจว่ารั่วไหม

### สอง — เอาการขยาย-หดรูปทรงมาแก้ปัญหาของเส้น
2026-09-04 ใช้ morphological closing รัศมี 0.40 เมตรกับ**ก้อนพื้นที่**ที่ไล่ได้
กลบสามเหลี่ยมบอกระดับได้จริง แต่ **(ก)** เอากรอบป้ายที่กว้างเกือบ 2 เมตรไม่อยู่
**(ข)** เอาวงสวิงประตูรัศมีเกือบ 1 เมตรไม่อยู่ **(ค)** มนมุมจริงของห้องด้วยรัศมีเดียวกัน
ทำให้ขอบลอยห่างผนัง เจ้าของงานจับได้ทันทีจากรูป ทั้งที่ตัวเลขพื้นที่ดูสมเหตุสมผล
→ **การเพิ่มรัศมีไม่ใช่คำตอบ** รัศมีที่ใหญ่พอจะกลบป้ายได้ จะกินเสาหายและมนมุมจนไม่ใช่ห้อง
→ ปัญหาของเส้นต้องแก้ที่เส้น คือคัดว่าเส้นไหนกั้น ก่อนจะเริ่มไล่สี

### สาม — ตัวเลขถูกไม่ได้แปลว่ารูปถูก
พื้นที่ที่ได้อาจใกล้เคียงของจริงทั้งที่รูปทรงผิดคนละเรื่อง เพราะส่วนที่ขาดกับส่วนที่เกิน
หักกลบกันพอดีโดยบังเอิญ · **ต้องดูรูปทับบนแบบทุกครั้ง ไม่ใช่ดูแค่ตัวเลข**
2026-09-04 เคยรายงานว่าแก้แล้วโดยถ่ายภาพหน้าจอเก็บไว้แต่ไม่ได้เปิดดู ตัวเลขดีขึ้นจริง
แต่รูปยังผิด · **ถ่ายแล้วต้องเปิดดูก่อนพูด**

### สี่ — ลดจุดของขอบด้วย Douglas-Peucker
วิธีนั้นยอมแทนบันไดพิกเซลด้วย**เส้นเฉียง**ถ้าคลาดไม่เกินค่าที่ตั้งไว้ ซึ่งกินมุมเสาไปเป็น
สามเหลี่ยมโดยที่ตัวเลขพื้นที่ยังดูสมเหตุสมผล · องค์อาคารเป็นเหลี่ยม ขอบจึงต้องเป็น
แนวนอนกับแนวตั้งล้วน **โดยโครงสร้างของอัลกอริทึม ไม่ใช่โดยค่าที่ตั้งไว้**
→ ไล่ขอบตามรอยต่อระหว่างพิกเซล (`traceRectilinearOutline`) แล้วยุบเฉพาะขั้นที่สั้นกว่า
`OUTLINE_MIN_STEP_METRES` ซึ่งเป็นความหยาบของภาพ ไม่ใช่รูปทรง

### ห้า — ปล่อยขอบไว้ข้างในเส้นผนัง
การไล่สีหยุดที่พิกเซลมืดตัวแรก ขอบจึงอยู่**ข้างใน**เส้น แต่เส้นที่เขียนในแบบมีความหนา
และมันแทนผิวผนังซึ่งไม่มีความหนา **ผิวจริงอยู่ที่กึ่งกลางเส้น** ต่างกันแค่หนึ่งถึงสองพิกเซล
แต่ผิดทุกด้านเท่ากันหมด → `snapToLinePixels` ดันแต่ละด้านออกไปหากึ่งกลางเส้นที่มันชนอยู่

## ห้ามใช้แบบจำลองภาษาในขั้นนี้

เขียนไว้ที่หัว `src/lib/region-fill.ts` แล้วและยังจริงอยู่ — ห้องเดียวกันต้องได้พื้นที่เท่ากัน
ทุกครั้งที่คลิก ซึ่งแบบจำลองรับประกันให้ไม่ได้ และมันขัดกับจุดขายข้อแรกที่แพลตฟอร์มประกาศไว้ว่า
**ถามซ้ำกี่ครั้งก็ได้คำตอบเดิม** (`src/lib/method-claims.ts`) · ผลพลอยได้ของการไม่ใช้คือ
ไม่มีค่าใช้จ่ายต่อคลิกและทำงานได้แม้ไม่มีเน็ต

**ที่ใช้แบบจำลองได้คือขั้นที่คนกดรับทีละรายการ** เช่น อ่านป้าย `F1` `C1` มาเสนอว่าห้องนี้
ใช้พื้นชนิดไหน ตาม ADR 0019 และ 0024 — ไม่ใช่ขั้นที่คลิกแล้วออกมาเป็นตัวเลขทันที

## หน่วยและการแปลง

- พิกัดทุกจุดที่เก็บลงฐานเป็น **หน่วยหน้ากระดาษ (point)** ไม่ใช่พิกเซลบนจอ — ค่าที่วัดได้
  จึงไม่ขยับเมื่อผู้ใช้ซูม
- ภาพที่ใช้ไล่ขอบคือ**ชั้นวิเคราะห์**ซึ่งความละเอียดคงที่ต่อหน้า ไม่ผูกกับระดับซูม
  ถ้าเผลอไปใช้ภาพที่เห็นบนจอ ห้องเดียวกันที่ซูมต่างกันจะได้รูปคนละรูป
- ค่าคงที่ที่เป็นเมตรอยู่ใน `region-fill.ts` ส่วนตัวฟังก์ชันรับเป็นพิกเซล
  ผู้เรียกแปลงด้วย `analysisScale / pageScale.metresPerPoint`

## กับดักของเครื่องมือทดสอบ ไม่ใช่ของแอป

- **MCP คลิกต่ำกว่าเป้า 46 พิกเซล** วัดไว้เมื่อ 2026-09-04 สั่งคลิกปุ่มที่ (199,127)
  ไปลงจริงที่ (199,172) ทำให้สรุปผิดว่าปุ่มทั้งแถบตาย ทั้งที่คีย์ลัดใช้ได้ปกติ
  → ก่อนสรุปว่าอะไรพัง ให้ดักจับพิกัดจริงด้วย `pointerdown` listener แล้วเทียบกับ
  `getBoundingClientRect` ของเป้า · ชดเชยด้วยการวางกล่องเล็งสูงกว่าเป้า 46 พิกเซล
- **ภาพหน้าจอกับพิกัดหน้าเว็บไม่เท่ากัน** วัดได้ `sx = 1.395·vx` และ `sy = 1.396·vy − 65`
  คาลิเบรตใหม่ทุกครั้งด้วยการวางจุดสีสองจุดที่พิกัดที่รู้ค่า แล้วอ่านจากภาพ
- **dispatch PointerEvent เองบนผืนวาดไม่ได้** state ของ React เพี้ยนหนึ่งจังหวะ
  ต้องใช้ปุ่มเล็ง `#aim-box` ที่ `position:fixed; pointer-events:none` แล้วให้ MCP คลิกที่ uid ของมัน
