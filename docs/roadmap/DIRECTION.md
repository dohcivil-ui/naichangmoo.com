# ทิศทางที่เหลือของแพลตฟอร์มนายช่างหมู

**อนุมัติโดยเจ้าของงาน 2026-08-26** — จัดทำจากโรดแมป v0.63.0, ADR 0001–0017, handoff ล่าสุด และสถานะ `.env` จริง
เอกสารนี้บอกลำดับใหญ่ระหว่างเฟส ส่วนแผนที่รันได้จริงยังอยู่ที่ `roadmap.json` ตามลำดับศักดิ์เดิม

หลักที่เจ้าของงานประกาศ: **ทำเดโมแอปทั้งหมดให้เสร็จก่อนเพื่อหาสมาชิกและตั้งค่าสมาชิก
จากนั้น deploy VPS แล้วค่อยลุยระบบ Hermes 24/7 เป็นงานท้ายสุด**

---

## หกเฟส

### เฟส 1 — เปลือกเดียวทั้งแพลตฟอร์ม + ปิดงาน Landing (กำลังทำ)

- **เป้าหมาย:** ทุกแอปและต้นแบบกลับหน้าหลักได้ หน้าแรกพูดความจริงตามทะเบียน
- **รายการ:** IP-155, IP-156, IP-157 (เปลือกกลาง) · IP-145 (เสร็จ v0.62.0), IP-123 (เสร็จ v0.62.0), IP-146 ·
  IP-147, IP-148, IP-122 · IP-165 (เสร็จ v0.63.0) · หน้า /roadmap จัดกลุ่มตามแอป
- **นิยามเสร็จ:** ไม่มีหน้าใดไม่มีทางกลับหน้าหลัก · `gl-platbar` หายไป · ตรวจใน Edge จริงทั้งเดสก์ท็อปและจอแคบ

### เฟส 2 — เดโมแอปครบตามเกณฑ์ต่อแอป (~3–5 สัปดาห์ ขนานสองเซสชันได้)

- **เป้าหมาย:** แอปทั้ง 7 ใบการ์ดถึงระดับ "เดโมเสร็จ" ตามเกณฑ์สามระดับด้านล่าง
- **รายการ:** PRICEMETR: IP-161, IP-162, IP-163, IP-164, IP-166 · ผู้ช่วยสร้างแผนงาน: IP-143 (+IP-167 S-Curve),
  IP-138, IP-137, IP-139, IP-136, IP-140, IP-144 · ESCALATION K: IP-096, IP-097, IP-098, IP-099, IP-107 ·
  ESTIMETR เก็บตก: IP-064, IP-073, IP-052, IP-070
- **ทำไมมาก่อน deploy:** เดโมคือเครื่องมือหาสมาชิก deploy ของที่ยังไม่มีอะไรให้ดูคือจ่ายค่า VPS เปล่า

### เฟส 3 — ระบบสมาชิกพร้อมรับคนจริง + เอกสารกฎหมาย (~2 สัปดาห์ ขนานท้ายเฟส 2 ได้)

- **เป้าหมาย:** สมัคร → ได้สิทธิ์ → ใช้แอป → หมดอายุ → read-only ครบวงจรจริง และเอกสารที่กฎหมายต้องการครบ
- **รายการ:** IP-093, IP-094, IP-054, IP-058, IP-076, IP-105, IP-108, IP-113, IP-114 ·
  กฎหมาย: IP-129 (terms), IP-111 + IP-112 (consent), IP-126 + IP-127 (นิติบุคคล), IP-175 (privacy policy)
- **เหตุผล:** รับสมาชิกจริงโดยไม่มี terms และ consent คือความเสี่ยง PDPA ที่แก้ย้อนหลังไม่ได้

### เฟส 4 — Deploy VPS + soak test กลุ่มปิด (~1–2 สัปดาห์)

- **คำตอบเรื่อง VPS: ใช่ ไป Hostinger VPS ตาม ADR 0001 — จบเฟส 3 แล้ว deploy ทันที
  ใช้ VPS เป็นสนาม soak test กลุ่มปิดก่อนประกาศรับสมาชิกหนึ่งเฟส**
- เหตุผล: สมาชิกรุ่นแรกต้องเจอบ้านจริงตั้งแต่วันแรก · ปัญหาที่ Vercel ไม่มีวันเจอ (restart, disk, migration
  บนเครื่องจริง) ต้องเจอตอนคนดูมีแค่เรา · deploy ก่อนเดโมเสร็จคือจ่าย operational burden ก่อนพิสูจน์ product
- **รายการ:** IP-168 (Dockerfile), IP-169 (backup), IP-170 (monitoring), IP-171 (โดเมน+TLS+OAuth),
  IP-172 (runbook), IP-173 (soak test)
- `.env` วันนี้พร้อม 10 คีย์ ขาด 13 คีย์: R2 ทั้งชุด (5), REDIS_URL, STRIPE 2, LINE/Facebook OAuth 4 —
  R2/Redis เลื่อนไปเฟส 5–6 ได้ · Stripe รอ IP-081 · ต้องเคาะว่าเปิดตัวด้วย Google อย่างเดียวหรือรอ LINE

### เฟส 5 — เปิดรับสมาชิกสาธารณะ + เปิดรับชำระเงิน

- **หลักการตั้งราคา (เจ้าของงานประกาศ 2026-08-27):** แอปของเราตั้งราคาเท่าคู่แข่งไม่ได้
  เพราะทุกแอปมีผู้ช่วย AI ในตัว — ราคาต้องสะท้อนมูลค่าของผู้ช่วยอัจฉริยะ ไม่ใช่เทียบราคาชนกับ
  เครื่องมือที่ไม่มี AI งานตั้งราคาทุกชิ้น (IP-081, IP-085, ราคาของ PRICEMETR ที่ยังไม่เคาะ)
  ต้องเริ่มจากหลักข้อนี้ และตัวเลขทั้งหมดยังอยู่ที่ /pricing ที่เดียวตาม ADR 0011
- **รายการ:** IP-081 (payment provider + webhook + ADR ใหม่ตาม ADR 0011), IP-085, IP-079, IP-106, IP-109, IP-174 (อีเมลระบบ)
- **เส้นตายจริง:** เปิดรับสมาชิกได้ก่อนมีระบบเก็บเงิน (trial + member_free ฟรี) แต่นาฬิกา trial 7 วัน
  ของสมาชิกที่อยากจ่ายคนแรกคือเส้นตายของ IP-081 — เริ่มเลือก provider ตั้งแต่เฟส 4 ขนาน soak

### เฟส 6 — Hermes 24/7 (ท้ายสุด ตามคำสั่งเจ้าของงาน)

- **รายการ:** IP-176 — Redis queue + worker + container แยกสิทธิ์ต่ำสุด ตามกรอบ ADR 0004
  (อ่านหลักฐาน AI Takeoff และสรุปประเด็นเท่านั้น ห้ามเขียนข้อมูลธุรกิจ)
- **เงื่อนไขเริ่ม:** มีสมาชิกจริงใช้ ESTIMETR แล้ว — ไม่มีงาน Takeoff จริง Hermes ไม่มีอะไรให้ตรวจ

## เกณฑ์ "เดโมเสร็จ" สามระดับ — ไม่ต้องเท่ากันทุกแอป

**ระดับ A ใช้ทำงานจริงได้หนึ่งงานจบ** (เส้นทางหลักครบ บันทึกลงฐานข้อมูล พิมพ์/ส่งออกได้)

| แอป | เกณฑ์ผ่าน |
|---|---|
| ESTIMETR | ถึงระดับนี้แล้วเกือบหมด — ปิด IP-064, IP-073 และ IP-052/IP-070 |
| PRICEMETR | สามแหล่งดูได้ (เสร็จแล้ว) + ราคาอยู่รอด restart (IP-162) + หยิบข้ามเครื่องส่งเข้า ESTIMETR (IP-163) + สิทธิ์ฝั่งเซิร์ฟเวอร์ (IP-164) |
| ผู้ช่วยสร้างแผนงาน | สิบเมนู (IP-137) + Gantt/CPM (IP-143) + Excel/LINE (IP-138) + **Postgres (IP-139) บังคับ** — เดโมที่ข้อมูลหายเมื่อเปลี่ยนเครื่องทำลายความเชื่อ |

**ระดับ B เดินได้หนึ่งเส้นทางพร้อมคำเตือนขอบเขต:** ESCALATION K — คำนวณค่า K หนึ่งสัญญาแล้วพิมพ์ใบรายการได้
(IP-098, IP-099, IP-096, IP-097, IP-107)

**ระดับ C การ์ดพูดความจริงก็พอ:** RCOPT · TRAFFIC SIGN — การ์ด + สถานะจากทะเบียนตาม ADR 0015 ·
LAND ACQUISITION V2 — การ์ด doh_staff_only ห้ามแตะ legacy ตาม PROJECT.md

**เกณฑ์ร่วม:** เปลือกกลางตาม IP-155 · การ์ดพูดหมวดสิทธิ์ ไม่พูดตัวเลขเงิน · S-Curve เป็นเมนูในแอปแผนงาน (IP-167)

## ความเสี่ยงหลักและวิธีกัน

1. **สองเซสชันบนสาขาเดียว** — คงวินัย git add ทีละไฟล์ · ผนวกการแก้ release script ให้เทียบเฉพาะไฟล์ที่รุ่นแตะเข้า IP-172
2. **ข้อมูลราชการยังไม่มีวิศวกรรับรอง** (IP-070, IP-097, IP-052/161) — ให้การรับรองเป็นเงื่อนไขเปิดสมาชิกของแอปนั้น ไม่ใช่งานตามหลัง
3. **เปิดรับสมาชิกแล้วไม่มีทางจ่ายเงินทัน** — trial 7 วันคือเส้นตายของ IP-081
4. **PDPA/นิติบุคคลแก้ย้อนหลังไม่ได้** — IP-126/127/129/111/112/175 เป็น gate ของเฟส 4 ไม่ใช่ nice-to-have
5. **VPS เดี่ยวไม่มี backup** — IP-162 + IP-169 ต้องเสร็จก่อนมีข้อมูลสมาชิกจริง และ backup ที่ไม่เคยกู้จริงถือว่ายังไม่มี
