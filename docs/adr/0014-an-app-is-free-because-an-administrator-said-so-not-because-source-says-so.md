# ADR 0014: แอปหนึ่งใช้ฟรีเพราะผู้ดูแลประกาศ ไม่ใช่เพราะมีคนพิมพ์ไว้ในโค้ด

**Status:** Accepted — extends the registry scope granted in ADR 0013

## Context

การ์ด "สมาชิกใช้ฟรี" บนหน้า `/pricing` พิมพ์ชื่อแอปไว้ใน source ตรง ๆ — `"Retaining Wall Cantilever และ TRAFFIC SIGN"` เป็น string ในอาร์เรย์ `highlights` ของ `src/lib/pricing.ts` เช่นเดียวกับเชิงอรรถที่พิมพ์ชื่อ `LAND ACQUISITION V2` ไว้ในไฟล์เดียวกัน

นั่นคือคำแถลงต่อสาธารณะที่ไม่มีใครเป็นเจ้าของ ถ้าแอปตัวหนึ่งเลื่อนกำหนด เปลี่ยนโมเดลการเข้าถึง หรือถูกถอดออก หน้าเว็บจะประกาศต่อไปจนกว่าจะมีคนเปิด editor แก้แล้ว commit ผู้ดูแลแพลตฟอร์มซึ่ง ADR 0013 มอบ "ทะเบียนแอป" ให้ดูแลอยู่แล้ว ทำอะไรกับมันไม่ได้เลย

ตาราง `apps` มี `access_model` และ `enabled` อยู่แล้วตั้งแต่ migration แรก แต่ **ไม่มี query ไหนในโปรเจ็กต์อ่าน `enabled` เลยแม้แต่ที่เดียว** และแถวในตารางนั้นไม่ได้เกิดจากผู้ดูแล — `activateEstimeterTrial()` แทรกแถวเองตอนลูกค้าคนแรกกดเริ่มทดลองใช้ ทะเบียนที่มีอยู่จึงเป็นผลข้างเคียงของการใช้งาน ไม่ใช่บันทึกของการตัดสินใจ

## Decision

**สิ่งที่แพลตฟอร์มประกาศต่อสาธารณะว่าแอปหนึ่งเปิดภายใต้สิทธิ์แบบใด คือแถวในทะเบียนที่ผู้ดูแลประกาศไว้ ไม่ใช่บรรทัดใน source**

**1. การประกาศเป็นการกระทำที่มีผู้รับผิดชอบ ไม่ใช่การมีแถว** เพิ่ม `announced_at` และ `announced_by` ลงตาราง `apps` แอปถูกนับว่าประกาศแล้วก็ต่อเมื่อ `announced_at` ไม่เป็น null การมีแถวเฉย ๆ ไม่ใช่คำประกาศ เพราะแถวเกิดขึ้นเองได้จากเส้นทางที่ไม่มีผู้ดูแลเกี่ยวข้อง

**2. หน้าสาธารณะเอ่ยชื่อได้เฉพาะแอปที่ประกาศแล้ว และ fail closed** เมื่ออ่านฐานข้อมูลไม่สำเร็จ การ์ดสมาชิกใช้ฟรีจะไม่เอ่ยชื่อแอปใดเลย แสดงประโยคเดียวที่ไม่ระบุชื่อ และเชิงอรรถของแอปที่จำกัดสิทธิ์จะหายทั้งประโยค รายชื่อที่ผิดแย่กว่ารายชื่อที่หายไป และเป็นแนวเดียวกับ `resolvePlatformAdmin()` กับ `AccessStatePanel` ที่ปฏิเสธเมื่ออ่านไม่ได้

**3. การประกาศไม่ใช่การให้สิทธิ์** ทะเบียนเป็นคำแถลง สิ่งที่สมาชิกคนหนึ่งใช้ได้จริงยังตัดสินที่แถวใน `app_entitlements` ของเขาเสมอ วันนี้ยังไม่มีเส้นทางใดออกแถว `member_free` ให้ใครโดยอัตโนมัติ ดังนั้น **แอปที่ประกาศเป็น `member_free` จะตั้งสถานะ "เปิดใช้แล้ว" ไม่ได้** จนกว่าเส้นทางออกสิทธิ์จะมีจริง ข้อห้ามนี้บังคับในโค้ดและมีเทสต์ ไม่ใช่คอมเมนต์ หน้าเว็บที่สัญญาสิ่งที่ตัวผลิตภัณฑ์ปฏิเสธคือความเสียหายแบบเดียวกับปุ่มชำระเงินที่ยังไม่มีระบบรับเงินซึ่ง ADR 0011 ห้ามไว้

**4. `enabled` มีความหมายเดียว คือ "เปิดใช้แล้ว" และมันปิดทางเข้าจริง** แยกจาก "ประกาศแล้ว" แอปที่ประกาศแล้วแต่ยังไม่เปิดใช้ถูกเอ่ยชื่อได้พร้อมคำกำกับว่ากำลังเตรียมระบบ คำกำกับนั้นมาจากทะเบียน ไม่ใช่จาก `status` ใน source

และเมื่อทะเบียนบอกว่ายังไม่เปิดใช้ `/apps/<slug>` ต้องแสดงหน้ากำลังเตรียมระบบ ไม่ใช่หน้าทำงาน สวิตช์ที่ติดป้ายว่าปิดแล้วคนยังเดินเข้าได้ แย่กว่าไม่มีสวิตช์ เพราะมันสอนผู้ดูแลว่าปุ่มนี้หลอก — เป็นหลักเดียวกับข้อ 3 ที่ห้ามหน้าเว็บสัญญาสิ่งที่ผลิตภัณฑ์ปฏิเสธ เพียงใช้กลับด้าน นี่เป็นคำแถลงเรื่อง **ความพร้อม** ไม่ใช่ด่านอนุญาต จึงเป็นหน้าอธิบาย ไม่ใช่ 403 และเมื่ออ่านฐานข้อมูลไม่ได้ให้คงพฤติกรรมเดิม ไม่ใช่ล็อกทุกแอปทั้งแพลตฟอร์ม — ด่านจริงยังเป็น `app_entitlements` ผ่าน `resolveEstimeterContext()` ซึ่งไม่ได้ย้ายไปไหน

**5. คำประกาศขัดกับค่าตั้งต้นใน source ได้ และทะเบียนเป็นฝ่ายถูก** ผู้ดูแลประกาศแอปที่ตั้งต้นเป็น `paid_trial` ให้เป็น `member_free` ได้ ถ้าห้าม แปลว่า source ยังเป็นเจ้าของความจริงอยู่ดี ราคาที่จ่ายคือทุกการประกาศและทุกการถอนต้องพิมพ์เหตุผลอย่างน้อย 4 ตัวอักษรและเขียน `audit_events` ทุกครั้ง แบบเดียวกับ `updateCustomerEntitlement()` ของ ADR 0013 และหน้าหลังบ้านต้องขึ้นเตือนให้เห็นเมื่อคำประกาศขัดกับค่าตั้งต้น

**6. ถอนคำประกาศด้วยการล้าง `announced_at` ไม่ใช่ลบแถว** `app_entitlements.app_id` เป็น `ON DELETE CASCADE` การลบแถวทะเบียนจะลบสิทธิ์ของลูกค้าที่ผูกกับแอปนั้นหายไปเงียบ ๆ ซึ่งเป็นสิ่งที่ ADR 0013 ห้ามผู้ดูแลทำที่สุด

**7. ฟิลด์ `access` ใน `src/lib/platform.ts` เปลี่ยนชื่อเป็น `seededAccess`** เพื่อให้คนอ่านโค้ดเห็นทันทีว่าเป็นค่าตั้งต้น ไม่ใช่คำประกาศ

## Alternatives considered

| Alternative | Why not selected now |
|---|---|
| ใช้ "มีแถวในตาราง = ประกาศแล้ว" ไม่ต้องมี migration | ผิดตั้งแต่ลูกค้าคนแรกกดปุ่มทดลองใช้ เพราะ `activateEstimeterTrial()` แทรกแถวเองโดยไม่มีผู้ดูแลเกี่ยวข้อง ทะเบียนจะบันทึกว่ามีคน "ประกาศ" สิ่งที่ไม่เคยมีใครประกาศ |
| ให้ "กำลังเตรียมระบบ" มาจาก `status` ใน `platform.ts` แทนที่จะใช้ `enabled` | ไม่ต้องแตะสคีมา แต่คำแถลงต่อสาธารณะจะกลับไปอยู่ใน source อีกครึ่งหนึ่ง ซึ่งคือสิ่งที่เอกสารฉบับนี้ทั้งฉบับตั้งใจกำจัด |
| อ่านทะเบียนไม่ได้แล้วถอยไปใช้รายชื่อใน source | หน้าเว็บจะไม่มีวันเงียบ แต่ราคาคือรายชื่อที่ผู้ดูแลถอนไปแล้วจะกลับมาปรากฏทุกครั้งที่ฐานข้อมูลสะดุด — fail-open ที่แต่งตัวมาดี |
| ทำเส้นทางออกสิทธิ์ `member_free` อัตโนมัติในรอบเดียวกัน | เป็นการตัดสินใจคนละเรื่องที่มีคำถามของตัวเองครบชุด ใครได้ ได้ตอนไหน องค์กรไหนถือ ถอนอย่างไร สมควรมี ADR และรอบของตัวเอง (IP-093) การพ่วงมากับรอบนี้คือการตัดสินใจสี่เรื่องพร้อมกันโดยไม่มีใครทบทวน |
| ห้ามผู้ดูแลประกาศขัดกับค่าตั้งต้นใน source | ฟังดูปลอดภัย แต่แปลว่า source ยังเป็นเจ้าของคำประกาศอยู่ดี ทะเบียนจะกลายเป็นสำเนาที่แก้ได้บางส่วน ซึ่งแย่กว่ามีความจริงแหล่งเดียวที่แก้ได้ทั้งหมดพร้อมร่องรอย |
| ทำระบบ feature flag กลาง (ตาราง `feature_flags` + หน้าเปิดปิดทุกอย่าง) แทนที่จะใช้ทะเบียนแอป | วันนี้มีของให้เปิดปิดอยู่อย่างเดียวคือแอป และ `enabled` คือสวิตช์นั้นอยู่แล้ว การเพิ่มตาราง flag จะได้สองสวิตช์คุมหลอดเดียวกัน ปิดจากทะเบียนแล้วยังเปิดอยู่เพราะ flag อีกตัว คือบั๊กที่หาสาเหตุยากที่สุดประเภทหนึ่ง และ flag หนึ่งตัวคือ code path สองเส้นที่ต้องมีเทสต์ทั้งคู่ตลอดไป ADR 0013 ปฏิเสธการแยกผู้ดูแลเป็นสองบทบาทด้วยเหตุผลเดียวกันนี้ สิ่งที่รับมาแทนคือรูปทรง: ทะเบียนมีทางเข้าเดียวที่ `src/server/app-registry.ts` ถ้าวันหนึ่งต้องมี flag จริง มันสลับข้างในโมดูลได้โดยไม่ต้องแตะหน้าราคา |
| ย้ายการปิดกั้น `doh_staff_only` ที่ `/apps/[slug]` มาอ่านทะเบียนด้วยในรอบนี้ | นั่นคือการบังคับสิทธิ์ ไม่ใช่ป้ายโฆษณา และ fail closed ที่จุดนั้นแปลว่าฐานข้อมูลสะดุดครั้งเดียวทุกแอปเข้าไม่ได้ทั้งแพลตฟอร์ม เป็นการแลกที่ต้องตัดสินแยก (IP-092) |

## Consequences

**Migration** ต้องมี migration 0006 เพิ่ม `announced_at` (nullable timestamp) และ `announced_by` (nullable, อ้าง `users.id`) ลง `apps` แถวที่มีอยู่แล้วจะได้ `announced_at` เป็น null ซึ่งถูกต้องตามนิยาม — ไม่เคยมีใครประกาศมันจริง ๆ

**หลัง deploy หน้าราคาจะเงียบจนกว่าจะมีคนประกาศ** ทะเบียนเริ่มจากไม่มีอะไรถูกประกาศเลย ไม่มี seed script เพราะการประกาศคือการกระทำของคน ไม่ใช่ค่าที่ระบบเติมให้ ข้อนี้ต้องอยู่ในหมายเหตุการติดตั้งคู่กับ `pnpm db:migrate` และ `scripts/grant-platform-admin.mjs`

**Security** บัญชีผู้ดูแลที่ถูกยึดประกาศแอปที่ขายอยู่ให้เป็นของฟรีได้ สิ่งที่จำกัดความเสียหายคือทุกการประกาศมี actor เวลา และเหตุผลติดอยู่ใน `audit_events` และการประกาศไม่ได้ออกสิทธิ์ให้ใครโดยอัตโนมัติ (ข้อ 3) ความเสียหายจึงจำกัดอยู่ที่คำโฆษณาบนหน้าเว็บ ไม่ใช่การแจกสิทธิ์จริง

**Testing** ต้องมีเทสต์ที่ยืนยันสามอย่าง: แอปที่ไม่ได้ประกาศไม่ปรากฏชื่อบนหน้าสาธารณะแม้ค่าตั้งต้นจะเป็น `member_free`, อ่านฐานข้อมูลไม่ได้แล้วได้ผลลัพธ์ที่แยกออกจาก "ไม่มีอะไรถูกประกาศ" ได้, และไฟล์ราคาไม่เอ่ยชื่อแอปใดเลยใน source — ข้อสุดท้ายสแกนเทียบกับชื่อแอปจริงในแคตตาล็อก เพื่อให้แดงทันทีถ้ามีคนพิมพ์กลับเข้ามาวันหลัง

**สิ่งที่ยังไม่ถูกแก้ในรอบนี้** หน้าแรกและ `/market/[slug]` ยังติดป้ายสิทธิ์จาก `seededAccess` ในโค้ด แปลว่าแอปที่ยังไม่ถูกประกาศจะยังขึ้นป้าย "สมาชิกใช้ฟรี" บนหน้าแรก เป็นความจริงสองแหล่งที่รู้ตัวและตั้งเป็น IP-092 ไว้แล้ว ไม่ใช่สิ่งที่หลุดรอดไป
