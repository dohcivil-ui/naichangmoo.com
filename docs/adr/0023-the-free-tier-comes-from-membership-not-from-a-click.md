# ADR 0023: สิทธิ์ฟรีของ PRICEMETR มาจากการเป็นสมาชิก ไม่ใช่จากการกด

**Status:** Accepted — เจ้าของงานเคาะ 2026-08-29 (IP-164)

## Context

`docs/requirements/pricemetr-membership.md` เขียนเส้นแบ่งฟรีกับ VIP ไว้ครบตั้งแต่ 2026-08-26
พร้อมข้อห้ามสี่ข้อ **แต่โค้ดไม่เคยบังคับสักข้อจนถึงวันนี้** ใครเปิดหน้า `/prototype/price-check`
ก็ได้ทุกอย่างเท่ากันหมด รวมถึงกราฟย้อนหลังยี่สิบสี่เดือนที่เอกสารระบุว่าเป็นของ VIP —
หน้าจอส่ง `months: 24` ตายตัวและ API รับค่านั้นไปตรง ๆ โดยไม่ตรวจว่าใครขอ

การผูกสิทธิ์เข้าจริงเปิดคำถามสามข้อที่เอกสารเดิมตอบไม่ได้

**หนึ่ง** ESTIMETR ใช้ ADR 0006 สองด่าน คือเข้าสู่ระบบทำให้เป็นสมาชิกแพลตฟอร์ม แล้วต้องกด
ยอมรับอีกครั้งนาฬิกาทดลองใช้เจ็ดวันถึงเริ่มเดิน แอปราคาวัสดุต้องทำแบบเดียวกันไหม

**สอง** เอกสารพูดถึง "สมาชิกแพลตฟอร์ม" กับ VIP เท่านั้น ไม่เคยพูดถึงคนที่ยังไม่ได้เข้าสู่ระบบ
ทั้งที่หน้านี้เปิดให้ใครก็เข้าได้ และหลักที่ใช้ตัดสินทั้งเอกสารคือ **ราคาที่หน่วยงานรัฐประกาศ
เป็นข้อมูลเปิด ไม่ใช่ของเรา**

**สาม** เอกสารเขียนว่ารายการที่หยิบไว้ของสมาชิกฟรี "จำกัดจำนวนบรรทัด" แต่ไม่เคยเคาะตัวเลข

## Decision

1. **สิทธิ์ฟรีมาจากการเป็นสมาชิก ไม่ใช่จากการกด** สมาชิกที่เข้าสู่ระบบแล้วได้สิทธิ์ฟรีของแอปนี้
   ทันทีที่เปิดหน้า ไม่มีปุ่มให้กดยอมรับ **ADR 0006 ไม่ใช้กับแอปนี้** เพราะด่านที่สองของ ADR นั้น
   มีไว้เพื่อสองอย่าง คือเริ่มนาฬิกา ณ วินาทีที่คนกด และเก็บหลักฐานว่าเขาเห็นเงื่อนไขแล้ว
   สิทธิ์ฟรีของแอปนี้ไม่มีนาฬิกาให้เริ่มและไม่มีเงื่อนไขให้ยอมรับ ปุ่มยอมรับจึงเป็นด่านที่ไม่ปกป้องอะไร

2. **ผลตามมาที่สำคัญกว่าตัวปุ่ม: ทางอ่านสิทธิ์ไม่เขียนอะไรลงฐานข้อมูลเลย**
   สมาชิกที่ไม่มีแถว `app_entitlements` **คือ** สมาชิกฟรี ไม่ใช่สภาพผิดพลาดที่ต้องซ่อมด้วยการ
   แอบเขียนแถวตอนมีคนเปิดหน้า หลักการเดิมของ ESTIMETR ที่ว่าห้ามเขียนแถวขณะอ่านจึงยังอยู่ครบ
   และแถวสิทธิ์จะเกิดเฉพาะวันที่มีคนได้ VIP ซึ่งวันนั้นมันคือหลักฐานว่ามีคนให้สิทธิ์จริง

3. **ผู้มาเยือนที่ยังไม่ได้เข้าสู่ระบบ อ่านราคาได้ครบเท่าสมาชิกฟรี** ไม่เบลอ ไม่สุ่ม ไม่ตัดทอน
   ตามหลักข้อ 1 ของเอกสารเส้นแบ่ง สิ่งที่เขาทำไม่ได้คือ **หยิบราคาเข้ารายการ** เพราะรายการ
   ต้องผูกบัญชีถึงจะเก็บข้ามเครื่องและส่งต่อเข้า ESTIMETR ได้ ไม่ใช่เพราะเราอยากบังตัวเลข

4. **สามระดับ ไม่ใช่สอง** — ผู้มาเยือน · สมาชิกฟรี · VIP

   | | ผู้มาเยือน | สมาชิกฟรี | VIP |
   |---|---|---|---|
   | ราคาทุกรายการ ทุกจังหวัด เดือนล่าสุด | ครบ | ครบ | ครบ |
   | จำนวนครั้งที่ค้นหา | ไม่จำกัด | ไม่จำกัด | ไม่จำกัด |
   | กราฟย้อนหลัง | 6 เดือน | 6 เดือน | ถึงมกราคม 2545 |
   | หยิบเข้ารายการ | ไม่ได้ | 50 บรรทัด | ไม่จำกัด |
   | ส่งออกใบสรุปที่ตรวจย้อนได้ | ไม่ได้ | ไม่ได้ | ได้ |

5. **สมาชิกฟรีหยิบได้ 50 บรรทัด** พอทำงานจริงขนาดเล็กได้จบหนึ่งงาน แต่ยังรู้สึกถึงเพดาน
   เมื่อทำโครงการเต็ม เป็นตัวเลขที่ไม่ดูใจร้ายและไม่ดูหลอก

6. **VIP ที่หมดอายุตกลงมาเป็นสมาชิกฟรี ไม่ใช่ผู้มาเยือน** เขายังเป็นสมาชิกของแพลตฟอร์มอยู่
   การถีบกลับไปเท่าคนที่ไม่เคยสมัครคือการลงโทษที่ไม่มีใครสั่ง ส่วนบัญชีที่ถูกระงับลงมาเท่า
   ผู้มาเยือน คืออ่านราคาได้ (ห้ามไม่ได้ เป็นข้อมูลเปิด) แต่หยิบไม่ได้

7. **การหนีบ ไม่ใช่การปฏิเสธ** คำขอที่เกินสิทธิ์ได้คำตอบเท่าที่สิทธิ์ให้ พร้อมตัวเลข
   `monthsGranted` กลับไปด้วย ไม่ใช่ 403 ที่ทำให้กราฟหายทั้งใบทั้งที่หกเดือนแรกเขามีสิทธิ์เต็ม
   และหน้าจอพูดได้เฉพาะตัวเลขที่เซิร์ฟเวอร์ตอบมา ห้ามเดาเอง (ข้อห้ามข้อ 3)

8. **ชั้นตัดสินสิทธิ์แยกจากชั้นอ่านฐานข้อมูล** `src/lib/pricemetr-tier.ts` ไม่รู้จัก `@/db`
   ไม่รู้จัก session และไม่รู้จัก Next จึงทดสอบครบทุกสถานะได้โดยไม่ต้องยก Postgres
   ส่วน `src/server/pricemetr-access.ts` ทำหน้าที่อ่านอย่างเดียว

9. **ไม่เติมช่องใหม่ลง `STATE_POLICY` ของ `entitlement.ts`** ตารางนั้นเป็นของ ESTIMETR ทั้งใบ
   และมีอีกหกแอปพึ่งมันอยู่ การเอาศัพท์ของแอปเดียวไปแขวนไว้ในของกลางทำให้ทุกแอปต้องแบก
   ช่องที่ตัวเองไม่ใช้ ไฟล์ใหม่จึง **เรียก** `resolveEntitlement` ของเดิมใช้ ไม่ได้ลอกมาเขียนซ้ำ

## Alternatives considered

| Alternative | Why not selected |
|---|---|
| ใช้ ADR 0006 สองด่านเหมือน ESTIMETR | เหมือนกันทั้งแพลตฟอร์มจริง แต่เพิ่มปุ่มที่ไม่ปกป้องอะไร คั่นระหว่างคนกับราคาที่เขามีสิทธิ์ดูอยู่แล้ว |
| เขียนแถว `member_free` ให้อัตโนมัติตอนเปิดหน้าครั้งแรก | อ่านง่ายกว่าเพราะทุกคนมีแถว แต่แปลว่าคำขออ่านเขียนฐานข้อมูล ซึ่งเป็นสิ่งที่ ADR 0006 ห้ามไว้ด้วยเหตุผลที่ยังจริงอยู่ และสร้างแถวขยะให้ทุกคนที่แวะดูเฉย ๆ |
| บังคับให้เข้าสู่ระบบก่อนถึงเห็นราคา | ได้อีเมลทุกคนที่เข้ามาดู แต่ชนหลักข้อ 1 ของเอกสารตรง ๆ คือเอาข้อมูลเปิดของรัฐมาบังแล้วเก็บค่าผ่านทาง |
| ให้ผู้มาเยือนหยิบได้ด้วย เก็บในเบราว์เซอร์ | ใจดีกว่า แต่รายการที่หายเมื่อเปลี่ยนเครื่องคือสิ่งที่ IP-163 ตั้งใจจะเลิกทำ และจะกลายเป็นสัญญาที่เราผิดเอง |
| ตอบ 403 เมื่อขอเกินสิทธิ์ | ตรงไปตรงมากว่าในเชิงโปรโตคอล แต่ผู้ใช้เห็นกราฟหายทั้งใบแทนที่จะเห็นหกเดือนที่เขามีสิทธิ์ |
| เติม `historyMonths` กับ `lineLimit` ลง `EntitlementLimits` | ใช้กลไก "เก็บค่าแคบกว่านโยบายได้" ของเดิมได้ฟรี แลกกับการที่อีกหกแอปต้องแบกช่องของแอปราคาวัสดุไปตลอด |

## Consequences

**การทำงาน** คำขอของผู้มาเยือนไม่แตะฐานข้อมูลเลย จบที่การอ่าน session ว่าง ส่วนสมาชิกมี
คิวรีอ่านสิทธิ์เพิ่มหนึ่งครั้งต่อการเปิดหน้าและต่อการขอกราฟ

**สิ่งที่ยังกั้นไม่ได้จริงในรุ่นนี้ ต้องพูดให้ชัด** เพดาน 50 บรรทัดวันนี้ **เซิร์ฟเวอร์เป็นคนบอกตัวเลข
และหน้าจอบังคับตาม** ไม่ใช่เซิร์ฟเวอร์ปฏิเสธ เพราะรายการที่หยิบไว้ยังอยู่ในหน่วยความจำของหน้า
ไม่มีทรัพยากรฝั่งเซิร์ฟเวอร์ให้ปกป้อง ด่านที่ปฏิเสธจริงจะเกิดพร้อม IP-163 ที่เก็บรายการลงฐานข้อมูล
**เขียนไว้ตรงนี้เพื่อไม่ให้ใครอ่านโค้ดแล้วเข้าใจว่ากั้นครบแล้ว** ส่วนความยาวกราฟกั้นจริงตั้งแต่วันนี้
พิสูจน์ได้ด้วยการยิง `POST /api/prototype/price-history` ตรงโดยไม่ผ่านหน้าจอ

**ราคา** ADR นี้ไม่แตะเรื่องเงินเลย ราคา VIP ของแพลตฟอร์มยังเป็น 1,170/10,440 ตาม ADR 0011
ส่วนราคาเฉพาะแอปราคาวัสดุยังไม่เคาะ เจ้าของงานขอวัดต้นทุน token จริงของผู้ช่วยก่อน
ซึ่งวัดได้จริงเมื่อระบบเสร็จกว่านี้ · ข้อสังเกตที่บันทึกไว้คือ PRICEMETR ยังไม่มีทักษะผู้ช่วยเลย
ต้นทุนต่อคนจึงแทบเป็นศูนย์ และกลไก "โหมดไม่มีผู้ช่วย" มีอยู่แล้วที่ `EntitlementLimits.aiEnabled`

**ความปลอดภัย** ไม่มีข้อมูลส่วนบุคคลใหม่ ไม่มี migration ไม่มีตารางใหม่ การตัดสินทั้งหมด
อ่านจากของที่มีอยู่แล้ว

**การทดสอบ** `src/pricemetr-tier-fence.test.ts` เรียก route จริงเพื่อพิสูจน์ว่าจำนวนเดือนที่วิ่งไปถึง
สนค. ถูกหนีบจริง ไม่ใช่แค่ค้นคำในไฟล์ — พิสูจน์แล้วว่าถอดตัวหนีบออกเทสต์แดงสองข้อทันที
บวกเทสต์ครบทุกสถานะของ `resolveEntitlement` โดยไม่ต้องมีฐานข้อมูล
