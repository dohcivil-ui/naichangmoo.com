# ADR 0015: การ์ดแนะนำแอปได้เสมอ แต่คำแถลงต้องมาจากทะเบียนเท่านั้น

**Status:** Accepted — amends §2 of ADR 0014, and closes the unfinished work that ADR named IP-092

## Context

ADR 0014 §2 เขียนไว้ว่า **"หน้าสาธารณะเอ่ยชื่อได้เฉพาะแอปที่ประกาศแล้ว และ fail closed"**

กติกาข้อนั้นเขียนขึ้นจากเคสเดียว คือการ์ด "สมาชิกใช้ฟรี" บนหน้า `/pricing` ที่พิมพ์ชื่อแอปไว้ใน `highlights` ของ `src/lib/pricing.ts` ตรง ๆ แล้วมันกวาดรวม **การเอ่ยชื่อทุกชนิดบนทุกหน้า** เข้าไปด้วย

วันนี้ตาราง `apps` มีแถวเดียว คือ `estimeter` และ `announced_at` เป็น null — **ไม่มีแอปไหนในผลิตภัณฑ์เคยถูกประกาศเลยสักตัว** ขณะที่หน้าแรกเรนเดอร์การ์ดห้าใบจาก `platformApps` ทุกครั้งที่มีคนเปิด ตามตัวอักษรของ §2 หน้าที่เป็นสาธารณะที่สุดของผลิตภัณฑ์จึงละเมิดกติกาของตัวเองมาตลอดตั้งแต่วันที่ ADR 0014 ถูกรับ

และมันหนักกว่าการเอ่ยชื่อ `src/components/landing/app-card.tsx` เรนเดอร์ `accessLabel[app.seededAccess]` ซึ่งสำหรับ `paid_trial` แปลว่า **"ฟรี ทดลองใช้งาน 7 วัน"** — นั่นคือการแถลงเงื่อนไขทางพาณิชย์ของแอปที่ไม่มีผู้ดูแลคนไหนเคยประกาศ การ์ดใบเดียวกันยังเรนเดอร์ `appStatusLabel[app.status]` จาก source ทั้งที่ §4 ของ ADR 0014 ตัดสินไว้แล้วว่าคำกำกับความพร้อม *"มาจากทะเบียน ไม่ใช่จาก `status` ใน source"* และใส่ทางเลือกที่ใช้ `status` ไว้ในตาราง Alternatives ในฐานะข้อที่ **ถูกปฏิเสธ**

ADR 0014 รู้ตัวเรื่องนี้ ย่อหน้าสุดท้ายของมันเขียนไว้เองว่าหน้าแรกและ `/market/[slug]` ยังติดป้ายจาก `seededAccess` อยู่ และตั้งเป็น IP-092 ไว้ *"ไม่ใช่สิ่งที่หลุดรอดไป"* งานนั้นไม่เคยถูกทำ

`CONTEXT.md` ก็ขัดกันเองด้วยเหตุเดียวกัน entry **ประกาศแล้ว** ห้ามเอ่ยชื่อแอปที่ยังไม่ประกาศบนหน้าสาธารณะ ขณะที่ entry **ค่าตั้งต้นของสิทธิ์** อนุญาตให้ `seededAccess` เป็น *"ป้ายบอกหมวดในหน้าแนะนำแอปเท่านั้น"* — สองข้อนี้ดึงกันคนละทาง

## Decision

**การแนะนำแอปกับการแถลงเรื่องแอป เป็นการกระทำคนละอย่าง กติกาของ ADR 0014 คุมอย่างหลัง ไม่ใช่อย่างแรก**

**1. §2 ของ ADR 0014 ถูกแก้เส้น** จากเดิม "หน้าสาธารณะเอ่ยชื่อได้เฉพาะแอปที่ประกาศแล้ว" เป็น **"หน้าสาธารณะแถลงเรื่องสิทธิ์ ราคา และความพร้อมของแอปได้เฉพาะเท่าที่ทะเบียนประกาศไว้"** การเอ่ยชื่อแอปและบอกว่ามันทำอะไร ไม่ใช่คำแถลง จึงมาจาก source ได้เสมอ

เหตุผลที่แยกได้โดยไม่ทำให้ §2 อ่อนลง อยู่ที่ว่าชื่อแอปทำหน้าที่ต่างกันในสองที่ บนการ์ด "สมาชิกใช้ฟรี" ของหน้า `/pricing` **ชื่อแอปคือตัวคำแถลงเอง** — ประโยคนั้นแปลว่า "แอปเหล่านี้สมาชิกใช้ฟรี" การลบชื่อออกจึงคือการลบคำแถลงออก แต่บนการ์ดในแคตตาล็อก **ชื่อคือประธานของประโยค ส่วนคำแถลงคือป้ายที่แยกชิ้นกันอยู่** จึงถอดป้ายออกโดยเหลือประธานไว้ได้ พฤติกรรม fail closed ของ `/pricing` ตาม §2 เดิมจึงไม่เปลี่ยนแม้แต่น้อย

**2. สิ่งที่เป็นคำแถลง และแหล่งที่มีอำนาจของแต่ละอย่าง**

| สิ่งที่ปรากฏบนการ์ด | ชนิด | แหล่งที่มีอำนาจ |
|---|---|---|
| ชื่อ, `purpose`, ไอคอน, หมวด | การแนะนำ | `src/lib/platform.ts` |
| ป้ายสิทธิ์ | คำแถลง | ทะเบียน `access_model` |
| ป้ายความพร้อม | คำแถลง | ทะเบียน `enabled` |
| ถ้อยคำของปุ่ม ("เริ่มใช้" เทียบกับ "ดูรายละเอียด") | คำแถลง | ทะเบียน `enabled` |
| "ประกาศเมื่อ ‹เดือน ปี›" | คำแถลง | ทะเบียน `announced_at` |

ถ้อยคำของปุ่มอยู่ในตารางนี้เพราะคำว่า "เริ่มใช้" คือคำสัญญาว่ามีทางเข้า ปุ่มที่ชวนให้เริ่มใช้แอปที่ทะเบียนบอกว่ายังไม่เปิด คือความเสียหายแบบเดียวกับที่ §4 ปิดประตู `/apps/<slug>` ไว้ เพียงย้ายมาอยู่บนปุ่ม

**3. ไม่มีคำประกาศ แปลว่าเงียบ ไม่ใช่หาย** การ์ดของแอปที่ยังไม่ถูกประกาศยังเรนเดอร์ชื่อ ไอคอน และ `purpose` ตามปกติ แต่ไม่มีป้ายสิทธิ์ ไม่มีป้ายความพร้อม ไม่มีวันที่ และปุ่มใช้ถ้อยคำแบบไม่สัญญา **และเมื่ออ่านฐานข้อมูลไม่สำเร็จ ให้ได้ผลลัพธ์เหมือนกันทุกประการกับ "ยังไม่มีอะไรถูกประกาศ"** นี่คือ fail closed แบบเดียวกับ §2 เดิม เพียงแต่สิ่งที่ปิดคือคำแถลง ไม่ใช่ทั้งการ์ด — คำแถลงที่ผิดยังคงแย่กว่าคำแถลงที่หายไป

**4. ราคาบนการ์ดคือหมวดสิทธิ์ ไม่ใช่ตัวเลข** ทะเบียนไม่มีคอลัมน์ราคาต่อแอป และตัวเลขเงินทุกตัวของแพลตฟอร์มอยู่ใน `src/lib/pricing.ts` ก้อนเดียวไม่แยกรายแอป การเอาตัวเลขนั้นไปแปะการ์ดทั้งห้าใบจะได้เลขเดียวกันห้าที่ ซึ่งเป็นสิ่งที่ `pricing.ts` เขียนห้ามตัวเองไว้ในหัวไฟล์ (*"four copies means one of them is stale the day a price moves"*) และมันตอบผิดคำถามด้วย — คนที่เลื่อนดูแคตตาล็อกถามว่า "ต้องจ่ายไหมถึงจะเข้าได้" ไม่ใช่ "แอปนี้กี่บาท" ตัวเลขยังอยู่ที่ `/pricing` ที่เดียวตาม ADR 0011

**5. วันที่บนการ์ดของแอปที่ยังไม่เปิด คือ "ประกาศเมื่อ" และไม่มีอย่างอื่น** แสดงเมื่อแอปถูกประกาศแล้วแต่ทะเบียนยังบอกว่าไม่เปิดใช้ ที่มาคือ `announced_at` ซึ่งเป็นข้อเท็จจริงที่มีผู้รับผิดชอบและเวลากำกับอยู่แล้ว ไม่ต้องแก้สคีมา และไม่มีใครต้องมาคอยเติมให้มันสดทุกสัปดาห์

ยิ่งวันที่นั้นเก่า ยิ่งอ่านแล้วเสียหายกับเรา — **นั่นคือกลไกที่ต้องการ ไม่ใช่ผลข้างเคียงที่ต้องกลบ** ตัวเลขเปอร์เซ็นต์ความคืบหน้าแบบที่คู่แข่งใช้ถูกปฏิเสธเพราะมันพิสูจน์อะไรไม่ได้เลย ต้องมีคนคิดเลขขึ้นมาเองทุกสัปดาห์ และมันค้างที่ 90% เสมอ คำถามนี้ถูกตอบไว้ที่นี่ครั้งเดียว เพื่อไม่ต้องเถียงใหม่ทุกครั้งที่คู่แข่งปล่อยของแบบนั้นออกมา

**6. §3 และ §4 ของ ADR 0014 ไม่เปลี่ยน** การประกาศยังไม่ใช่การให้สิทธิ์ แอปที่ประกาศเป็น `member_free` ยังตั้งเป็นเปิดใช้แล้วไม่ได้จนกว่า IP-093 จะมีจริง และประตูที่ `/apps/<slug>` ยังทำงานเหมือนเดิม เอกสารฉบับนี้คือสิ่งที่ปิดงานค้าง IP-092 ที่ ADR 0014 ตั้งชื่อไว้เอง

## Alternatives considered

| Alternative | Why not selected |
|---|---|
| ไม่แก้ ADR ปล่อยให้หน้าแรกเงียบทั้งหมดตาม §2 เดิม | ถูกตามตัวอักษรที่สุด และคืนนี้หน้าแรกจะว่างเปล่าทันทีเพราะไม่มีแอปไหนถูกประกาศเลย ผลลัพธ์คือการซ่อนแคตตาล็อกทั้งชุดเพื่อรักษากติกาที่เขียนไว้กว้างเกินเจตนาของตัวเอง |
| แก้ ADR 0014 ในที่เดิม | เร็วกว่า แต่ลบร่องรอยว่าเส้นเคยอยู่ตรงไหนและทำไมมันขยับ ADR 0014 เองก็ขยาย ADR 0013 ด้วยการอ้างถึงไม่ใช่แก้ทับ ใช้แบบแผนเดียวกัน |
| ยอมรับว่า `seededAccess` เป็นป้ายหมวดได้จริงตาม entry `ค่าตั้งต้นของสิทธิ์` แล้วไม่ต้องแตะทะเบียน | ต้องเปลี่ยนถ้อยคำในป้ายจาก "ฟรี ทดลองใช้งาน 7 วัน" ให้ไม่ใช่คำสัญญาเสียก่อน ซึ่งพอทำจริงจะเหลือป้ายที่ไม่บอกอะไรเลย และมันคือการคงความจริงสองแหล่งไว้ ซึ่งเป็นสิ่งที่ ADR 0014 ทั้งฉบับตั้งใจกำจัด |
| เพิ่มคอลัมน์ให้ผู้ดูแลกรอก "คาดว่าเปิดเมื่อ" | เป็นคำสัญญาเรื่องอนาคตที่ผลิตภัณฑ์ยังทำตามไม่ได้ ซึ่ง ADR 0011 ห้ามไว้ด้วยเหตุผลเดียวกับปุ่มชำระเงินที่ยังไม่มีระบบรับเงิน และมันจะกลายเป็นเปอร์เซ็นต์ความคืบหน้าในรูปแบบวันที่ |
| ใช้ `apps.updated_at` เป็นวันที่ "ทำงานล่าสุด" | มันขยับทุกครั้งที่มีคนแก้แถวทะเบียนไม่ว่าด้วยเหตุใด การแก้คำผิดในชื่อแอปจะทำให้การ์ดบอกว่ามีความคืบหน้า เป็นตัวเลขที่ดูเหมือนข้อเท็จจริงแต่ไม่ได้วัดสิ่งที่คนอ่านคิดว่ามันวัด |
| ใส่ราคาจริงลงการ์ดทุกใบ | ราคาที่มีคือราคาแพลตฟอร์มก้อนเดียว การ์ดทั้งห้าใบจะขึ้น ฿1,170/เดือน เหมือนกันหมด ซึ่งตอบว่าแพลตฟอร์มราคาเท่าไร ไม่ใช่แอปนี้ราคาเท่าไร และสร้างสำเนาราคาห้าชุดที่ `pricing.ts` ห้ามไว้ |

## Consequences

**ไม่มี migration** ทุกอย่างในเอกสารนี้อ่านจากคอลัมน์ที่ ADR 0014 เพิ่มไว้แล้ว

**หลังแก้โค้ด การ์ดทั้งห้าใบจะเข้าสู่สถานะเงียบทันที** เพราะยังไม่มีแอปไหนถูกประกาศ การ์ดจะบอกชื่อและ `purpose` แต่ไม่บอกสิทธิ์ ความพร้อม หรือวันที่ สถานะนี้ต้องถูกออกแบบและมองด้วยตาก่อนขึ้นโค้ด ไม่ใช่ค้นพบหลังจากนั้น และ ADR 0014 ห้ามเขียน seed script ไว้แล้ว — ผู้ดูแลต้องเข้าไปประกาศเองในหลังบ้าน ซึ่งเป็นการทดสอบทะเบียนจริงครั้งแรกนับจาก v0.34.0 (IP-094)

**การ์ดของแอปที่ยังไม่ประกาศตอบได้ 2 ใน 4 คำถาม** คือ "นี่คืออะไร" กับ "กดอะไรต่อ" ส่วน "ใช้ได้เลยไหม" และ "เท่าไร" เงียบจนกว่าจะมีคนประกาศ นี่เป็นราคาที่ตั้งใจจ่าย การ์ดที่เดาคำตอบสองข้อนั้นเองคือสิ่งที่ ADR 0014 มีอยู่เพื่อห้าม

**Testing** ต้องมีเทสต์ยืนยันสามอย่าง: แอปที่ไม่ได้ประกาศเรนเดอร์ชื่อได้แต่ไม่มีป้ายสิทธิ์ ป้ายความพร้อม หรือวันที่เลย, อ่านฐานข้อมูลไม่สำเร็จให้ผลเหมือนกันทุกประการกับไม่มีอะไรถูกประกาศ, และแอปที่ทะเบียนประกาศสิทธิ์ขัดกับ `seededAccess` ต้องแสดงค่าของ **ทะเบียน**

**`CONTEXT.md` ขยับตาม** entry **ประกาศแล้ว** ถูกทำให้แคบลงเท่าที่ระบบบังคับใช้จริง ซึ่งเป็นการปิดข้อขัดแย้งกับ entry **ค่าตั้งต้นของสิทธิ์** ที่ค้างอยู่ด้วย
