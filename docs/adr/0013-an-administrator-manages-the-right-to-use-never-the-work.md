# ADR 0013: ผู้ดูแลจัดการสิทธิ์การใช้งาน ไม่ใช่ตัวงาน

**Status:** Accepted — extends the scope set in ADR 0012

## Context

ADR 0012 กำหนดขอบเขตของผู้ดูแลแพลตฟอร์มไว้ที่ "เนื้อหาของแพลตฟอร์มและตัวเลขสรุปเชิงรวม" ซึ่งแคบเกินกว่างานที่ต้องทำจริง เจ้าของงานระบุว่าผู้ดูแลต้องทำสี่อย่าง: จัดการสิทธิ์การใช้งาน ดูแลข่าวสาร แก้ข้อมูลต่าง ๆ และเปลี่ยนหรือสลับแอป

สามอย่างหลังคือเนื้อหา ซึ่ง ADR 0012 ครอบคลุมอยู่แล้ว อย่างแรกไม่ใช่ การต่ออายุทดลองใช้ให้สมาชิกคนหนึ่ง หรือระงับสิทธิ์บัญชีที่ผิดเงื่อนไข ต้องเขียนแถวใน `app_entitlements` ซึ่งมี `organization_id` คือผูกกับลูกค้ารายหนึ่ง

คำถามคือการเขียนแถวนั้นละเมิดหลักที่ ADR 0012 ตั้งไว้หรือไม่

## Decision

**ไม่ละเมิด เพราะเส้นแบ่งที่แท้จริงไม่ใช่ "ข้อมูลของลูกค้า" กับ "ข้อมูลของแพลตฟอร์ม" แต่คือ สิทธิ์การใช้งาน กับ ตัวงาน**

สิทธิ์การใช้งานคือความสัมพันธ์ระหว่างลูกค้ากับแพลตฟอร์ม ทั้งสองฝ่ายเป็นคู่สัญญา แพลตฟอร์มเป็นผู้ออกสิทธิ์นั้นเอง และเป็นฝ่ายที่ต้องแก้เมื่อมีคนจ่ายเงินแล้วสิทธิ์ไม่ขึ้น ตัวงานคือสิ่งที่ลูกค้าผลิตด้วยเครื่องมือ แพลตฟอร์มเก็บให้ แต่ไม่ได้เป็นเจ้าของและไม่มีเหตุผลต้องอ่าน

**ผู้ดูแลแพลตฟอร์มทำได้:**

| ขอบเขต | ตัวอย่าง |
|---|---|
| สิทธิ์การใช้งาน | ออก ต่ออายุ ระงับ และคืนสิทธิ์ใน `app_entitlements` แก้ `state`, `ends_at` และ `limits` |
| เนื้อหาที่ลูกค้าเห็น | ราคา ช่วงลดราคา ข่าวสาร ประกาศ ข้อความระดับสิทธิ์ |
| ทะเบียนแอป | เปิด ปิด สลับลำดับ และแก้คำอธิบายแอปใน `apps` |
| คำขอใบเสนอราคา | อ่านและเลื่อนสถานะตาม workflow ของ ADR 0005 — เอกสารนี้ถูกส่งมา *ถึง* แพลตฟอร์ม จึงเป็นงานของแพลตฟอร์มเอง |
| ตัวเลขสรุป | จำนวนแถวเชิงรวม และบันทึกเหตุการณ์ระดับแพลตฟอร์ม |

**ผู้ดูแลแพลตฟอร์มทำไม่ได้:**

`projects`, `drawing_documents`, `takeoff_runs`, `takeoff_groups`, `takeoff_items`, `takeoff_measurements`, `evidence_references`, `price_sets`, `price_observations`, `estimate_revisions` — ทั้งการอ่านและการเขียน สิ่งเหล่านี้คือสิ่งที่ลูกค้าถอดจากแบบและคำนวณเอง ผู้ดูแลที่ตั้งราคาบนหน้าเว็บไม่มีเหตุผลใดต้องเห็นตัวเลขในโครงการของใคร

**การเปลี่ยนสิทธิ์ทุกครั้งต้องเขียน `audit_events`** พร้อม `organization_id` ของลูกค้า `actor_id` ของผู้ดูแล และเหตุผลที่ระบุเป็นข้อความ การต่ออายุที่ไม่มีเหตุผลกำกับคือการแจกของฟรีที่ตรวจสอบไม่ได้

**การนับไม่ใช่การอ่าน** หน้าหลังบ้านนับจำนวนโครงการได้ แต่แสดงชื่อโครงการไม่ได้ เพราะชื่อโครงการคือข้อมูลของลูกค้า เส้นนี้ต้องรักษาไว้แม้จะดูเล็กน้อย เพราะทุกการขยาย "ขอแค่ชื่อ" คือขั้นแรกของการเปิดทั้งตาราง

## Alternatives considered

| Alternative | Why not selected now |
|---|---|
| คงขอบเขต ADR 0012 ไว้เท่าเดิม แล้วแก้สิทธิ์ด้วย SQL ตรง | ปลอดภัยที่สุดบนกระดาษ แต่ผลจริงคือทุกการต่ออายุเป็นการรันคำสั่งกับฐานข้อมูลผลิตจริงโดยไม่มี audit event และไม่มีเหตุผลกำกับ ซึ่งแย่กว่าการมีหน้าจอที่บันทึกทุกครั้ง |
| ให้ผู้ดูแลอ่านชื่อโครงการได้ เพื่อช่วยระบุตัวลูกค้าเวลาแก้ปัญหา | ชื่อโครงการของงานราชการมักมีชื่อหน่วยงานและสถานที่ ซึ่งเป็นข้อมูลของลูกค้า การระบุตัวลูกค้าใช้อีเมลและชื่อองค์กรได้อยู่แล้ว |
| แยกเป็นสองสิทธิ์ คนหนึ่งดูแลเนื้อหา อีกคนดูแลสิทธิ์การใช้งาน | ถูกต้องตามหลักการแบ่งแยกหน้าที่ แต่ตอนนี้ยังไม่มีผู้ดูแลแม้แต่คนเดียว การสร้างสองบทบาทก่อนมีคนใช้คือการเดาโครงสร้างองค์กรที่ยังไม่เกิด แยกทีหลังได้เพราะสิทธิ์เก็บเป็นแถวอยู่แล้ว |
| ให้ผู้ดูแลเข้าถึงข้อมูลลูกค้าได้เมื่อลูกค้าร้องขอความช่วยเหลือ | เป็นความต้องการจริงและจะมาถึงวันหนึ่ง แต่มันคือสิทธิ์คนละตัวที่ต้องมีการยินยอมของเจ้าของข้อมูลและมีวันหมดอายุ ไม่ใช่ผลพลอยได้ของสิทธิ์แก้ราคา |

## Consequences

**หน้าจอที่ต้องมี** การจัดการสิทธิ์ต้องค้นหาลูกค้าจากอีเมลหรือชื่อองค์กรได้ แสดงสถานะสิทธิ์ปัจจุบัน และเปลี่ยนได้พร้อมช่องเหตุผลที่บังคับกรอก ช่องเหตุผลที่กรอกว่างได้คือช่องที่จะถูกกรอกว่างเสมอ

**การบังคับใช้อยู่ที่ repository ไม่ใช่ที่หน้าจอ** ฟังก์ชันที่อ่าน `projects` และตารางงานทั้งหมดยังรับ `organizationId` เป็นเงื่อนไขเหมือนเดิม การเพิ่มสิทธิ์ผู้ดูแลไม่ได้เพิ่มทางเข้าใหม่ให้ฟังก์ชันเหล่านั้น และห้ามเพิ่ม

**Testing** ต้องมีเทสต์ที่ยืนยันว่าผู้ดูแลแพลตฟอร์มเรียกเส้นทางอ่านงานของลูกค้าไม่ผ่าน เทสต์ที่ยืนยันแค่ว่า "หน้าจอไม่มีปุ่ม" ไม่นับ เพราะขัดกับกฎ prefer server-side authorization checks over hiding UI controls

**Security** ขอบเขตนี้กว้างกว่า ADR 0012 จริง บัญชีผู้ดูแลที่ถูกยึดตอนนี้แจกสิทธิ์ใช้งานฟรีให้ตัวเองได้ สิ่งที่จำกัดความเสียหายคือ audit event ทุกรายการมี actor และเหตุผล ทำให้ตรวจย้อนได้ว่าเกิดอะไรขึ้นเมื่อไร ไม่ใช่การหวังว่าจะไม่เกิด
