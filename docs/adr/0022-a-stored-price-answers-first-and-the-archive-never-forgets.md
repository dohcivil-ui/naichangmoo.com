# ADR 0022: ราคาที่เก็บไว้ตอบก่อนต้นทาง และคลังราคาไม่ลบของเก่าทิ้ง

**Status:** Accepted — เจ้าของงานเคาะ 2026-08-29 ผ่านการกริลสองรอบ (IP-162)

## Context

ราคาวัสดุที่ PRICEMETR ดึงจาก สนค. อยู่ใน `Map` ในหน่วยความจำของเซิร์ฟเวอร์เท่านั้น อายุหนึ่งชั่วโมง
**รีสตาร์ตแล้วหายเกลี้ยง** ผู้ใช้คนแรกหลังรีสตาร์ตต้องรอต้นทางตอบก้อน 3.3 MB ซึ่งวัดจริงได้ถึง
สิบสองวินาที และถ้าต้นทางล่มพร้อมกัน หน้าจอจะตกไปใช้ไฟล์ตัวอย่างชุดเดียวในรีโป ซึ่งเป็นข้อมูล
ของเดือนเดียวที่แช่ไว้ตอนพัฒนา ไม่ใช่ราคาจริงที่เราเคยดึงมาได้

เมื่อฐานข้อมูลเข้ามาเป็นที่มาที่สาม คำถามที่ต้องตอบให้ชัดคือ **ที่มาไหนตอบก่อน** และ
**หน้าจอจะบอกผู้ใช้อย่างไรว่าตัวเลขตรงหน้ามาจากไหน** ข้อหลังไม่ใช่เรื่องความสวยงาม เพราะ
`docs/requirements/pricemetr-membership.md` ข้อ 4.3 ห้ามขึ้นป้ายสถานะที่ไม่ตรงกับคำตอบของเซิร์ฟเวอร์
และจุดขายทั้งแอปคือ "ตรวจย้อนได้" ซึ่งพังทันทีถ้าเราตอบด้วยสำเนาแล้วบอกว่าเป็นของสด

## Decision

1. **ลำดับความเชื่อสี่ชั้น: หน่วยความจำ → คลังราคา → สนค. → ไฟล์ตัวอย่าง**
   คลังมาก่อนต้นทาง ไม่ใช่เป็นตาข่ายรับตอนต้นทางล่ม เพราะถ้าเป็นอย่างหลัง ผู้ใช้คนแรก
   หลังรีสตาร์ตก็ยังรอสิบสองวินาทีอยู่ดี ซึ่งแปลว่าไม่ได้แก้อะไรเลย
2. **ตรวจความใหม่ด้วยคำขอเล็กเสมอ ไม่ใช่ด้วยนาฬิกา** ทุกคำขอที่แคชในหน่วยความจำหมดอายุ
   จะถาม `master` ของ สนค. (คำขอเล็ก) ก่อน แล้วเทียบ **รุ่นของชุดข้อมูล** กับที่คลังมี
   ตรงกันจึงตอบจากคลัง ไม่ตรงจึงดึงก้อนใหญ่ · ทางเลือกที่ปฏิเสธคือตั้งอายุให้ของในคลัง
   ซึ่งเร็วกว่าแต่ทำให้เราพูดว่าเป็นเดือนล่าสุดทั้งที่ต้นทางออกเดือนใหม่ไปแล้ว
3. **รุ่นของชุดข้อมูลคือ `lastUpdated` ของ สนค. ไม่ใช่เดือนของราคา** ต้นทางแก้ราคาย้อนหลัง
   ของเดือนเดิมได้โดยเดือนไม่เปลี่ยน เดือนจึงตอบไม่ได้ว่าสำเนายังตรงไหม
4. **คลังไม่ลบของเก่า** หน้าต่างที่ดึงมาคือหกเดือน พอเดือนใหม่มา เดือนที่เจ็ดหลุดจากหน้าต่าง
   แต่ยังอยู่ในคลัง นี่คือทางเดียวที่จะไปถึงข้อ VIP "ย้อนหลังเต็มถึงมกราคม 2545" โดยไม่ต้อง
   พึ่งว่าต้นทางจะยอมให้ดึงย้อนหลังได้ตลอดไป
5. **ที่มาของคำตอบเป็นค่าสามค่า ไม่ใช่ธงจริงเท็จ** — `live` `stored` `sample` — ประกาศโดย
   เซิร์ฟเวอร์ค่าเดียว หน้าจอห้ามเดาเอง และแต่ละค่ามีถ้อยคำกับสถานะของตัวเองบนแถบสถานะ
6. **คลังราคาห้ามโยน error ออกไปเด็ดขาด** หน้าราคาทำงานได้โดยไม่ต้องมีฐานข้อมูลเลยมาตั้งแต่ต้น
   ถ้าคลังพังแล้วลากหน้าจอพังตาม รุ่นนี้จะทำให้ของที่เคยดีแย่ลง ทุกทางออกของโมดูลคลังจึงเป็น
   `null` หรือเงียบ แล้วปล่อยให้ชั้นบนไหลลงชั้นถัดไป
7. **ชื่อ หน่วย และหมวดของสินค้าอยู่คนละตารางกับราคา** (`price_catalogue_items`)
   หนึ่งรหัสสินค้ามีชื่อเดียวแต่มีราคาหลายเดือน การเก็บชื่อซ้ำทุกเดือนคือหกโอกาสที่ของชิ้นเดียวกัน
   จะไม่ตรงกันเอง
8. **ราคารวมภาษีเก็บเท่าที่ต้นทางส่งมา ห้ามคูณเติมเอง** การปัดเศษเป็นของผู้ประกาศ
   ถ้าคำนวณเอง ราคาที่ผู้ใช้เห็นวันนี้ (จากต้นทาง) กับพรุ่งนี้ (จากคลัง) จะต่างกันในหลักสตางค์
   โดยไม่มีใครอธิบายได้

## Alternatives considered

| Alternative | Why not selected |
|---|---|
| เก็บสแนปช็อตเป็น JSON ก้อนเดียวต่อจังหวัดต่อเดือน | เขียนเร็วและแถวน้อยจริง แต่ค้นระดับรายการไม่ได้ ต้องอ่านทั้งก้อนก่อนเสมอ และ IP-163 (ชุดราคาของโครงการ) กับข้อ VIP ย้อนหลังยี่สิบสี่ปี ต้องการรายแถวอยู่ดี เลือกทางนี้วันนี้คือรื้อในอีกสองงานข้างหน้า |
| ให้คลังเป็นตาข่ายรับหลังต้นทาง | ไม่แก้โจทย์ที่ตั้งไว้ คือความช้าหลังรีสตาร์ต |
| ตั้งอายุของในคลัง 24 ชั่วโมงแล้วเชื่อไปเลย | ประหยัดคำขอเล็กหนึ่งครั้ง แลกกับการบอกผู้ใช้ว่าเป็นเดือนล่าสุดทั้งที่ไม่ใช่ ซึ่งชนข้อห้ามเรื่องป้ายสถานะ |
| เก็บแค่หกเดือนล่าสุด ลบที่เหลือ | ประหยัดพื้นที่หลักสิบเมกะไบต์ แลกกับคลังที่สร้างใหม่ไม่ได้ถ้าวันหนึ่งต้นทางตัดการดึงย้อนหลัง |
| คงธง `stale` จริง/เท็จไว้ ให้ของจากคลังนับเป็นไม่เก่า | หน้าจอไม่ต้องแก้เลย แต่เท่ากับไม่บอกผู้ใช้ว่าตัวเลขมาจากสำเนาของเราหรือจากต้นทาง |
| ทำงานตามเวลาดึงครบ 77 จังหวัดเข้าคลัง | ราวสามล้านแถว และยังไม่มีตัวเดินงานตามเวลาในระบบ เป็นการตัดสินใจคนละใบ รุ่นนี้ให้สคริปต์อุ่นด้วยมือแทน |

## Consequences

**การทำงาน** คำขอที่แคชหมดอายุจะมีคำขอเล็กไปหา `master` เพิ่มหนึ่งครั้ง แลกกับการไม่ต้องยิง
ก้อน 3.3 MB เมื่อรุ่นยังตรง · การเขียนลงคลังเกิดหลังตอบผู้ใช้ไปแล้วและแบ่งชุดละ 1,000 แถว
หนึ่งจังหวัดหนึ่งรอบมีได้ถึงราวสามหมื่นแปดพันแถว

**ความปลอดภัย** ไม่มีข้อมูลส่วนบุคคลในสามตารางนี้ ทั้งหมดเป็นราคาที่หน่วยงานรัฐประกาศเปิด
`price_catalogue_items` ถูกเพิ่มเข้าบัญชีตารางที่ผู้ดูแลแพลตฟอร์มอ่านไม่ได้ตาม ADR 0013
ด้วยเหตุผลเดียวกับ `price_observations` คือหลังบ้านจัดการสิทธิ์ ไม่ใช่จัดการงาน

**ค่าใช้จ่าย** พื้นที่เพิ่มตามจำนวนจังหวัดที่มีคนเปิดจริง ไม่ใช่ตามจำนวนจังหวัดทั้งหมด
เพราะเก็บเมื่อมีคนขอเท่านั้น

**การย้ายข้อมูล** migration เป็นการเพิ่มล้วน ตารางใหม่หนึ่งตารางกับสองคอลัมน์ใน
`price_observations` ซึ่งไม่เคยมีแถวเลยตั้งแต่สร้างในรุ่น 0000 การเพิ่มคอลัมน์บังคับจึงปลอดภัย

**การทดสอบ** ส่วนประกอบตารางกลับจากคลังเป็นฟังก์ชันบริสุทธิ์และมีเทสต์คุมโดยไม่ต้องมีฐานข้อมูล
ส่วนการเขียนอ่านจริงมีเทสต์ที่เปิดด้วยธง `PRICE_ARCHIVE_DB_TESTS=1` และลบของตัวเองทิ้งเสมอ

**อ้างอิง** roadmap v0.90.0 · IP-162 · บันทึกส่งงาน 2026-08-29
