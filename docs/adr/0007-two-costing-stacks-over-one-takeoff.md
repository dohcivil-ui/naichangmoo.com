# ADR 0007: Two costing stacks over one take-off

**Status:** Superseded by ADR 0008 — วิธีคิดราคาย้ายจากโครงการไปอยู่ที่ revision

## Context

ESTIMETR ถอดปริมาณได้แล้วตั้งแต่ v0.15.0 แต่ยังไม่มีชั้นราคา หน้า take-off เขียนบอกผู้ใช้เองว่า
`WORKFLOW 3 / 4` เพราะขั้นที่สี่ยังไม่มีจริง และ `PROJECT.md` ข้อ 7 บังคับว่าทุก release ต้องรักษาร่องรอย
จาก input ถึง pricing และ output decision ให้ครบ ชั้นราคาจึงเป็นงานถัดไปที่เลี่ยงไม่ได้

เจ้าของงานส่งเอกสารอ้างอิงมาสองชุด และสองชุดนี้อธิบายวิธีคิดราคาที่ **ไม่ใช่เรื่องเดียวกัน**

**ชุดที่หนึ่ง — ราคากลางงานราชการ** (ปร.1–ปร.6, ตาราง Factor F งานอาคาร, บัญชีค่าแรง ว809 กรมบัญชีกลาง,
บัญชีราคา สพฐ., หลักเกณฑ์การเผื่อวัสดุมวลรวม)

```
ค่างานต้นทุน = Σ (ปริมาณ × (ค่าวัสดุ/หน่วย + ค่าแรง/หน่วย))
ราคากลาง     = ค่างานต้นทุน × Factor F
```

Factor F เป็นตารางที่รัฐประกาศ ไม่ใช่ตัวเลขที่ผู้ประมาณเลือกเอง มัน **รวมค่าอำนวยการ ค่าดอกเบี้ย ค่ากำไร
และ VAT ไว้ในตัวคูณเดียว** แล้ว ตารางมี 12 ชุดตามเงินล่วงหน้าจ่าย {0, 5, 10, 15}% คูณกับเงินประกันผลงานหัก
{0, 5, 10}% แต่ละชุดมี 24 ช่วงค่างานต้นทุน และถ้าค่างานตกอยู่ระหว่างช่วงต้องเทียบอัตราส่วนเชิงเส้น
ผลลัพธ์คือเพดานราคาที่ต้องป้องกันได้ตอนถูกตรวจสอบ

**ชุดที่สอง — ต้นทุนและกำไรของผู้รับเหมา** (`km/boqtarget/`)

```
Direct Cost  = Material + Labor + Equipment + Subcontract
Total Cost   = Direct Cost + Site Overhead + Office Overhead + Contingency
Selling Price = Total Cost + Profit  (แล้วดู margin ที่เหลือจริง)
```

ที่นี่ไม่มี Factor F อยู่ที่ไหนเลย เพราะบริษัทไม่ได้ใช้ Factor F คิดต้นทุนของตัวเอง เปอร์เซ็นต์ทุกตัว
เป็นนโยบายของบริษัท ไม่มีแหล่งอ้างอิงภายนอกให้ตรวจ และคำถามที่ระบบต้องตอบคือ "กำไรเหลือเท่าไร
ถ้าเหล็กขึ้น 10%" ไม่ใช่ "ราคากลางเท่าไร"

**จุดร่วมคือปริมาณ** ฐานรากขนาด 1.50 × 1.50 × 0.35 ม. มีคอนกรีต 0.788 ลบ.ม. เท่ากันทั้งสองสาย
สิ่งที่ต่างคือชั้นที่บวกทับปริมาณนั้น

โค้ดเคยรับรู้เรื่องนี้แล้วแต่ไม่เคยลงถึงฐานข้อมูล `src/lib/estimation-workflow.ts` ประกาศ
`ProjectPath = "private" | "government"` และ `getWorkflowBlocker` บล็อกขั้นแรกด้วยข้อความ
"เลือกสายงานเอกชนหรือราชการก่อนเริ่มโครงการ" แต่ตาราง `projects` มีแค่ `work_type` ไม่มีคอลัมน์สายงาน
แนวคิดจึงค้างอยู่ใน demo workflow เฉย ๆ

การตัดสินใจนี้กลับยากเพราะมันกำหนดรูปของ `estimate_revisions`, `price_sets` และตารางราคาทั้งหมด
ถ้าเลือกผิดแล้วต้องเพิ่มอีกสายทีหลัง ต้อง migrate revision ของลูกค้าที่คำนวณไปแล้ว จึงบันทึกก่อนลงมือ

## Decision

**ถอดปริมาณชุดเดียว รองรับสองชั้นราคา เลือกด้วย `projects.project_path` และ implement ทีละสาย
โดยเริ่มจากสายราชการ**

1. **ชั้นถอดปริมาณเป็นกลางเรื่องเงิน** `takeoff_runs`, `takeoff_items`, `takeoff_measurements`
   และ `evidence_references` เก็บเฉพาะสิ่งที่วัดได้ วิธีที่วัด และค่าเผื่อ **ห้ามมีคอลัมน์ใดที่พูดถึงราคา
   ต้นทุน กำไร หรือภาษี** ถ้าวันหนึ่งมีคอลัมน์ราคาโผล่ในตารางกลุ่มนี้ แปลว่าสองสายเริ่มรั่วใส่กัน

2. **`projects.project_path` เป็น enum `private | government` และเลือกตอนสร้างโครงการ**
   เปลี่ยนสายกลางคันไม่ได้เมื่อมี revision ที่คำนวณแล้ว เพราะตัวเลขที่ได้คนละความหมายกัน
   ค่านี้บังคับว่าโครงการจะเดินเข้าชั้นราคาไหน

3. **สายราชการ (`government`) ทำก่อน** เพราะทุกตัวเลขมีเอกสารอ้างอิงให้ตรวจคำตอบได้
   ค่าอำนวยการ ค่าดอกเบี้ย และกำไรมาจากตาราง Factor F ที่รัฐประกาศ ระบบ **ไม่เปิดให้ผู้ใช้แก้ตัวเลขเหล่านี้**
   สิ่งที่ผู้ใช้เลือกได้คือเงินล่วงหน้าจ่าย เงินประกันผลงานหัก และงานนี้ต้องชำระ VAT หรือไม่ ซึ่งเป็นตัวเลือก
   ที่ตารางกำหนดไว้ให้เลือก ไม่ใช่ตัวเลขที่กรอกเอง

4. **Factor F เป็นชุดข้อมูลที่มี version และมีที่มา ไม่ใช่ค่าคงที่ในโค้ด** แต่ละ version ต้องบันทึก
   อัตราดอกเบี้ยเงินกู้ที่ตารางนั้นอ้าง (ปัจจุบัน 7% ต่อปี ตามหนังสือ ว499) วันที่ประกาศ checksum ของแหล่ง
   และใครเป็นผู้ตรวจทานตัวเลข เพราะถ้าอัตราดอกเบี้ยประกาศใหม่ ตารางเปลี่ยนทั้งชุด

5. **สายผู้รับเหมา (`private`) ทำทีหลัง** และเปอร์เซ็นต์ทุกตัว (site overhead, office overhead,
   contingency, profit) เป็นค่าที่องค์กรกรอกเองพร้อมบันทึกว่าใครตั้งเมื่อไร ไม่มีค่าเริ่มต้นที่ระบบเดาให้
   เพราะไม่มีแหล่งอ้างอิงใดบอกได้ว่า 5% หรือ 3% ถูกต้องสำหรับบริษัทไหน

6. **`estimate_revisions` เก็บผลลัพธ์ที่คำนวณแล้วพร้อมชื่อสายและ version ของชุดข้อมูลที่ใช้**
   revision ที่คำนวณด้วย Factor F เวอร์ชันหนึ่งต้องอ่านย้อนได้ว่าใช้ตัวไหน แม้ภายหลังจะมีตารางใหม่แล้ว

7. **AI เสนอปริมาณได้ แต่ไม่สร้างราคา** ตาม `PROJECT.md` ข้อ 3 ราคาทุกตัวต้องมาจากรายการที่มีแหล่งอ้างอิง
   ในฐานข้อมูลราคา ข้อนี้ใช้กับทั้งสองสายเท่ากัน

## Alternatives considered

| Alternative | Why not selected now |
|---|---|
| ทำสายราชการอย่างเดียว ไม่ต้องมี `project_path` | ผู้รับเหมาเอกชนคือกลุ่มที่จ่ายเงิน การเติมสายที่สองทีหลังโดยไม่มีรอยต่อไว้ก่อน แปลว่าต้องรื้อ `estimate_revisions` ตอนที่มีข้อมูลลูกค้าแล้ว |
| ทำสายผู้รับเหมาอย่างเดียว | ทุกเปอร์เซ็นต์เป็นค่าที่ผู้ใช้กรอก ไม่มีอะไรให้ตรวจว่าระบบคำนวณถูก สายราชการมีคำตอบที่ถูกต้องอยู่ในเอกสาร จึงเป็นสายที่พิสูจน์ความถูกต้องของเครื่องมือได้จริง |
| **รวมเป็นชั้นราคาเดียวที่ตั้งค่าได้ แล้วมอง Factor F เป็น markup ตัวหนึ่ง** | เป็นทางที่ดูสะอาดที่สุดและผิดที่สุด Factor F ไม่ใช่ markup ที่ตั้งค่าได้ มันเป็นตารางที่ผูกกับช่วงค่างานต้นทุน ต้อง interpolate และ **รวมกำไรไว้ข้างในแล้ว** ถ้าให้ผู้ใช้ตั้ง markup เองแล้วเรียกผลลัพธ์ว่าราคากลาง เขาจะได้ตัวเลขที่หน้าตาเหมือนราคากลางแต่ป้องกันไม่ได้ตอนถูกตรวจ และถ้าเผลอบวกกำไรทับ Factor F อีกชั้นก็จะกำไรซ้อนโดยไม่มีใครเห็น |
| แยกเป็นสอง app | ปริมาณชุดเดียวกันจะถูกถอดสองรอบ ซึ่งขัดกับเหตุผลทั้งหมดของการมี evidence ที่ตรวจย้อนได้ และผู้ใช้คนเดียวกันมักทำทั้งงานราชการและงานเอกชน |
| ให้ `project_path` แก้ภายหลังได้เสมอ | ค่างานที่คำนวณด้วยสองสายมีความหมายคนละอย่าง การสลับสายหลังมี revision แล้วทำให้ตัวเลขเก่าอ่านผิดความหมายโดยไม่มีสัญญาณเตือน |

## Consequences

- **Migration รอบนี้เพิ่ม `projects.project_path`** เป็น enum ใหม่ `project_path` โครงการที่มีอยู่แล้ว
  ต้องมีค่าเริ่มต้น เลือก `government` เพราะเป็นสายที่กำลังจะ implement และเป็นสายที่มีกฎเกณฑ์ชัดกว่า
  ฐานข้อมูลตอนนี้เป็น dev ล้วน จึงยังไม่ต้องมี approval record ตาม AGENTS.md
- **การตรวจสอบความถูกต้องของเครื่องมือทำได้จริง** เพราะเอกสารราชการมีตัวอย่างที่คำนวณเสร็จแล้ว
  test สามารถยืนยันกับตัวเลขจากเอกสารได้ ไม่ใช่ยืนยันกับตัวเลขที่เราคิดเอง
- **ชุดข้อมูลราคาและ Factor F ต้องมีขั้นตอนคนตรวจก่อนใช้** การดึงตัวเลขจาก PDF ด้วย OCR มีข้อผิดพลาดจริง
  ที่ตรวจพบแล้วทั้งในตาราง Factor F และในบัญชีค่าแรง ว809 ตัวเลขที่ยังไม่ผ่านการตรวจต้องใช้คำนวณไม่ได้
- **UI เพิ่มการตัดสินใจหนึ่งข้อที่หน้าสร้างโครงการ** ซึ่งตรงกับที่ `getWorkflowBlocker` คาดหวังไว้แล้ว
  และเป็นการตัดสินใจที่ผู้ใช้ตอบได้ทันทีโดยไม่ต้องเปิดแบบ
- **ค่าใช้จ่ายที่ยอมรับ:** โค้ดชั้นราคาจะมีสองทางเดินตลอดไป ไม่ใช่ทางเดียวที่ตั้งค่าได้ ซึ่งโค้ดยาวกว่า
  แต่เป็นความยาวที่สะท้อนความจริงของโดเมน ไม่ใช่ความซับซ้อนที่เราสร้างขึ้นเอง
- **ถ้าจะเปลี่ยนกลับ** ต้องเขียน ADR ใหม่ และต้องตอบให้ได้ว่าจะทำอย่างไรกับ revision ที่คำนวณด้วยสายเดิมไปแล้ว
