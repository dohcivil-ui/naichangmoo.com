# ADR 0019: ผู้ช่วยเสนอได้ คนเท่านั้นที่ตัดสิน และตัวเลขที่ผิดไม่ได้ไม่เคยข้ามรอยต่อกลับมา

**Status:** Accepted — ฉบับใหม่ ไม่แก้ ADR 0004 · ปิด IP-191 · เป็นฐานของ IP-180 ถึง IP-190

## Context

แพลตฟอร์มกำลังจะตั้งราคาสูงกว่าคู่แข่งด้วยเหตุผลว่ามีผู้ช่วย AI (DIRECTION.md เฟส 5) คำแถลง
ที่ตามมาคือ

> **เสริมพลังให้แอปด้วยผู้ช่วย AI** — ไม่ใช่แค่ทำเร็วขึ้น แต่เป็นผู้ช่วยตรวจสอบงาน
> และตัวเลขทุกตัวชี้กลับไปยังที่มาได้ เพราะเงินทุกบาทระบบเป็นคนคำนวณ ไม่ใช่ AI

ประโยคนี้ขายสามอย่างพร้อมกัน: ตรวจงานได้ · ชี้ที่มาได้ · และ AI ไม่แตะเงิน ทั้งสามข้อเป็นคำสัญญาที่
ตรวจสอบได้ ไม่ใช่คำโฆษณา ถ้าข้อใดข้อหนึ่งไม่จริงแม้แต่ครั้งเดียวในเอกสารที่ลูกค้าเอาไปยื่นราชการ
ความเสียหายไม่ได้จบที่ความเชื่อถือ แต่ไปถึงคนที่เซ็นเอกสารนั้น

ก่อนรุ่นนี้ ของจริงในโค้ดคือ: ผู้ช่วยมีอยู่ตัวเดียว (แผนงาน) กฎทั้งหมดของมันอยู่ในไฟล์ของแอปนั้น
ไฟล์เดียว ปิดด้วย `NODE_ENV` ไม่เคยเรียก `run_ai` ไม่มีเพดาน ไม่มี audit และ **ไม่มีปุ่มปฏิเสธ**
— คำตอบของแบบจำลองทับแผนเดิมทันทีที่มันตอบ แอปที่สองที่อยากมีผู้ช่วยทำได้อย่างเดียวคือก๊อปไฟล์นั้น
ซึ่งจะทำให้สิ่งที่ผิดไม่ได้กระจายไปได้ถึงเจ็ดแอปคูณเจ็ดจังหวะ

ADR 0004 พูดเรื่อง Hermes ไปแล้ว แต่ครอบเรื่องนี้ไม่ได้ Hermes เป็น agent ที่ทำงานเบื้องหลังตามคิว
ผู้ช่วยรายแอปเป็นการเรียกในคำขอของผู้ใช้ที่ล็อกอินอยู่และกำลังมองหน้าจอรออยู่ — blast radius
คนละขนาด ผู้รับผิดคนละคน และวิธีหยุดคนละแบบ จึงเป็นฉบับใหม่ ไม่ใช่การแก้ฉบับเดิม

## Decision

เจ้าของงานวินิจฉัยเมื่อ 2026-08-27:

1. **ผู้ช่วยเสนอ คนตัดสิน** ทุกคำตอบของแบบจำลองออกมาเป็น `AssistantProposal` ที่มีรหัสอ้างอิง
   และต้องผ่าน `settleProposal` จึงจะกลายเป็นข้อมูลจริง ไม่มีเส้นทางไหนที่ค่าจากแบบจำลองไปนั่ง
   ในข้อมูลของผู้ใช้ได้โดยไม่มีคนกด **การปฏิเสธถูกบันทึกเท่ากับการรับ** เพราะอัตราการถูกปฏิเสธ
   คือมาตรวัดเดียวที่บอกได้ว่าผู้ช่วยตัวไหนควรเปลี่ยนรุ่นหรือแก้คำสั่ง
   ข้อเสนอที่ไม่มีใครตัดสินภายใน 24 ชั่วโมงหมดอายุ ตรวจตอนกดตัดสิน ไม่มีงานเบื้องหลังมากวาด
2. **แบบจำลองไม่มีช่องให้กรอกเงิน** `schema` ของทุกทักษะห้ามมีคีย์ที่เกี่ยวกับเงิน มีเทสต์เดินไล่
   ทะเบียนบังคับ (G1) เงินเข้า prompt ได้ทางเดียวคือบล็อกข้อเท็จจริงที่ระบบคำนวณมาแล้ว (G3)
   และสัดส่วนที่แบบจำลองเสนอถูกเกลี่ยด้วย `normaliseWeights` ให้ลงตัวเป๊ะก่อนกลายเป็น satang (G2)
   นี่คือการเปลี่ยนประโยค "AI ไม่คิดเงิน" จากวินัย เป็นโครงสร้างที่พังแล้วเทสต์ตก
3. **ตัวเลขที่ถอดจากเอกสารราชการต้องมีคนเซ็นรับรองก่อน ถ้าจะเอาไปคำนวณ**
   กฎที่บังคับคือ `returnsNumbers === true && source !== null` ⇒ `source.reviewedBy !== null`
   ทักษะที่คืนเฉพาะข้อความจึงอ้างชุดข้อมูลที่ยังไม่มีผู้รับรองได้ **นี่คือขอบเขตของการอนุโลม
   ว 109 ที่เจ้าของงานเคาะ** — อนุโลมเพราะทักษะไม่คืนตัวเลข ไม่ใช่เพราะเรายอมในกรณีนี้
   `computeK` ยังปฏิเสธทุกสูตรต่อไปจนกว่า IP-097 จะมีคนเทียบสัมประสิทธิ์กับหน้าสแกนทีละแถว
4. **ที่มาประกอบจากชุดข้อมูล ไม่ใช่จากแบบจำลอง** ทุกฟิลด์ของ `Citation` รวมถึงเลขข้อและเลขหน้า
   คัดมาจากไฟล์ในรีโป **ห้ามให้แบบจำลองเขียนเลขข้อ** เพราะเลขข้อคือสิ่งที่มันแต่งได้เนียนที่สุด
   และคนตรวจจับได้ยากที่สุด และหลักเกณฑ์ที่ `verified: false` ต้องขึ้นคำเตือนบนจอเสมอ
5. **ค่าใช้จ่ายมีเบรกสามชั้น** ต่อคนต่อเดือน (ถังรวมข้ามแอป หน้าต่างเดือนปฏิทินไทย) · ต่อคนต่อนาที ·
   และค่าใช้จ่ายจริงรวมทั้งแพลตฟอร์มต่อวัน ทะลุแล้วผู้ช่วยดับทั้งระบบ **พร้อมข้อความบอกผู้ใช้
   ไม่ใช่เงียบ** ตรวจสิทธิ์ก่อนนับโควตาเสมอ และนับโควตาเมื่อแบบจำลองตอบสำเร็จเท่านั้น
6. **เงินที่ออกไปต้องมีร่องรอยเสมอ** แถวใน `assistant_proposals` ถูกจองก่อนเรียกแบบจำลอง
   แล้วเติมทีหลัง คำขอที่ล้มกลางทางจึงยังอธิบายได้ว่าจ่ายไปกับอะไร

### รายการความสามารถที่ห้ามให้ รายแอป

| แอป | ห้ามเด็ดขาด | เหตุผล |
|---|---|---|
| ทุกแอป | สร้างหรือแถลงตัวเลขเงินทุกชนิด | ข้อ 2 |
| rcopt | ระบุค่าออกแบบโครงสร้างทุกชนิด | ค่าออกแบบผิด = คนตาย ช่วยได้แค่อธิบายว่าอะไรคือตัวคุมของหน้าตัด |
| escalation-k | เลือกสูตรและคำนวณค่า K หรือเงินชดเชย | ชุดข้อมูลยังไม่มีผู้รับรอง ข้อ 3 |
| ESTIMETR | เลือกแถว Factor F เอง ยืนยันแทนผู้ใช้ ปล่อยเอกสาร ปร. | `reviewedBy` ของ Factor F ยังว่าง (IP-070) |
| PRICEMETR | คืนราคา — คืนได้เฉพาะรหัสรายการ | ระบบไปหยิบราคาของรหัสนั้นเอง สิ่งที่ข้ามรอยต่อกลับมาจึงไม่ใช่เงิน |
| traffic-sign | ขนาด ชนิดแผ่นสะท้อน ความสูงของป้าย | ยังไม่มีชุดข้อมูลคู่มือ ทล. ในรีโป |
| land-acquisition | ไม่ทำผู้ช่วยในรีโปนี้ | ค่าทดแทนคือสิทธิ์ตามกฎหมายของประชาชน และข้อมูลเจ้าของที่ดินห้ามเข้า prompt |

## Alternatives considered

| Alternative | Why not selected |
|---|---|
| แก้ ADR 0004 ให้ครอบผู้ช่วยรายแอปด้วย | Hermes เป็น agent เบื้องหลังตามคิว ผู้ช่วยรายแอปเป็น sync call ของผู้ใช้ที่ล็อกอิน วิธีหยุด ขนาดความเสียหาย และผู้รับผิดคนละแบบ การรวมสองเรื่องไว้ในฉบับเดียวจะทำให้ข้อจำกัดของฝั่งหนึ่งถูกอ้างผิดฝั่ง |
| ห้าม AI แตะเงินด้วยการเขียนไว้ใน prompt | prompt คือคำขอ ไม่ใช่การบังคับ แบบจำลองทำตามเกือบทุกครั้ง ซึ่งแปลว่าครั้งที่ไม่ทำตามจะหลุดถึงหน้าจอโดยไม่มีใครดัก กฎที่ไม่มีเทสต์คือกฎที่พังเงียบ |
| ให้ผู้ช่วยเขียนค่าลงข้อมูลจริงได้เมื่อมั่นใจสูง | ไม่มีนิยามของ "มั่นใจ" ที่ตรวจสอบได้ และผู้ที่รับผิดตามกฎหมายคือคนที่เซ็นเอกสาร ไม่ใช่ผู้ให้บริการซอฟต์แวร์ ปุ่มปฏิเสธจึงไม่ใช่ทางเลือกของ UX แต่เป็นเส้นแบ่งความรับผิด |
| ปลด `reviewedBy` ของ ว 109 ทั้งหมดเพราะเอกสารมีอยู่จริง | เอกสารมีอยู่จริงกับตัวเลขถอดถูกเป็นคนละคำถาม ว 109 เป็นภาพสแกนล้วนที่สคริปต์เดิมเคยอ่านผิดมาแล้ว การตรวจซ้ำด้วยเงื่อนไข "สัมประสิทธิ์รวมได้ 1.000" จับการสลับเลขที่ยังรวมได้เท่าเดิมไม่ได้ จึงอนุโลมเฉพาะทักษะที่ไม่คืนตัวเลข |
| ตั้งเพดานเป็นจำนวน token | ผู้ใช้ไม่มีทางรู้ว่า token คืออะไร คำสัญญาเชิงพาณิชย์ที่นับไม่ได้ด้วยสายตาผู้ซื้อคือคำสัญญาที่จะถูกเถียงทุกเดือน จึงนับเป็นครั้งให้ผู้ใช้เห็น แล้วใช้เบรกค่าใช้จ่ายจริงเป็นชั้นหลังบ้าน |

## Consequences

- `src/server/ai/assistant.ts` เป็นประตูเดียว และมันไม่รู้จักชื่อแอปสักตัว เพิ่มผู้ช่วยให้แอปใหม่คือ
  เพิ่มแถวในทะเบียนทักษะ ไม่ต้องแก้ประตู
- migration `0009`: ตาราง `assistant_proposals` และ enum `assistant_decision` — และเป็นการใช้งานจริง
  ครั้งแรกของ `before_hash` กับ `after_hash` ใน `audit_events` ซึ่งว่างทั้งคอลัมน์มาตลอด
- เหตุการณ์ใหม่ใน `audit_events`: `ai.proposed` `ai.accepted` `ai.rejected` `ai.partially_accepted`
  `ai.expired` โดย `correlation_id` คือรหัสข้อเสนอ
- ผู้ดูแลแพลตฟอร์มใช้ผู้ช่วยของแอปที่ยังไม่เปิดได้ เพื่อทดสอบก่อนเปิดขาย โดยมีโควตาแยกของตัวเอง
  และทุกครั้งลงบันทึกว่าเป็นการใช้สิทธิ์ผู้ดูแล ไม่ปนกับการใช้ของลูกค้า
- คำแถลง "แอปนี้มีผู้ช่วย AI" **ยังไม่ขึ้นหน้าขาย** จนกว่า IP-190 จะให้ทะเบียนเป็นเจ้าของประโยคนั้น
  ตาม ADR 0015 และ ADR 0018 — วันนี้ยังไม่มีแอปไหนที่ลูกค้ากดใช้ผู้ช่วยได้จริง
- ผู้ช่วยแผนงานตัวเดิมยังเดินเส้นทางเก่าอยู่จนกว่า IP-184 จะย้ายหน้าจอมาที่ประตูนี้ ซึ่งเป็นรุ่นที่
  ปุ่มปฏิเสธจะไปถึงมือผู้ใช้จริง
