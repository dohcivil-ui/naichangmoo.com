# ADR 0010: ข้อความทดลองใช้เป็นประโยคเดียวทุกที่ก่อนเข้าใช้งาน

**Status:** Accepted — supersedes the `marketDetail.availabilityNote` row in the ADR 0009 decision table · amended by ADR 0018 (2026-08-26): the sentence's public copy now lives in the registry as `apps.availability_note`, and the value in `platform.ts` is only the suggestion an administrator sees in the back office

## Context

ADR 0009 แยกข้อความก่อนเข้าใช้งานเป็นสองชั้น พาดหัวไม่บอกเพดาน 1 โครงการ แต่หน้ารายละเอียดแอปยังบอก ด้วยเหตุผลว่าหน้านั้นมีหน้าที่เป็น truthful pre-entry detail ตาม `docs/requirements/civil-apps-market.md`

เจ้าของงานตรวจผลจริงแล้วปฏิเสธเส้นแบ่งนั้น ข้อความ `"ทดลองใช้ได้ 7 วัน 1 โครงการ โดยปิดการส่งออกและพิมพ์"` บนหน้ารายละเอียดแอปให้ผลตรงข้ามกับที่ ADR 0009 ตั้งใจ เพราะมันเรียงข้อจำกัดสามข้อติดกันในประโยคเดียว โดยที่ผู้อ่านยังไม่รู้ว่าเครื่องมือทำอะไรได้ กล่องนั้นอยู่ใต้หัวข้อ "การเข้าใช้งาน" ซึ่งเป็นกล่องที่ควรตอบว่า *เข้าได้อย่างไร* ไม่ใช่ *เข้าแล้วทำอะไรไม่ได้*

ผู้เขียน ADR 0009 แย้งข้อนี้ไว้แล้วครั้งหนึ่งและเจ้าของงานยืนยันการตัดสินใจ ADR นี้บันทึกทั้งการตัดสินใจและข้อแย้ง เพื่อให้คนที่มาอ่านทีหลังเห็นว่าอะไรถูกชั่งแล้ว

## Decision

`marketDetail.availabilityNote` ของ ESTIMETR เป็น **"ทดลองใช้งานฟรี 7 วัน"** ประโยคเดียว ไม่มีเพดานโครงการ ไม่มีการล็อก export และ print

ผลคือ **ทุกพื้นผิวก่อนเข้าใช้งานพูดประโยคเดียวกัน** พาดหัว ปุ่มเข้าใช้ และกล่องการเข้าใช้งานบนหน้ารายละเอียด ล้วนบอกแค่ว่าทดลองใช้ฟรี 7 วัน เส้นแบ่งจาก ADR 0009 ที่แยกพาดหัวออกจากรายละเอียดถูกยกเลิก แทนด้วยเส้นแบ่งที่ตรงกว่า: **ก่อนเข้าใช้งาน พูดประโยคเดียว ตอนตกลงและตอนใช้งาน บอกครบ**

สิ่งที่ **ไม่เปลี่ยน** จาก ADR 0009:

| จุด | ยังบอกเงื่อนไขครบ | เหตุผล |
|---|---|---|
| หน้าจอกดเริ่มทดลองใช้ (`trial-activation.tsx`) | ใช่ — 7 วัน, 1 โครงการ, ล็อก export/print, read-only retention | เป็นจุดที่ผู้ใช้ตกลงรับเงื่อนไข เจ้าของงานเลือกให้คงไว้ที่นี่ตั้งแต่รอบ ADR 0009 |
| ตัวนับในแอป (`entitlement-status.tsx`, `apps/estimeter/page.tsx`) | ใช่ | เป็นสถานะจริงของบัญชี |
| การบังคับใช้ (`STATE_POLICY.trial`, `ESTIMETR_TRIAL_LIMITS`) | ใช่ — `projectLimit` ยังเป็น `1` | ADR นี้เปลี่ยนข้อความ ไม่ได้เปลี่ยนสิ่งที่เซิร์ฟเวอร์บังคับใช้ |

## Alternatives considered

| Alternative | Why not selected now |
|---|---|
| คงเส้นแบ่งของ ADR 0009 ไว้ | เจ้าของงานตรวจผลจริงแล้วปฏิเสธ กล่อง "การเข้าใช้งาน" ที่เรียงข้อจำกัดสามข้อคือคำตอบผิดคำถาม |
| ตัดเพดานออกจากหน้าจอกดเริ่มด้วย ให้ประโยคเดียวทั้งระบบ | ผู้ใช้จะกดตกลงโดยไม่รู้เงื่อนไข แล้วไปเจอกำแพงตอนสร้างโครงการที่สอง ADR 0009 ปฏิเสธข้อนี้ไปแล้วและ ADR นี้ไม่รื้อ |
| ย้ายเงื่อนไขไปเป็นลิงก์ "ดูเงื่อนไขทั้งหมด" บนหน้ารายละเอียด | เพิ่มพื้นผิวที่ต้องดูแลและต้องตัดสินใจเรื่องเนื้อหาอีกชุด ยังไม่มีเหตุจำเป็นตอนนี้ หน้าจอกดเริ่มทำหน้าที่นี้อยู่แล้ว |
| ปลดเพดาน 1 โครงการออกจริง ให้ข้อความตรงกับการบังคับใช้ | เป็นการเปลี่ยนเชิงพาณิชย์ ไม่ใช่การเปลี่ยนข้อความ อยู่นอกขอบเขตที่เจ้าของงานสั่ง |

## Consequences

**ความเสี่ยงที่รับไว้อย่างรู้ตัว** ผู้ใช้ที่อ่านเฉพาะพื้นผิวก่อนเข้าใช้งานจะไม่รู้เรื่องเพดาน 1 โครงการจนถึงหน้าจอกดเริ่ม ความเสี่ยงถูกจำกัดด้วยข้อเท็จจริงว่าหน้าจอกดเริ่มมาก่อนการใช้สิทธิ์เสมอ ไม่มีเส้นทางใดที่ทำให้สิทธิ์ทดลองใช้เริ่มเดินโดยผู้ใช้ไม่ผ่านหน้าจอนั้น — Gate 2 ของ ADR 0006 บังคับไว้

**Testing** `platform.test.ts` ตรวจแค่ว่า `availabilityNote` ไม่ว่าง จึงไม่แดงจากการเปลี่ยนนี้ ควรเพิ่ม assertion ว่าข้อความก่อนเข้าใช้งานไม่มีคำว่า `โครงการ` เพื่อให้การถอยกลับโดยไม่ตั้งใจถูกจับได้ เช่นเดียวกับที่ `accessLabel` ถูกจับไว้แล้ว

**Requirements** `docs/requirements/civil-apps-market.md` ระบุว่าเพดานยังบอกที่หน้ารายละเอียดแอป ประโยคนั้นต้องแก้ให้ตรงกับ ADR นี้

**Security and data** ไม่มีผล ไม่แตะสิทธิ์ ความลับ หรือ migration
