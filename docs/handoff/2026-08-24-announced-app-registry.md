## สิ่งที่เปลี่ยน

การ์ด **สมาชิกใช้ฟรี** บน `/pricing` เคยพิมพ์ `"Retaining Wall Cantilever และ TRAFFIC SIGN"` ไว้ใน `highlights` และเชิงอรรถเคยพิมพ์ `LAND ACQUISITION V2` ไว้อีกที่ ทั้งสองคือคำแถลงต่อสาธารณะที่ไม่มีใครเป็นเจ้าของ ตอนนี้ทั้งคู่มาจากทะเบียนที่ผู้ดูแลประกาศ

**ตัดสินใจสำคัญ 4 ข้อ (ทั้งหมดอยู่ใน ADR 0014)**

1. **แถวในตารางไม่ใช่คำประกาศ** `activateEstimeterTrial()` แทรกแถวเองตอนลูกค้าคนแรกกดเริ่มทดลองใช้ โดยไม่มีผู้ดูแลเกี่ยวข้อง migration 0006 จึงเพิ่ม `announced_at` + `announced_by` และนั่นคือสิ่งเดียวที่หน้าสาธารณะอ่านเป็นคำแถลงได้
2. **การประกาศไม่ใช่การให้สิทธิ์** ยังไม่มีเส้นทางใดออกแถว `member_free` ให้ใคร แอปที่ประกาศเป็นสมาชิกใช้ฟรีจึง **ตั้งเป็นเปิดใช้แล้วไม่ได้** บังคับที่เซิร์ฟเวอร์และมีเทสต์ — IP-093 คือสิ่งที่ลบข้อห้ามนี้ อย่างตั้งใจ
3. **ถอนคำประกาศคือล้าง `announced_at` ไม่ใช่ลบแถว** `app_entitlements.app_id` เป็น `ON DELETE CASCADE` การลบแถวทะเบียนจะลากสิทธิ์ของลูกค้าหายไปด้วย ซึ่ง ADR 0013 ห้ามที่สุด
4. **ไม่ทำระบบ feature flag กลาง** วันนี้มีของให้เปิดปิดอย่างเดียวคือแอป และ `apps.enabled` คือสวิตช์นั้นอยู่แล้ว ตาราง flag เพิ่มเข้ามาจะได้สองสวิตช์คุมหลอดเดียวกัน สิ่งที่รับมาแทนคือรูปทรง — `src/server/app-registry.ts` เป็นทางเข้าเดียว ไม่มีหน้าไหนยิงตาราง `apps` เอง

`readAnnouncedApps()` ตัดสิน "ประกาศแล้ว" ใน TypeScript ไม่ใช่ใน `WHERE` โดยตั้งใจ เพราะกฎข้อที่ทั้งรอบนี้หมุนรอบมันคือกฎที่ต้องมีเทสต์ยืนยันได้ และตารางนี้มีแถวละแอปตลอดไป

## เซสชันหน้าต้องรู้

### ยังไม่ได้รัน และเป็นเงื่อนไขของการใช้งานจริง

```bash
pnpm db:migrate                                    # 0005, 0006 และ 0007 ของอีกเซสชัน
node scripts/grant-platform-admin.mjs <อีเมล>      # คนนั้นต้องเคยล็อกอินแล้ว
```

จนกว่าจะรันสองคำสั่งนี้ `/admin` ปฏิเสธทุกคน และ `/admin/apps` จะขึ้น "อ่านทะเบียนแอปไม่ได้" ส่วนการ์ดสมาชิกใช้ฟรีจะเงียบ — **ทั้งสามอย่างคือ fail-closed ที่ตั้งใจ ไม่ใช่บั๊ก**

### IP-094 — พรีวิวที่ยังไม่ได้ทำ ไล่ตามลำดับนี้

1. `/pricing` ตอนทะเบียนว่าง → การ์ดไม่เอ่ยชื่อแอปใดเลย และไม่มีเชิงอรรถ
2. `/admin/apps` → ประกาศ `rcopt` เป็นสมาชิกใช้ฟรี ยังไม่เปิดใช้ พร้อมเหตุผล
3. ลองตั้งสมาชิกใช้ฟรี + เปิดใช้แล้ว → ปุ่มต้องถูกปิดและคำเตือนต้องขึ้น **ก่อน** กด
4. ประกาศ `estimeter` เป็นสมาชิกใช้ฟรี → ต้องขึ้นเตือนว่าขัดกับค่าตั้งต้น แต่ยังบันทึกได้
5. `/pricing` อีกครั้ง → ขึ้นชื่อแอปพร้อมกำกับกำลังเตรียมระบบ
6. `/apps/rcopt` → หน้ากำลังเตรียมระบบ ไม่ใช่หน้าทำงาน
7. `/admin` → เห็น `app.announced_by_administrator` ในการ์ดบันทึกการเปลี่ยนแปลง
8. ถอนคำประกาศ → ชื่อหายจาก `/pricing` และสิทธิ์ใน `/admin/entitlements` ยังอยู่ครบ
9. ดูด้วยตาว่า eyebrow บนการ์ดหน้าราคาอ่านออกแล้ว (แก้ contrast ไปในรอบนี้)

### บทเรียนเรื่องหลายเซสชันในไดเรกทอรีเดียว

เซสชันนี้ทำงานพร้อมกับอีกสองเซสชันใน worktree เดียวกัน และเกิดของจริงสองอย่าง

- ผมใช้ `git reset --hard` ตอนแก้ commit message ซึ่ง **ลบงานที่ยังไม่ commit ของอีกเซสชันไปด้วย** กู้คืนได้ครบเพราะยังมี diff อยู่ในบริบท — **ห้ามใช้ `reset --hard`, `checkout --`, `stash`, `clean` ใน worktree ที่แชร์กัน** ถ้าต้องแก้ประวัติ ใช้ `commit-tree` + `reset --soft`
- การเขียนไฟล์ทับ dev server ที่คนอื่นเปิดอยู่ ทำให้เขาเห็น error ที่ไม่ใช่บั๊กของเขา ควรบอกก่อนเริ่ม ไม่ใช่บอกตอนเขาไล่ไปครึ่งทางแล้ว
