# Handoff — `v0.30.0: Someone To Check Against`

ข้าม `/grill-with-docs` ตาม AGENTS.md ข้อ 1 เพราะการตัดสินใจทั้งหมดของรอบนี้ถูกซักและบันทึกใน ADR 0012 ซึ่งมีตารางทางเลือกที่พิจารณาแล้วห้าข้อ กระบวนการที่บังคับให้เขียน alternatives considered ทำหน้าที่เดียวกับการซักถาม

## Description

ก่อนรอบนี้ระบบไม่มีแนวคิดผู้ดูแลแพลตฟอร์มเลย `member_role` ที่มีอยู่ (`owner/admin/member/viewer`) ผูกกับ `organization_members` คือเป็น admin ของ *องค์กรหนึ่ง* ไม่ใช่ของแพลตฟอร์ม จึงไม่มีใครที่ระบบจะตรวจสิทธิ์ด้วยได้เมื่อมีคนขอแก้ราคาหรือตั้งโปรโมชัน นี่คือเหตุผลที่ IP-078 ต้องมาก่อนทั้ง admin panel และการตั้งโปรโมชันจากหลังบ้าน

ADR 0012 ทำให้สิทธิ์นี้เป็น **แถวที่ถูกมอบให้** ไม่ใช่ธงบนบัญชีและไม่ใช่รายชื่ออีเมลใน env เพราะคำถามที่การตรวจสอบจะถามคือ *"วันที่ 15 มีนาคม ใครแก้ราคาได้บ้าง"* ซึ่งคอลัมน์ที่เก็บสถานะปัจจุบันตอบไม่ได้ แถวที่ถูกถอนจึงไม่ถูกลบ

## สองการตัดสินใจที่ควรอ่านก่อนขยายระบบนี้

**ขอบเขตถูกจำกัดไว้โดยเจตนา** ผู้ดูแลแพลตฟอร์มดูแลเนื้อหาของแพลตฟอร์มและตัวเลขสรุปเชิงรวม **ไม่มีสิทธิ์อ่านโครงการ แบบก่อสร้าง บรรทัดวัด หรือชุดราคาของลูกค้ารายใด** ข้อมูลเหล่านั้นยังอยู่หลัง `projects.organization_id` เหมือนเดิม การรวมสองอย่างเข้าด้วยกันจะทำให้บัญชีเดียวที่ถูกยึดกลายเป็นการรั่วของข้อมูลทั้งแพลตฟอร์ม ถ้าวันหน้าต้องการสิทธิ์ช่วยเหลือลูกค้าที่เห็นข้อมูลได้ ต้องเป็นสิทธิ์คนละตัวที่มีการยินยอมและมีอายุจำกัด

**การตรวจ fail closed ทุกทาง** `resolvePlatformAdmin()` ปฏิเสธเมื่อไม่มี session, ไม่มีแถว, แถวถูกถอน และ **เมื่ออ่านฐานข้อมูลไม่ได้** ข้อสุดท้ายคือจุดที่ระบบส่วนใหญ่พลาด เพราะ "ตรวจไม่ได้ก็ปล่อยไปก่อน" ดูเหมือนความยืดหยุ่นแต่คือประตูที่เปิดค้าง

## Security and data impact

**มี migration** `drizzle/0005_unknown_chat.sql` เพิ่มตารางเดียวและไม่แก้ตารางใด **ยังไม่ได้ apply กับฐานข้อมูลใด** ต้องรัน `pnpm db:migrate` ตอน deploy

สิทธิ์ใหม่นี้ไม่ขยายการเข้าถึงข้อมูลลูกค้าแม้แต่แถวเดียว หน้าแรกของหลังบ้านนับจำนวนเท่านั้น และกรองเหตุการณ์ที่มี `organization_id` ออกจากรายการล่าสุด

`scripts/grant-platform-admin.mjs` ต้องการ `DATABASE_URL` และ **ไม่พิมพ์มันออกมา** สคริปต์ล็อกตารางด้วย `SHARE ROW EXCLUSIVE` ระหว่างตรวจและเขียน เพื่อไม่ให้สองการรันพร้อมกันมองเห็นตารางว่างทั้งคู่แล้วต่างคนต่างคิดว่าตัวเองคือ bootstrap

## Risk

ระบบที่ยังไม่รันสคริปต์จะเข้าหลังบ้านไม่ได้เลย ซึ่งเป็นพฤติกรรมที่ต้องการ ไม่ใช่ข้อบกพร่อง

การถอนผู้ดูแลคนสุดท้ายทำได้ และจะทำให้ระบบกลับไปสู่สภาพที่ต้องใช้สคริปต์ bootstrap อีกครั้ง ADR 0012 เลือกแบบนี้โดยตั้งใจ เพราะกฎห้ามถอนคนสุดท้ายจะสร้างบัญชีที่ถอนไม่ได้ ซึ่งแย่กว่า

เมนูในหลังบ้านแสดงหัวข้อที่ยังไม่มีหน้าอยู่ด้วย โดยติดป้าย "ยังไม่เปิด" และกดไม่ได้ เลือกแบบนี้เพราะเมนูที่ค่อย ๆ งอกขึ้นเงียบ ๆ ไม่บอกใครว่าระบบจะทำอะไรได้บ้าง และลิงก์ที่พาไปหน้าที่ยังไม่เสร็จแย่กว่าลิงก์ที่บอกว่ายังไม่พร้อม
