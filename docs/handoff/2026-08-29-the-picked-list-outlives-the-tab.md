# v0.93.0 — รายการที่หยิบไว้อยู่ได้นานกว่าแท็บ

**วันที่** 2026-08-29 · **สาขา** `initial-project/nextjs-foundation` · **รายการ** IP-163, IP-215

---

## หนึ่ง — ปัญหาที่แก้

รุ่นก่อนปิดท้ายด้วยหนี้ที่จดไว้ตรง ๆ ใน ADR 0023 ว่า **เพดาน 50 บรรทัดยังบังคับที่หน้าจอ**
เซิร์ฟเวอร์บอกตัวเลขได้อย่างเดียวแต่ยังปฏิเสธไม่ได้ เพราะรายการที่หยิบไว้อยู่ในหน่วยความจำ
ของหน้า ไม่มีทรัพยากรฝั่งเซิร์ฟเวอร์ให้ปกป้อง ใครเรียก server action ตรงก็หยิบเกินได้

และปัญหาต้นทางของ IP-163 เอง คือปิดแท็บแล้วรายการหาย เปลี่ยนเครื่องแล้วต้องหยิบใหม่หมด
ส่งต่อเข้างานประมาณราคาไม่ได้เลย

## สอง — สามเรื่องที่เจ้าของงานเคาะก่อนเขียนโค้ด

1. **ตะกร้าเป็นขององค์กร ไม่ใช่ของคน** จดว่าใครหยิบทั้งระดับใบและระดับบรรทัด
   เพราะโครงการปลายทางเป็นขององค์กรอยู่แล้ว ตะกร้าส่วนตัวจะข้ามไปหาโครงการขององค์กร
   ไม่ได้โดยไม่มีใครอธิบายได้ว่าใครอนุญาต
2. **ตารางของตัวเอง แยกจาก `price_sets`** ไม่ใช่ทำให้ `project_id` ว่างได้
3. **ส่งเข้า ESTIMETR คือคัดลอกเป็นชุดราคาที่นิ่ง ตะกร้ายังอยู่**

## สาม — สิ่งที่เปลี่ยน

**สามตารางใหม่ migration 0012 เพิ่มล้วน**

| ตาราง | ถืออะไร |
|---|---|
| `price_baskets` | ใบเดียวต่อองค์กร มี `created_by` |
| `price_basket_lines` | บรรทัดที่แก้ได้ มี `added_by` และช่องหลักฐานหกช่อง |
| `price_set_lines` | สำเนาที่นิ่ง ผูกกับ `price_sets` ที่มีอยู่แล้วแต่ไม่เคยมีใครเขียนลง |

**ช่องหลักฐานหกช่อง** `source_key` · `catalog_code` · `province_code` · `effective_month` ·
`document_page` · `rate_condition` — เดิมหน้าจอเก็บแค่ชื่อ หน่วย ราคา จำนวน ซึ่งพอสำหรับ
คูณให้ดูบนจอ แต่ไม่พอสำหรับใบสรุปที่เอกสารเส้นแบ่งสัญญาไว้
**เก็บตอนหยิบ ไม่ใช่ตอนส่งออก** เพราะตอนส่งออกเดือนอาจเปลี่ยนไปแล้ว แล้วเราจะไม่มีทางรู้
ว่าตอนเขากดหยิบเขาเห็นราคาของเดือนไหน

**เพดานเริ่มปฏิเสธได้จริง** การนับอยู่ในทรานแซกชันเดียวกับการเขียน ไม่ใช่ตรวจก่อนแล้วค่อยเขียน
เพราะสองแท็บที่กดพร้อมกันตอนอยู่ที่ 49 บรรทัดจะผ่านการตรวจทั้งคู่แล้วได้ 51
ส่วนการหยิบซ้ำชนดัชนีที่ฐานข้อมูล และไม่นับเป็นการเกินเพดาน

**หน้าจอเดาไปก่อน เซิร์ฟเวอร์ชนะเสมอ** บรรทัดขึ้นจอทันทีไม่ต้องรอเครือข่าย
ถ้าเซิร์ฟเวอร์ปฏิเสธก็ถอยกลับพร้อมเหตุผลจริงจากเซิร์ฟเวอร์ ไม่ใช่เหตุผลที่หน้าจอเดาเอง

**ปุ่มส่งเข้า ESTIMETR** เลือกโครงการของตัวเอง โครงการขององค์กรอื่นถูกปฏิเสธที่เซิร์ฟเวอร์
`payloadHash` คิดจากบรรทัดที่คัดลอกจริง และมีบันทึกตรวจสอบ `price_set.created_from_basket`

**ของกลางที่ขยับ** `ensurePersonalOrganization` ย้ายจาก `estimeter-access.ts` ไป `app-access.ts`
เพราะสองแอปต้องใช้ด่านที่หนึ่งของ ADR 0006 เหมือนกัน สำเนาที่สองของกติกาการตั้ง id
จะเพี้ยนวันที่มีใครแก้ข้างเดียว · เพิ่ม `priceCatalogueItems` กับ `platformChannels`
เข้า `schema` ที่หายไปตั้งแต่ตอนสร้าง

## สี่ — บั๊กที่เจอระหว่างทาง

**ที่มาของบรรทัดถูกแช่เป็นข้อความตั้งแต่ตอนหยิบ** โดยประกอบจากจังหวัดที่ **กำลังเลือกอยู่**
หยิบราคาเชียงใหม่แล้วสลับไปสงขลา ข้อความเก่ายังบอกเชียงใหม่ถูกอยู่ก็จริง แต่พอรายการ
ถูกอ่านกลับจากฐานข้อมูล ข้อความนั้นไม่มีแล้ว เหลือแต่รหัสจังหวัดที่ถูกต้อง
รุ่นนี้จึงเลิกเก็บข้อความ สร้างจากหลักฐานทุกครั้ง และแยกชื่อจังหวัดของบรรทัดออกจาก
จังหวัดที่กำลังเลือกอยู่ — บั๊กเดิมที่ไม่มีใครเห็นเพราะรายการไม่เคยอยู่ข้ามรอบ

## ห้า — ตรวจของจริง

- **เทสต์ที่แตะฐานข้อมูลจริง 11 ข้อผ่านครบ** เปิดด้วยธง `PRICE_BASKET_DB_TESTS=1`
- **พิสูจน์ว่าเพดานกัด** ถอดการกันออกชั่วคราว แดงสองข้อทันที ทั้งคำตอบของฟังก์ชัน
  และ **จำนวนแถวจริงในฐานข้อมูล** ที่กลายเป็น 50 แทน 49 แล้วใส่กลับ
- **เปิดของจริงใน Edge** หยิบสามบรรทัด รีโหลดหน้า **รายการกลับมาครบสามบรรทัด**
  ยอดรวม 8,790 บาทตรง ที่มาถูกต้อง
- **ยิงคิวรีเข้าฐานข้อมูลตรง ๆ** เห็นแถวจริงพร้อม `catalog_code` `effective_month`
  `source_key` และ `added_by` ครบ — ไม่ใช่ของที่อยู่ในเบราว์เซอร์
- **กดปุ่มส่งเข้า ESTIMETR** แผงเลือกโครงการขึ้นถูกต้อง และรายงานตามจริงว่าบัญชีนี้
  ยังไม่มีโครงการ
- **390px** แผงกว้าง 362px ไม่ล้นแนวนอน พื้นทึบสนิท แล้วล้าง emulation แล้ว
- **ลบแถวที่เกิดจากการทดสอบออกจากฐานข้อมูลของเจ้าของงานแล้ว**
- lint typecheck สะอาด · เทสต์ **813 ผ่าน** จาก 808

## หก — สิ่งที่ยังไม่ได้ทำ พูดให้ชัด

**เส้นทางส่งเข้าโครงการยังไม่ได้กดจริงในเบราว์เซอร์** เพราะบัญชีของเจ้าของงานยังไม่มีโครงการ
ใน ESTIMETR การสร้างโครงการต้องกดเปิดทดลองใช้ก่อนตาม ADR 0006 ซึ่งเป็นสิ่งที่เจ้าของงาน
ต้องกดเอง ผมจึงไม่สร้างโครงการปลอมไว้ในบัญชีจริง · **เส้นทางนั้นพิสูจน์แล้วด้วยเทสต์ที่แตะ
ฐานข้อมูลจริง** ครบทั้งการคัดลอก การนิ่งหลังส่ง การปฏิเสธโครงการขององค์กรอื่น และบันทึกตรวจสอบ

**ยังไม่มีหน้าฝั่ง ESTIMETR ที่แสดงชุดราคาที่รับมา** รุ่นนี้ทำฝั่งส่ง ฝั่งรับยังไม่มีจอ

## เจ็ด — งานถัดไป

- หน้าฝั่ง ESTIMETR ที่แสดงชุดราคาที่รับมาและผูกเข้ากับ revision
- **IP-213** วัดต้นทุน token ต่อทักษะ ทำได้เมื่อระบบเสร็จกว่านี้ · บล็อก IP-081 อยู่
- **IP-209 / IP-210** `color-mix` แปดจุด และคอนทราสต์สี่จุด
- **IP-166** ตราประจำแอป PRICEMETR · **IP-161** ว809 หน้าสแกน
- ยังไม่ได้ตรวจธีมของหน้า `/account` และหน้าย่อยของ ESTIMETR
