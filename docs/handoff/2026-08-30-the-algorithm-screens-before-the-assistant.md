ที่ถูกคือ `docs/roadmap/CHANGELOG.md` บรรทัดที่ 3 เขียนไว้ชัดว่า **v0.92.0 ถึง v0.95.0

## สอง — สิ่งที่รุ่นนี้ห่อไว้

สี่ commit จากเซสชันก่อน ทั้งหมดอยู่ในเส้นทางเดียวคือทำให้ฉบับคำนวณมีบรรทัด BOQ ของตัวเอง

| รายการ | เรื่อง |
|---|---|
| IP-217 | ตาราง `boq_items` กับ migration `0014` ผู้ช่วยเสนอคู่ คนกดรับทีละคู่ |
| IP-218 | หมวดงานครบตามที่ใบ ปร.4 แยก และ BOQ แสดงแยกหมวดพร้อมยอดของหมวด |
| IP-219 | อัลกอริทึมสามชั้นคัดกรองก่อน แบบจำลองตัดสินเฉพาะคู่ที่สูสี |
| IP-220 | คำโฆษณาวิธีทำงานที่ทุกข้อชี้ไฟล์เทสต์ซึ่งพิสูจน์มันได้ |

หัวใจของรุ่นคือ **หน้าที่ของอัลกอริทึมเป็นการคัดกรองและรับประกัน ไม่ใช่การตัดสิน** Hungarian
จับคู่ทั้งใบพร้อมกันจึงรับประกันหนึ่งรายการต่อหนึ่งราคาด้วยตัวมันเอง ไม่ต้องพึ่งคำสั่งที่บอกแบบจำลอง
ว่าห้ามใช้ซ้ำ ส่วนคู่ที่คะแนนสูสีเกินกว่าจะตัดสินด้วยการเทียบชื่อ ระบบบอกว่าไม่ชัดและยกตัวเลือก
ให้ดู ตาม ADR 0019 ที่ว่าผู้ช่วยเสนอได้ แต่คนเป็นคนตัดสิน

## สาม — ตรวจของจริง

**ฐานข้อมูล** migration `0014` ลงจริงแล้ว นับได้ 15 ชุด · `boq_items` ครบสิบคอลัมน์
· index ครบสามตัว รวม unique ของ `revision_id` กับ `takeoff_item_id` · มีบรรทัดที่รับไว้ 1 บรรทัด

**เบราว์เซอร์ Edge เดินเส้นทางจริงหนึ่งรอบ** เปิดหน้าโครงการ อาคารเรียน 4 ชั้น โรงเรียนบ้านหนองแวง
แล้วกดปุ่มให้ผู้ช่วยจับคู่ ได้ผลว่า **อัลกอริทึมตัดสินเอง 0 คู่ ผู้ช่วยช่วยตัดสินอีก 1 คู่**
ตรงกับที่ IP-219 วัดไว้ว่าคู่นี้สูสีเกินกว่าจะตัดสินด้วยการนับคำ ผู้ช่วยอธิบายกลับมาเองว่าหน่วยตรงกัน
เป็น ลบ.ม. และกำลังอัด 240 ตรงกับบรรทัด P3 · ปุ่มรับปิดอยู่จนกว่าจะติ๊ก และมีคำเตือนว่ายังไม่มั่นใจเต็มที่
· กด ไม่รับชุดนี้ เพื่อไม่ให้มีบรรทัดใหม่เข้าใบ

**แผง BOQ** หมวดงานโครงสร้าง 32,292 บาท ตรงกับ 2,990 คูณ 10.8 ทุกบาท และบรรทัดบอกที่มาว่า
ผู้ช่วยเสนอและมีคนรับ ความมั่นใจ สูง · **แผงคำโฆษณา** ขึ้นครบหกข้อใต้ยอดรวมของฉบับ

**เทสต์** `pnpm lint` และ `pnpm typecheck` สะอาด · `pnpm test` ผ่าน 864 ข้าม 64 จาก 928

## สี่ — อาการ 500 ที่ไม่ใช่บั๊กของโค้ด

รอบแรกที่กดเรียกผู้ช่วย หน้าจอขึ้นว่าเรียกผู้ช่วยไม่สำเร็จ และ server action ตอบ 500
ไล่ดูจนถึงต้นทาง พบว่าเป็น dev server ที่ค้างมาจากเซสชันก่อนตายไปแล้ว โดย log ที่
`.next/dev/logs/next-development.log` บอกว่า `Jest worker encountered 2 child process
exceptions` แล้วตามด้วย `write EPIPE` **หน้าเว็บที่เป็น GET ยังเรนเดอร์ได้ แต่ worker
ที่รับ server action ตายไปแล้ว** จึงเห็นเป็น 500 เฉพาะตอนกดปุ่ม

ปิด process เดิมด้วย `taskkill` แล้วเปิด `pnpm dev` ใหม่ อาการหายทันทีและเส้นทางเดินจบ
**ไม่มีโค้ดถูกแก้เพราะเรื่องนี้** และ Next 16 ไม่ยอมให้เปิด dev server ตัวที่สองบนโฟลเดอร์เดียวกัน
จึงเลี่ยงด้วยการเปิดคนละพอร์ตไม่ได้ ต้องปิดตัวเดิมก่อน

## หก — งานถัดไป

- **IP-221 ทศนิยม 2 ตำแหน่ง** เจ้าของงานสั่งระหว่างเซสชันนี้ว่าตัวเลขในการคำนวณให้ใช้
  ทศนิยม 2 ตำแหน่งเสมอ และเลือกวิธีว่า **ปัดที่บรรทัด แล้วบวกจากบรรทัดที่ปัดแล้ว** เพื่อให้
  ใบงานบวกตรงกับที่ตาเห็นทุกบาท ตอนนี้แผงผู้ช่วยยังโชว์ปริมาณเป็น `10.800000` และยอดเงิน
  แสดงแบบไม่มีทศนิยม งานนี้แตะสูตรคำนวณ จึงต้องมีแผนและเทสต์ก่อนเขียนโค้ด
- คูณตัวคูณของวิธีคิดเข้ากับฉบับ แล้วขึ้น ปร.4 ถึง ปร.6 ตาม ADR 0008 ข้อ 7 ถึง 10
- **ADR 0008 ข้อ 3** ลบ `projects.project_path` กับ enum แล้วแก้ฟอร์มสร้างโครงการ
- **สองจุดเล็กที่เจอระหว่างตรวจ ยังไม่ได้แก้** หนึ่ง ผู้ช่วยเสนอคู่ของรายการที่อยู่ในใบแล้ว
  ทำให้จ่ายค่าเรียกแบบจำลองซ้ำโดยไม่จำเป็น สอง `acceptMatches` ใช้ `onConflictDoNothing`
  แต่รายงานกลับว่ารับแล้วเท่าจำนวนที่ส่งมา ข้อความจึงบอกเกินจริงเมื่อรับซ้ำของเดิม
- **IP-213** วัดต้นทุน token ต่อทักษะ · บล็อก IP-081
- **IP-166** ตราประจำแอป PRICEMETR ต้องมีไฟล์ภาพก่อน · **IP-161** ว809 หน้าสแกน
- ยังไม่ได้ตรวจธีมของหน้า `/account` และหน้าย่อยของ ESTIMETR
