## Description

ก่อนหน้านี้โปรเจกต์มีไฟล์ `km/ตาราง Factor F อาคาร ใหม่.pdf` ที่ไม่มีที่มาในตัวเองเลย — ไม่มีเลขหนังสือ
ไม่มีวันที่ ไม่มีชื่อหน่วยงาน — และ roadmap ระบุหน่วยงานผู้ออกผิดเป็นกรมโยธาธิการและผังเมือง
รอบนี้ตาราง Factor F เข้ามาอยู่ใน repository เป็นชุดข้อมูลที่ตรวจสอบได้ พร้อมหนังสือเวียนที่ประกาศมัน
และโมดูลที่ปฏิเสธการหยิบตารางผิดฉบับแทนที่จะหาค่าที่ใกล้เคียงที่สุดมาให้

## สิ่งที่จงใจไม่ทำ และเหตุผล

1. **ไม่ใส่ช่วงวันที่บังคับใช้** — ว481 ลงวันที่ 26 มิ.ย. 2569 แต่ ปร.4 จริงตั้งราคา 20 มิ.ย. 2569
   และใช้ค่าจากตาราง 6% แล้ว แปลว่ามีหนังสือเวียนฉบับ 6% ก่อนหน้าที่เรายังไม่มี การเดาช่วงวันที่ลงไป
   จะทำให้ระบบเลือกตารางผิดฉบับให้โครงการที่อยู่คาบเกี่ยว → **IP-068**
2. **ไม่ตัดสินเรื่องการเทียบอัตราส่วน** — หมายเหตุท้ายตารางสั่งให้เทียบอัตราส่วนเมื่อค่างานอยู่ระหว่างช่วง
   แต่ ปร.4 จริงใช้ค่าของแถวที่ต่ำกว่าตรง ๆ ต่างกัน **1,400 บาท** บนโครงการ 3.3 ล้าน
   `selectFactorFRow()` จึงคืนทั้งสองแถวพร้อมธง `betweenRows` ให้ผู้มีคุณวุฒิตัดสิน → **IP-069**
3. **ไม่ seed เข้าฐานข้อมูล** — ยังไม่มีชั้นราคาที่จะอ่านมัน และ schema ที่ถูกต้องขึ้นกับคำตอบของข้อ 1 และ 2
   ชุดข้อมูลใน repository review ผ่าน pull request ได้ ซึ่งเป็นสิ่งที่ต้องการที่สุดในตอนนี้
4. **`reviewedBy` เป็น null** — การตรวจเชิงกลไก 1,644 แถวไม่ใช่การรับรองโดยคน โมดูลเปิดค่านี้ออกมา
   เพื่อให้ผู้เรียกปฏิเสธการคิดราคาบนตารางที่ยังไม่มีผู้รับรองได้ → **IP-070**

## Findings

- **หน่วยงานผู้ออก Factor F คือกรมบัญชีกลาง ไม่ใช่กรมโยธาธิการและผังเมือง** โดยอาศัยอำนาจตามประกาศ
  คณะกรรมการราคากลางและขึ้นทะเบียนผู้ประกอบการ ข้อขัดแย้งที่ `harness-audit-2026-08-23.md` บันทึกไว้
  จึงมีคำตอบแล้ว และ IP-042 ถูกแก้ถ้อยคำให้ตรงตั้งแต่ v0.21.0
- **ไฟล์ `ตาราง Factor F อาคาร ใหม่.pdf` คือส่วนที่ตัดมาจาก ว499 หน้า 3-15** ค่าตรงกันทุกตัว การใช้ไฟล์นั้น
  ลำพังจึงไม่มีทางรู้ว่าเป็นตารางของอัตราดอกเบี้ยใด ประกาศเมื่อไร หรือยังบังคับใช้อยู่หรือไม่
- **ว499 กับ ว481 ใช้จำนวนธนาคารต่างกัน** (5 แห่งกับ 4 แห่ง) และปัดคนละทาง (6.90 ปัดขึ้นเป็น 7,
  6.38 ปัดลงเป็น 6) ทั้งคู่ถูกตามกฎเดียวกัน
