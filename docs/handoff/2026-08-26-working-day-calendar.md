## ห้า — งานถัดไป และการตัดสินใจที่ต้องทำก่อนเขียนโค้ด

### IP-142 ส่วนที่เหลือ — ต่อปฏิทินเข้าชั้นเวลาของแผนงาน

ชั้นคำนวณอยู่ที่ `src/lib/work-calendar.ts` และหน้าจออยู่ที่
`src/components/prototype/work-calendar-panel.tsx` **แต่ยังไม่มีใครเรียกใช้ในการคำนวณแผน**
`src/lib/work-plan.ts` ยังนับ `startOffsetDays` และ `durationDays` เป็นวันปฏิทินล้วน

**การตัดสินใจที่ต้องได้คำตอบก่อนแตะโค้ด** — ระยะเวลาที่ผู้ใช้กรอกในตารางรายการงาน
หมายถึงวันทำงานหรือวันปฏิทิน สองทางนี้ให้ผลต่างกันมากและเปลี่ยนความหมายของแผนทั้งใบ

| ทางเลือก | ผลที่ตามมา |
|---|---|
| นับเป็นวันทำงานเสมอ | ตรงกับที่ผู้รับเหมาคิด แต่แผนเก่าที่กรอกไว้ทั้งหมดจะยาวขึ้นทันทีเมื่ออัปเกรด |
| เลือกได้ต่อโครงการ | ไม่ทำลายแผนเก่า แต่เพิ่มสวิตช์อีกตัวที่ผู้ใช้ต้องเข้าใจ |
| นับเป็นวันปฏิทินเหมือนเดิม แล้วใช้ปฏิทินแค่แสดงผล | เปลี่ยนน้อยที่สุด แต่ไม่ได้แก้ปัญหาที่ IP-142 ตั้งใจแก้ |

`src/lib/work-plan.ts` มีเทสต์ 37 ข้อคุมอยู่ การเปลี่ยนหน่วยเวลาจะกระทบเทสต์เหล่านั้น

- `.env` มี `OPENAI_API_KEY` `DEEPSEEK_API_KEY` `DATABASE_URL` `GOOGLE_CLIENT_ID/SECRET`
  — ANTHROPIC และ MOONSHOT ยังไม่มี
- ฐานข้อมูลต่อติดจริง 26 ตาราง **แต่แอปแผนงานยังไม่ได้ต่อคลาวด์เลย** เก็บใน localStorage
  ที่ schema รุ่น 3 — ไฟล์รุ่น 1 และ 2 ยังเปิดได้
- dev server ที่ `localhost:3000` อาจมีตัวเดิมรันค้าง ตรวจก่อนสั่งรันใหม่
- MCP `chrome-devtools` ตั้งเป็น Edge และหลุดบ่อย ถ้าเชื่อมไม่ได้ให้ปิดเฉพาะโปรเซส Edge
  ที่มีคำว่า `chrome-devtools-mcp` ในบรรทัดคำสั่ง **ห้ามปิด Edge ส่วนตัวของเจ้าของงาน**
- **สิทธิ์ทดลองใช้ระบบคู่แข่งหมดวันที่ 2026-08-27** เข้าไปเก็บเพิ่มไม่ได้อีกหลังจากนั้น
  ข้อมูลที่เก็บมาอยู่ครบในเอกสารวิจัยแล้ว
- **ห้ามบันทึก token ของเจ้าของงานลงไฟล์ใด** `iframe.src` ของแอปคู่แข่งมี JWT กับอีเมลติดอยู่
