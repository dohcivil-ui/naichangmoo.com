## สอง — คำวินิจฉัยของเจ้าของงานที่เกิดหน้างาน ต้องรู้ก่อนแตะทะเบียน

1. **เจ้าของงานประกาศแอปครบทั้ง 7 ด้วยมือผ่านหลังบ้านจริง** (บัญชีผู้ดูแลคือ doh.civil@gmail.com)
   แต่พอถึงสวิตช์เปิดใช้ของ ESTIMETR เขาหยุดและพูดว่า **"ยังไม่มีงานไหนเสร็จ 100% เลยนะ"**
   ผลคือทุกแอปเป็น "ประกาศแล้ว + กำลังเตรียมระบบ" ทั้งกระดาน การเปิดใช้ ESTIMETR แยกเป็น **IP-179**
   รอเกณฑ์เดโมระดับ A ผ่านครบ (IP-064/070/073/052 + การตรวจเบราว์เซอร์จริง IP-094)
   **อย่าเปิดใช้แอปใดในทะเบียนโดยไม่มีคำสั่งใหม่จากเจ้าของงาน**
2. **Hermes 24/7 คือธุรกิจบริการ setup ระบบผู้ช่วยตาม request** ให้องค์กร/บริษัท/ห้างร้าน/เจ้าของกิจการ
   use case แรกอยู่ใน `docs/requirements/hermes-24-7-use-case-1.md` — เจ้าของงานสั่งเก็บรายละเอียดเป็น
   **ความลับ** ช่อง Hermes บนหน้าแรกพูดได้แค่ประโยคแนะนำบริการกับปุ่มส่ง use case (ชี้ไป /enterprise)
   หน้า request เฉพาะทางคือ IP-178 ทำตอนเฟส Hermes
3. **ประโยคความพร้อมเป็นแพทเทิร์น**: `availabilityNotePresets` ใน `platform.ts` สี่ประโยค + เงียบ + กำหนดเอง
   เพิ่มประโยคมาตรฐานใหม่ต้องเพิ่มที่นั่นที่เดียว และห้ามมีคำว่า "โครงการ" (เทสต์คุมอยู่)

## สี่ — เรื่องที่เจ็บแล้วต้องจำของเซสชันนี้

1. **Google บล็อกการกรอกรหัสผ่านในเบราว์เซอร์ที่ MCP ควบคุม** ("เบราว์เซอร์หรือแอปนี้อาจไม่ปลอดภัย")
   — บัญชีที่มี session ค้างในโปรไฟล์กดเลือกได้ แต่บัญชีใหม่กรอกรหัสไม่ได้เลย ทางออกที่ใช้จริง:
   งานหลังบ้านที่ต้องล็อกอิน **ให้เจ้าของงานทำใน Edge ส่วนตัว** แล้วเราตรวจผลจากหน้าสาธารณะ/ฐานข้อมูล
2. **Edge ของ MCP ถูกอีกเซสชันถือโปรไฟล์อยู่** เปิดพร้อมกันไม่ได้ — ปิดเฉพาะ msedge ที่มี `edge-mcp-profile`
   ในบรรทัดคำสั่ง (เจ้าของงานอนุมัติแล้ว) ห้ามแตะ Edge ส่วนตัว
3. **`pnpm release` ปฏิเสธเมื่อมีไฟล์รุ่นถัดไปค้างใน tree** — v0.66.0 ใช้ปักธงมือสี่ขั้น
   (tag → push branch → push tag → gh release create) ตามที่เจ้าของงานเคยอนุมัติ slug ต้องตรงสูตรใน
   `scripts/release.mjs` (ห้าคำแรกที่ไม่ใช่ stopword ของ title)
4. **จอ "กำลังเตรียมระบบ" ของสมาชิกที่ล็อกอินแล้วยังไม่เคยถูกดูด้วยตา** — ติดไปกับ IP-179/IP-094
