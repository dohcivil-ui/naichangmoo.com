# Handoff — `v0.32.0: An Extension Nobody Can Grant Without Saying Why`

ข้าม `/grill-with-docs` ตาม AGENTS.md ข้อ 1 ขอบเขตของงานนี้ถูกตัดสินไว้แล้วใน ADR 0013 รอบนี้เป็นการทำตามขอบเขตนั้น ไม่ได้เปิดการตัดสินใจใหม่

## Description

ADR 0013 อนุญาตให้ผู้ดูแลจัดการสิทธิ์การใช้งานได้ แต่ยังไม่มีหน้าจอ รอบนี้เปิด `/admin/entitlements` ซึ่งค้นลูกค้าจากอีเมลสมาชิกหรือชื่อองค์กร แล้วแก้สถานะและวันหมดอายุของสิทธิ์ในแต่ละแอปได้

**ช่องเหตุผลเป็นหัวใจของหน้านี้** ไม่ใช่ส่วนประกอบ การต่ออายุที่ไม่ต้องอธิบายคือการแจกของฟรีที่ตรวจสอบย้อนหลังไม่ได้ เหตุผลจึงถูกตรวจ **ฝั่งเซิร์ฟเวอร์ก่อนแตะฐานข้อมูล** ไม่ใช่แค่ `required` ใน markup — เบราว์เซอร์ไม่ใช่ที่ที่กฎอยู่ ส่วน `required` ในฟอร์มช่วยแค่ให้ผู้ดูแลไม่ต้องเสียรอบไปกลับ

## สามอย่างที่ตั้งใจให้เป็นแบบนี้

**การตรวจสิทธิ์ถูกทำซ้ำใน server action** ทั้งที่ layout กันหน้าไว้แล้ว เพราะ server action เป็นทางเข้าของตัวเอง ใครก็ตามที่ post เข้ามาได้ก็เรียกมันได้ ไม่ว่าหน้ารอบ ๆ จะกันไว้อย่างไร การพึ่งว่าหน้ารอบ ๆ ตรวจแล้ว คือวิธีที่ action กลายเป็น API ที่ไม่มีใครเฝ้า

**ค้นว่างแล้วไม่ได้อะไร** การเปิดหน้านี้เฉย ๆ ไม่ใช่คำขอเรียกดูรายชื่อลูกค้าทั้งหมด หลังบ้านที่ลิสต์ลูกค้าทุกรายตอนโหลด คือหลังบ้านที่เผยแพร่รายชื่อลูกค้าไปแล้ว

**ค้นด้วยชื่อโครงการไม่ได้** ค้นได้เฉพาะอีเมลกับชื่อองค์กร ซึ่งเป็นสองสิ่งที่คนขอความช่วยเหลือบอกเกี่ยวกับตัวเองได้ ชื่อโครงการระบุตัวลูกค้าได้เหมือนกัน แต่ ADR 0013 ปิดไว้

## Security and data impact

ไม่มี migration ในรอบนี้

หน้านี้เขียน `app_entitlements` ได้ ซึ่งเป็นสิทธิ์ที่ ADR 0013 อนุญาต และ**ไม่มี query ใดในไฟล์ทั้งชุดที่อ้างถึง** `projects`, `drawing_documents`, `takeoff_*`, `evidence_references`, `price_sets`, `price_observations` หรือ `estimate_revisions`

ทุกการเปลี่ยนแปลงเขียน `audit_events` ที่มี `organization_id` ของลูกค้า `actor_id` ของผู้ดูแล สถานะก่อน สถานะหลัง และเหตุผล และหน้านี้แสดงประวัตินั้นกลับมาให้เห็นในตัวมันเอง ผู้ดูแลจึงเห็นสิ่งที่ตัวเองและคนอื่นทำไปแล้ว

## Risk

**IP-088 ยังไม่ได้ทำ** ยังไม่มีเทสต์ที่พิสูจน์ว่าผู้ดูแลเข้าถึงแถวงานของลูกค้าไม่ได้ สิ่งที่มีตอนนี้คือการไม่มี query แบบนั้นอยู่ในโค้ด ซึ่งเป็นข้อเท็จจริงที่ตรวจด้วยตาได้แต่ไม่มีอะไรกันไม่ให้ใครเพิ่มเข้ามาวันหลัง

ยังไม่มีการจำกัดอัตราการเรียกค้นหา ผู้ดูแลที่บัญชีถูกยึดสามารถไล่ค้นอีเมลทีละตัวได้ ตาราง `rate_limit_counters` มีอยู่แล้วและใช้ได้ ควรทำเมื่อมีผู้ดูแลมากกว่าหนึ่งคน
