# Handoff — `v0.28.0: The Platform States Its Prices, and the Day Pass Stops Competing With VIP`

ข้าม `/grill-with-docs` ตาม AGENTS.md ข้อ 1 เพราะราคาเป็นการตัดสินใจเชิงพาณิชย์ที่เจ้าของงานให้ตัวเลขมาโดยตรง ไม่ใช่สิ่งที่การซักถามจะหาคำตอบได้ คำถามที่ซักจริงคือสองข้อที่เป็นปัญหาของตัวเลขเอง — ราคาแยกแอปที่แพงกว่าเหมารวม และฟอนต์ — ทั้งคู่ถามและตอบก่อนแตะโค้ด

## Description

ข้อกำหนดเดิมห้ามแสดงราคาเป็นตัวเลขไว้สามจุด ข้อห้ามนั้นไม่ได้มีเพื่อปิดราคาตลอดไป แต่มีเพื่อกันตัวเลขที่ยังไม่อนุมัติไม่ให้ขึ้นหน้าที่ลูกค้าเห็น เมื่อเจ้าของงานอนุมัติราคาชุดแรก ADR 0011 จึงมาแทนข้อห้ามนั้น

**สิ่งที่จับได้ระหว่างตรวจตัวเลข** ราคาแยกแอปที่เสนอมา 49 บาทต่อวัน คิดเป็น 1,470 บาทต่อเดือน ซึ่งแพงกว่า VIP ที่ 1,170 บาทและได้ทุกแอป ถ้าขายแบบรายเดือนทั้งคู่ ตัวเลือกแยกแอปจะถูกครอบทุกทางและไม่มีใครเลือกเลย เจ้าของงานตัดสินให้เป็น **บัตรรายวัน** ซึ่งย้ายมันออกจากการแข่งกับ VIP ไปเป็นสินค้าคนละประเภทสำหรับคนที่มีงานด่วนชิ้นเดียว

**ข้อที่สองที่จับได้** คำโฆษณา "วันละ 29 บาท" เป็นจริงเฉพาะรายปี (10,440 ÷ 365 = 28.60) รายเดือนคือ 39.00 บาทต่อวัน ตัวเลขต่อวันบนหน้าเว็บจึงคำนวณจากรอบที่ผู้ใช้เลือกอยู่ ไม่ใช่ค่าคงที่ และประโยคเปรียบกาแฟแสดงเฉพาะรอบรายปี

เทสต์ที่คุ้มค่าที่สุดสามตัว: ส่วนลดรายปีต้องเท่ากับ `1170*12 - 10440` ไม่ใช่เลข 3600 ที่พิมพ์ไว้เอง; `Math.round(perDayBaht("yearly"))` ต้องเป็น 29 และ `Math.round(perDayBaht("monthly"))` ต้องไม่ใช่ 29; และข้อความในระดับสมาชิกทุกบรรทัดต้องไม่มีรูปแบบ `ตัวเลข + บาท` เพื่อบังคับว่าราคามีที่อยู่ที่เดียว

## Security and data impact

ไม่มี migration ไม่แตะสิทธิ์หรือความลับ **ยังไม่เปิดรับชำระเงิน** — ไม่มี payment provider ในโปรเจกต์และไม่มีสถานะ entitlement ที่ผูกกับการชำระ ปุ่มบนระดับ VIP จึงเป็นการแจ้งความสนใจที่พาไป `/enterprise` และมีหมายเหตุระบุตรง ๆ ว่ายังไม่เปิดรับชำระผ่านเว็บไซต์ งานเปิดรับชำระเป็น **IP-081** และต้องมี ADR ของตัวเอง

## Risk

`pricePromotions` เป็นอาร์เรย์ว่างใน source แปลว่าการตั้งโปรโมชันวันนี้ต้อง commit ไม่ใช่กดจากหลังบ้าน โมเดลข้อมูลพร้อมแล้ว (มี `startsAtIso`/`endsAtIso` และ `activePromotion()` ที่ตรวจช่วงเวลา) แต่พื้นผิวที่เขียนมันได้ต้องรอ **IP-078** ซึ่งเป็นโมเดลสิทธิ์ผู้ดูแลระบบ

ตารางความสามารถตอนนี้มีสี่คอลัมน์ และคอลัมน์ VIP กับองค์กรเหมือนกันทุกแถว เพราะทั้งคู่ map ไปที่สถานะ `active` เดียวกัน นี่คือความจริงตามนโยบาย ไม่ใช่ข้อบกพร่องของตาราง แต่ถ้าสองระดับนี้ควรต่างกันจริงในอนาคต ต้องเพิ่มสถานะสิทธิ์ ไม่ใช่แก้ที่ตาราง

## Rollback

กลับไป tag `v0.27.0-access-page` แล้ว revert commit ของ v0.28.0 ไม่มี migration และไม่มีรายการค้างกับผู้ให้บริการชำระเงินใด เพราะยังไม่ได้เปิดรับชำระ
