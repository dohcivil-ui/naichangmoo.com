## 2. ข้อเท็จจริงเรื่องเวลาวาด — วัดจริง 2026-09-02 ห้ามเดาเวลาเอง

วัดด้วย pdfjs-dist 4.10.38 ตัวเดียวกับโปรเจกต์ บน Edge เครื่องเจ้าของงาน (dpr 1.89)
ไฟล์ kusumal_hospital 32 หน้า A3 1191×842 pt วอร์มอัปก่อนจับเวลา

**หน้า 7 วาดทั้งหน้าที่สเกลต่าง ๆ**

|---|---|---|---|

| 2.0 | 2382×1684 | 4.01 | 94 ms |

**หกหน้าเนื้อหาต่างกัน** — ทั้งหน้าที่ 2.0 อยู่ช่วง 32–74 ms · ทั้งหน้าที่ 4.17 อยู่ช่วง 32–75 ms ·
เฉพาะกรอบจอที่ซูม 8 เท่า 19–45 ms (ค่า 352 ms ของหน้า 2 คือครั้งแรกที่ยังโหลดฟอนต์ ไม่ใช่ต้นทุนการวาด)

**ข้อสรุปที่แผนนี้ยึด**

1. **เวลาวาดไม่ขึ้นกับสเกล** ต้นทุนอยู่ที่การแปลคำสั่งวาดของหน้า ไม่ใช่การระบายพิกเซล —
   **สเกลแลกด้วยหน่วยความจำอย่างเดียว ไม่แลกด้วยเวลา**
2. สมมติฐานเดิมที่ว่า "ความเร็วคือเหตุผลของการปะเฉพาะกรอบที่มองเห็น" **ใช้ไม่ได้บนเดสก์ท็อป**
   โครงชั้นคมจึงเปลี่ยนเป็น **วาดทั้งหน้าเป็นหลัก และวาดเฉพาะกรอบเป็นทางถอยเมื่อชนงบพิกเซล**
   (โค้ดเส้นทางเดียวกัน ต่างแค่ `offsetX`/`offsetY`)
3. 300 dpi ทั้งหน้า A3 ทำได้ใน 46 ms / 70 MB — บันทึกเป็นข้อเท็จจริงให้ก้อน 9 (OCR)
   แต่ **ไม่ทำในก้อนนี้** และข้อตัดสิน "ส่งออกเฉพาะกรอบที่ครอบ" ยังมีผล เพราะเป็นเรื่องความปลอดภัย

### หลักฐานภาพจากแอปเดิม (เจ้าของงานส่งมา 2026-09-02) — ใช้เป็นสเปกเพิ่มเติม

1. **ด่านสเกลของแอปเดิมแคบกว่าของเรา** ในภาพ เส้นกริดร่างครบแนว 1–6 กับ A–B ·
   ระยะจริงใส่ค่าแล้วสี่เส้น (4.00 / 4.00 / 20.00 / 10.00 ม.) · หมุดนับจำนวนปักที่จุดตัดกริด
   สิบกว่าจุด — **ทั้งหมดนี้เกิดขณะแถบสถานะยังขึ้น "สเกล: ยังไม่ตั้ง"** สรุปเป็นกฎได้ว่า
   เครื่องมือที่คืนค่าเป็นจำนวนหรือพิกัด (ร่างกริด ระยะจริง นับจำนวน) ไม่ต้องมีสเกล
   ส่วนเครื่องมือที่คืนค่าเป็นเมตรหรือตารางเมตร (ความยาว พื้นที่) ต้องมี — กฎนี้ลงเป็นเทสต์ (9.3)
2. **Snap กับ Ortho เป็นปุ่มสลับแยกกันคนละปุ่ม** บนแถบเครื่องมือ ตามด้วยข้อความสเกล
   ของเราวันนี้ล็อกแนวได้ทาง Shift ค้างอย่างเดียว ต้องเพิ่มปุ่มสลับ "ล็อกแนวเส้น" (หัวข้อ 6)
3. **แถบสถานะล่างแสดงพิกัดเคอร์เซอร์สดเป็นหน่วยหน้ากระดาษ** เช่น `x: 461, y: -121 px`
   ค่าติดลบได้เมื่อเมาส์อยู่นอกขอบหน้า — เพิ่มเข้าแถบสถานะของเรา (หัวข้อ 5.6)
4. **เส้นกริดวาดสีทอง เส้นระยะจริงวาดสีแดงพร้อมหัวลูกศรสองหัวและตัวเลขที่คนพิมพ์**
   แยกสีกันชัดเพื่อไม่ให้สับสนกับรอยวัด — ของเราใช้กลไกเดียวกันผ่าน token ใหม่สองตัว
   ในครัวสีตาม ADR 0021 (หัวข้อ 5.6)
5. **หมุดนับจำนวนวางทับจุดตัดกริดพอดี พร้อมป้ายชนิด** เช่น `F2,C2` `GB1` ตรงกับกฎ
   ของแอปเดิมว่า จำนวนฐานราก = จำนวนจุดตัดกริดที่มีสัญลักษณ์ฐาน — เครื่องยนต์ดูดจุด
   (intersection บนเส้นกริดที่ร่างเอง) กับช่องชื่อรายการวัดที่มีอยู่แล้วรองรับพฤติกรรมนี้ครบ
   โดยไม่ต้องเพิ่มอะไร ส่วนการให้ AI อ่านสัญลักษณ์เองเป็นก้อน 11 ของแผนแม่

## 3. แผนชั้นวาดสามชั้น

### โครง

| ชั้น | ขอบเขต | สเกล | ถ่ายเมื่อไหร่ | context |
|---|---|---|---|---|
| **ชั้นฐาน** | ทั้งหน้า | `fullPageScaleFor(pageSize)` เป้า 2.0 หนีบด้วยงบ 2^24 จุด | ครั้งเดียวต่อหน้า ไม่มีวันค้าง | 2d ปกติ (GPU) |
| **ชั้นคม** (เมื่อเปิดโหมดคมชัด) | ทั้งหน้า หรือเฉพาะกรอบที่มองเห็นเมื่อเกินงบ | `view.scale × devicePixelRatio` หนีบด้วยงบ 16 ล้านจุด | หลังผู้ใช้หยุดมือ 180 ms · เปลี่ยนหน้า · เปิดโหมด · resize | 2d ปกติ (GPU) |
| **ชั้นวิเคราะห์** | ทั้งหน้า | `fullPageScaleFor(pageSize)` — **คงที่ต่อหน้า ไม่ขึ้นกับซูม** | ครั้งเดียวต่อหน้า | offscreen · `willReadFrequently: true` |

- **โหมดเบา (ค่าเริ่มต้น)** = แสดงชั้นฐานอย่างเดียว ไม่มีการวาดซ้ำเมื่อซูม พฤติกรรมนิ่งและประหยัดสุด
  ที่ซูม ≤ ~106% บนจอ dpr 1.89 ชั้นฐาน 2.0 ยังให้อัตราส่วน ≥ 1.0 อยู่แล้ว
- **โหมดคมชัด** = ชั้นคมวางทับชั้นฐาน · `wanted = view.scale × dpr` · ถ้า `wanted ≤ capScale`
  (สเกลสูงสุดที่ทั้งหน้าอยู่ในงบ 16 ล้านจุด — A3 ได้ 3.99 คมถึงซูม ~211%) วาดทั้งหน้าที่ `wanted` ·
  ถ้าเกิน วาดเฉพาะกรอบที่มองเห็นบวกระยะเผื่อ 64 พิกเซล CSS ต่อด้านที่ `wanted` เต็ม ๆ
  (กรอบผูกกับขนาดจอ ไม่โตตามซูม จึงไม่มีวันชนเพดาน 16,384 ต่อด้าน)
- **ไม่มีจอว่างระหว่างถ่าย** — ชั้นฐานอยู่ใต้เสมอ ชั้นคมถูกล้างตอนเริ่มถ่ายใหม่ได้โดยผู้ใช้เห็นแค่
  ภาพลดความคมชั่วครู่ (≤ ~100 ms ตามตารางเวลา) ไม่ใช่จอขาว · ระหว่างลาก/หมุนล้อ
  ภาพเดิมถูกยืดด้วย CSS transform ให้ตามมือทัน แล้วค่อยคมเมื่อหยุด
- **เมื่อชนงบพิกเซล ผู้ใช้ไม่ต้องรู้และไม่ต้องมีป้ายเตือน** เพราะทางถอยแบบกรอบรับประกัน
  อัตราส่วน ≥ 1.0 ในบริเวณที่มองเห็นเสมอ เพดานนี้จึงมองไม่เห็นโดยออกแบบ ไม่ใช่ข้อจำกัดที่ผู้ใช้แบก
- **งบชั้นคม 16 ล้านจุด (64 MB) ไม่ใช่ 24 ล้าน** เหตุผล: เกิน capScale ไปแล้วทางถอยแบบกรอบ
  ให้ความคมเท่ากันทุกประการ งบที่ใหญ่ขึ้นซื้อแค่ "วาดทั้งหน้าได้ที่ซูมสูงขึ้น" ซึ่งตาแยกไม่ออก
  แต่จ่ายหน่วยความจำค้างเพิ่ม 32 MB ตลอดเวลา · รวมสามชั้น A3 กรณีแย่สุด ฐาน 16 + คม 64 +
  วิเคราะห์ 16 ≈ 96 MB ยังอยู่ใต้เพดานผืนวาดเดสก์ท็อป และเหลือช่องให้ก้อนจอสัมผัส (งบเป็นพารามิเตอร์
  ส่งค่าต่ำกว่าได้ ไม่ปิดทางข้อตัดสิน 8)
- **ชั้นวิเคราะห์สเกลคงที่ต่อหน้า** ด้วยเหตุผลเดิมไม่เกี่ยวกับความเร็ว: ไล่พื้นที่ห้องและดูดจุดจากภาพ
  ต้องได้ผลเดิมทุกระดับซูม · `fullPageScaleFor` ขึ้นกับขนาดหน้าอย่างเดียว จึง deterministic
- **รองรับ OCR 300 dpi (สเกล 4.17)** — `planCropRender()` รับสเกลใด ๆ กับกรอบใด ๆ อยู่แล้ว
  ก้อน 9 เรียกฟังก์ชันเดียวกันด้วยสเกล 4.17 ได้โดยไม่แก้โครง
- ผืนวาดรูปย่อ (thumbnails) คงเดิม ไม่แตะในก้อนนี้ นอกจากลบฟิลด์ `canvas` ที่ตายแล้ว

### สิ่งที่หายไปจากโค้ดเดิม

state `renderScale` กับ effect ไล่ความละเอียดตามซูม (บรรทัด 347-353) ถูกถอดทิ้ง ·
`.mk__sheet` เปลี่ยนเป็นหน่วยหน้ากระดาษล้วน (`width: pageSize.width` CSS px,
`transform: translate(x,y) scale(view.scale)`) ผืนวาดทุกชั้นและ SVG overlay วางในระบบเดียวกัน

export type Segment = { a: PagePoint; b: PagePoint };
export type SnapHit = { kind: SnapKind; point: PagePoint; distance: number };

/** รวบรวมเรขาคณิตของหน้าให้เครื่องยนต์: รายการวัด (รูปปิดนับขอบปิดด้วย

 *  ไม่รวมเส้นร่างที่ยังลากไม่จบ */
export function collectSnapGeometry(
  measurements: readonly Measurement[],
  gridLines: readonly DraftedGridLine[],
  dimensions: readonly StatedDimension[],
  page: number
): { segments: Segment[]; loosePoints: PagePoint[] };

/** เครื่องยนต์เรขาคณิตหกแบบ (ไม่รวม image ซึ่งต้องใช้ภาพ)
 *  กติกาตามสเปกแอปเดิม: ทุกชนิดที่เปิดแข่งกันด้วยระยะล้วน ใกล้สุดชนะ ไม่มีลำดับชั้น
 *  ยกเว้น grid ใช้ต่อเมื่อชนิดอื่นไม่ติดเลย
 *  - endpoint: ปลายทุก segment + loosePoints
 *  - midpoint: กึ่งกลางทุก segment
 *  - intersection: จุดตัดจริงของทุกคู่ segment (พารามิเตอร์ทั้งสองใน [0,1]) — O(n²) รับได้
 *    เพราะ n คือรูปบนหน้าเดียว
 *  - perpendicular: ต้องมี lastPlaced · เท้าฉากจาก lastPlaced ลงแต่ละ segment (หนีบที่ปลาย)
 *    ให้คะแนนด้วยระยะเคอร์เซอร์ถึงเท้า
 *  - on_edge: จุดใกล้สุดบน segment ให้คะแนนด้วยระยะตั้งฉาก
 *  - grid: ปัดเข้าตารางระยะเท่า spacing = gridSpacingM / metresPerPoint
 *    (ไม่มีสเกล → GRID_FALLBACK_SPACING_POINTS) ยึดจุดตั้งต้นที่ lastPlaced
 *    ถ้าไม่มี lastPlaced ยึดมุมกระดาษ (0,0)
 *  กรณีขอบ: ไม่มีผู้สมัครในรัศมี → null · settings.enabled=false → null
 *  เสมอกันพอดี → ตัวแรกตามลำดับชนิดข้างบน (ผลนิ่ง เทสต์ได้) */
export function findGeometrySnap(input: {
  cursor: PagePoint;
  radiusPagePoints: number;          // = screenRadius / view.scale — ผู้เรียกคำนวณ
  geometry: { segments: readonly Segment[]; loosePoints: readonly PagePoint[] };
  lastPlaced: PagePoint | null;
  metresPerPoint: number | null;
  settings: SnapSettings;
}): SnapHit | null;

/** ดูดเข้าเส้นในแบบ — หาพิกเซล "ที่ใกล้ที่สุด" (ไม่ใช่เข้มที่สุด — จุดที่ต่างจากโค้ดเดิม)
 *  ที่ความสว่าง 0.299R+0.587G+0.114B < ceiling ในวงกลมรัศมี clamp(radiusPx,1,35)
 *  ข้ามพิกเซล alpha < 20 · เสมอกัน → ตัวแรกแบบไล่แถว (row-major)
 *  ทำงานบน ImageData ของชั้นวิเคราะห์ พิกัดเป็นพิกเซลของชั้นนั้น

### 5.7 การเปลี่ยนใน `drawing-markup.tsx` (พฤติกรรม ไม่ใช่โค้ด)

- `type Tool` กับ `toolNeedsScale` ย้ายออกไป `src/lib/drawing-tools.ts` (สัญญา 5.5)
  component import กลับมาใช้ — จุดเรียกเดิมไม่เปลี่ยนหน้าตา
- `TOOLS` เพิ่มสองรายการต่อท้าย นับจำนวน (ร่างกริด · ระยะจริง — ใกล้ลำดับท้ายแถบของ
  แอปเดิม โดยไม่สลับเก้าตัวเดิมที่ตรงต้นแบบ prototype อยู่แล้ว) และแถบเครื่องมือเพิ่ม
  ปุ่มสลับ `aria-pressed` สองปุ่มข้างปุ่มดูดจุด: **"ล็อกแนวเส้น"** (สลับ `axisLock` —
  Shift ค้างยังใช้ชั่วขณะได้เหมือนเดิม ตามภาพแอปเดิมที่ Snap กับ Ortho แยกปุ่มกัน)
  และ **"ความคมชัด"**
- **ลำดับใน `resolvePoint` ใหม่ (แก้บั๊กข้อ 3)**
  1. แปลงพิกัดจอเป็นหน้ากระดาษ
  2. `findGeometrySnap` — ติด → คืนเลย **ไม่ล็อกแนวทับ**
  3. เปิดดูดเส้นในแบบ → `findImageSnap` บนชั้นวิเคราะห์ — ติด → คืนเลย
  4. ไม่ติดเลยและ (เปิดล็อกแนวหรือกด Shift) และมีจุดล่าสุด →
     เครื่องมือวัด/ตั้งสเกล/ระยะจริง ใช้ `lockToAngle(15)` · ร่างกริดใช้ `lockToAxis`
  5. ไม่เข้าเงื่อนไขไหน → จุดดิบ
- state ใหม่: `sharpOn` (เริ่ม `false` — โหมดเบาเป็นค่าตั้งต้นตามคำเจ้าของงาน "คงโหมดเบาไว้") ·
  `snapSettings` (เริ่ม `DEFAULT_SNAP_SETTINGS` · ปุ่มดูดจุดเดิม/คีย์ N สลับ `enabled`) ·
  `gridLines: DraftedGridLine[]` · `dimensions: StatedDimension[]` ·
  `pendingRefStart: PagePoint | null` (จุดแรกของร่างกริด/ระยะจริง)
- **ประวัติ undo เปลี่ยนจาก `Measurement[][]` เป็นก้อนเดียว
  `{ measurements; gridLines; dimensions }`** เพราะผู้ใช้ที่ลากเส้นกริดพลาดจะกด Ctrl+Z
  แน่นอน — แก้ `commit/undo/redo` และจุดเรียกทั้งห้าจุด โครงเดิมคงไว้
