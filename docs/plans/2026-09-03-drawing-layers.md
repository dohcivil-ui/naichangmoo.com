# ชั้นของรอยวัดบนแบบ (layer) — จัดกลุ่ม ตั้งชื่อ ให้สี และเปิดปิดการแสดงผล

**ผู้วางแผน** Opus 5 · **สถานะ** สเปกร่าง รอเจ้าของงานเคาะรายละเอียดที่เหลือ ยังไม่เริ่มโค้ด
**ที่มา** เจ้าของงานเสนอ 2026-09-03 หลังกดจริงขั้น 6 ของ IP-233 ผ่าน
**ต้องทำหลัง** IP-234 หรือ **ทำรวมกับ IP-234** (เหตุผลอยู่หัวข้อสอง ข้อนี้สำคัญที่สุดในเอกสาร)
**รายการโรดแมป** ยังไม่มีเลข ต้องขอเลข IP ใหม่ตอนตัดรุ่นถัดไป (roadmap.json ถูก hook ตรวจว่าต้องตรงกับไฟล์รุ่น)

---

## หนึ่ง — สิ่งที่เจ้าของงานเคาะแล้ว (อย่าถามซ้ำ)

| เรื่อง | คำตัดสิน |
|---|---|
| layer ครอบอะไร | **ทุก object ที่เราวาดเอง** — เส้นบอกระยะ รายการวัดทุกชนิด และแนวเสา อยู่ในระบบ layer เดียวกัน เพราะคนใช้เข้าใจง่ายกว่าว่าของบางอย่างเข้า บางอย่างไม่เข้า |
| สีมาจากไหน | **ACI ชุดเล็ก เก็บเป็นโทเคนของธีม** — เลือกเฉพาะสีที่อ่านออกบนแบบขาวดำ ไม่ฝ่าฝืน ADR 0021 และทดสอบคู่สีกับพื้นหลังได้ |
| เก็บที่ไหน | **เก็บกับแบบใบนั้น ทุกคนเห็นเหมือนกัน** — ไม่ใช่ค่าประจำตัวรายคนแบบ `drawing_view_states` |

## สอง — เงื่อนที่ต้องแก้ก่อน: รายการวัดยังไม่ลงฐาน

**IP-233 เก็บลงฐานแค่สามอย่าง** คือ สเกล (คอลัมน์ `metres_per_point`) แนวเสา (`grid` jsonb) และ
ระยะจริง (`dimensions` jsonb) ทั้งสามอยู่ในแถวของ `drawing_calibrations`

**รายการวัด (measurement) ยังไม่ลงฐานเลย** อยู่ในหน่วยความจำเบราว์เซอร์เท่านั้น พิสูจน์แล้วเมื่อ
2026-09-03 ตอนกดจริง: วัดช่วง 5.00 ม. ได้หนึ่งรายการ ปิดแท็บ เปิดใหม่ เลือกไฟล์เดิม
แผงขวาขึ้น "0 รายการ" ขณะที่สเกล แนวเสา และเส้นระยะจริงกลับมาครบ

ที่เก็บของรายการวัดคือ `drawing_marks` ซึ่งเป็น **ขั้น 1 ของ IP-234** และ migration 0016
**ยังไม่ได้รัน** เพราะรอเจ้าของงานเคาะ

**ผลที่ตามมา** layer เป็นความสัมพันธ์ที่ต้องแขวนไว้กับตัว object ทุกชิ้น ถ้าทำ layer ก่อน
`drawing_marks` การจัด layer ให้รายการวัดจะหายทุกครั้งที่ปิดแท็บ และถ้าทำ `drawing_marks`
ให้เสร็จก่อนโดยไม่คิดเรื่อง layer เราจะต้องแก้รูป `StoredMark` กับเขียน migration ถอนอีกใบทีหลัง

**ข้อเสนอ** ใส่ช่อง `layerId` เข้าไปใน `StoredMark` ของ IP-234 **ตั้งแต่ใบแรก** แล้วงาน layer
ที่เหลือ (ตาราง ทะเบียนสี แผงจัดการ) ตามมาเป็นรายการถัดไป — เท่ากับ migration 0016 เพิ่มมาหนึ่งช่อง
ไม่ต้องมีใบถอน

## สาม — ของที่ต้องเข้า layer และที่อยู่ปัจจุบันของมัน

| object | ชนิดใน TypeScript | ที่เก็บวันนี้ | ต้องเพิ่ม |
|---|---|---|---|
| รายการวัด 5 ชนิด (length polyline area rect count) | `Measurement` (`drawing-measurement.ts:57`) | ยังไม่ลงฐาน → `drawing_marks` ของ IP-234 | `layerId` |
| แนวเสา | `DraftedGridLine` (`drawing-grid.ts`) | `drawing_calibrations.grid` jsonb | `layerId` |
| ระยะจริง | `StatedDimension` (`drawing-scale.ts`) | `drawing_calibrations.dimensions` jsonb | `layerId` |

`Measurement` **มีช่อง `colour: string` อยู่แล้ว** วันนี้ถูกแจกอัตโนมัติแบบวนรอบจากโทเคนห้าสี
(`MEASUREMENT_COLOURS` ใน `drawing-markup.tsx:91`) เมื่อมี layer แล้ว สีต้องมาจาก layer ไม่ใช่
จากลำดับที่วาด — แต่ **ห้ามลบช่อง `colour` ออก** เพราะรายการที่วาดไว้ก่อนมี layer ต้องยังแสดงได้
กติกาที่เสนอ: สีที่แสดง = สีของ layer ถ้ามี `layerId` · ถ้า `layerId` เป็น null ใช้ `colour` เดิม

## สี่ — รูปทรงที่เสนอ

### 4.1 ตาราง `drawing_layer_sets` (หนึ่งแถวต่อแบบหนึ่งใบ)

ลอกรูปทรงเดียวกับ `drawing_calibrations` คือเก็บเป็น jsonb ก้อนเดียว ไม่แตกเป็นแถวต่อ layer
เพราะจำนวน layer ต่อแบบมีหลักสิบ การอ่านคือ "เอาทั้งชุด" ทุกครั้ง และการเรียงลำดับกับการเปิดปิด
เปลี่ยนพร้อมกันเป็นก้อน

```
drawing_layer_sets
  document_id   text PK → drawing_documents CASCADE
  layers        jsonb NOT NULL       -- {version:1, items: StoredLayer[]}
  updated_by    text NOT NULL → users
  created_at / updated_at
```

```ts
export type StoredLayer = {
  id: string;
  /** ชื่อที่ผู้ใช้ตั้ง เช่น ผนังชั้นสอง หรือ งานไฟฟ้า — ว่างไม่ได้ */
  name: string;
  /** เลข ACI ของสีชั้นนี้ ค่าที่แสดงจริงมาจากทะเบียนโทเคน ไม่ใช่ค่าสีดิบ */
  aci: AciIndex;
  /** ซ่อนแล้วยังอยู่ในฐานและยังนับเข้ายอดรวม แค่ไม่วาดบนแบบ */
  visible: boolean;
  /** ลำดับในแผง เลขน้อยอยู่บน */
  order: number;
};
```

**ทำไม `visible` อยู่ในแถวที่ทุกคนเห็นร่วมกัน** เพราะเจ้าของงานเคาะข้อสามว่าเก็บกับแบบใบนั้น
ทุกคนเห็นเหมือนกัน · **ผลข้างเคียงที่ต้องเขียนใน UI ให้ชัด** คนหนึ่งปิด layer ไว้ อีกคนที่เปิดแบบใบเดียวกัน
จะไม่เห็นของนั้นด้วย ต้องมีข้อความบอกว่าการซ่อนเป็นของทีม ไม่ใช่ของตัวเอง

**ไม่ลง audit** เหตุผลเดียวกับ `drawing_view_states` และ `drawing_marks` — การตั้งชื่อชั้นหรือ
เปิดปิดการแสดงผลยังไม่ใช่การกระทำที่ต้องตรวจย้อน จุดที่ต้องตรวจย้อนคือตอนส่งปริมาณเข้าถอดปริมาณ
ซึ่งลง audit อยู่แล้ว

### 4.2 ชั้นตั้งต้น

ทุก object ที่ `layerId` เป็น null ถือว่าอยู่ใน **ชั้นตั้งต้น** ซึ่งเป็นชั้นเสมือน ไม่มีแถวในฐาน
ชื่อในแผงว่า "ยังไม่จัดชั้น" ปิดไม่ได้ ลบไม่ได้ เปลี่ยนสีไม่ได้ — สีของสมาชิกมาจาก `colour` เดิมของมัน

เหตุผลที่ไม่สร้างแถวชั้นตั้งต้นให้อัตโนมัติ: แบบที่ยังไม่มีใครใช้ layer จะไม่มีแถวในตารางนี้เลย
การเปิดแบบเดิมจึงไม่ต้องเขียนฐานโดยที่ผู้ใช้ไม่ได้สั่งอะไร (บทเรียนจากบั๊กที่ effect เซฟจุดที่ค้าง
ไปทับแถวในฐานเองเมื่อ 2026-09-03)

### 4.3 ถาดสี — ชื่อตาม ACI ค่าที่แสดงเป็นโทเคน

**เอกสาร Autodesk ยืนยันโครงของ ACI** 255 สี เลข 1–255 · เลข 1–9 มีชื่อกำกับ โดยเอกสารไล่ชื่อไว้
1 Red · 2 Yellow · 3 Green · 4 Cyan · 5 Blue · 6 Magenta · 7 White/Black · เลข 10–249 เป็นถาดใหญ่
ไล่เฉดอย่างเป็นระบบ · 250–255 เป็นเฉดเทา
(help.autodesk.com GUID-C163F875-E449-48B7-8CF4-F90DF935118C)

**สองข้อที่ทำให้เอา ACI มาทั้งถาดไม่ได้ในรอบนี้**

1. **ค่า RGB ของเลข 10 ขึ้นไปไม่มีในเอกสารของ Autodesk** ตารางที่หาได้บนเน็ตเป็นของเว็บที่สาม
   และ **เลข 8 กับ 9 ค่าไม่ตรงกันระหว่างแหล่ง** (บางที่ 555555/AAAAAA บางที่ 414141/808080)
   การเอาตัวเลขที่ยืนยันไม่ได้มาฝังในโปรเจกต์ผิดกฎเรื่องอ้างแหล่งปฐมภูมิ
2. **ADR 0021 ห้ามค่าสีฝัง** ให้ใช้โทเคนของธีมเท่านั้น ตารางสี 255 แถวคือค่าสีฝัง 255 ค่า

**ที่เสนอสำหรับรอบแรก** ใช้ **ชื่อและเลขของ ACI 1–9 เป็นคำเรียก** เพราะเป็นคำที่ช่างพูดกันจริง
("ตั้งชั้นนี้เป็นสีแดง") แต่ **ค่าที่แสดงมาจากโทเคนของธีมที่เลือกให้อ่านออกบนกระดาษขาว**

| ACI | ชื่อ | ใช้ได้บนกระดาษขาวไหม | โทเคนที่เสนอ |
|---|---|---|---|
| 1 | แดง | ได้ | `--dimension-red` (มีอยู่แล้ว ใช้กับเส้นระยะจริง) |
| 3 | เขียว | ได้ | `--success` |
| 5 | น้ำเงิน | ได้ | ต้องเพิ่มโทเคนใหม่ |
| 6 | ม่วงแดง | ได้ | ต้องเพิ่มโทเคนใหม่ |
| 7 | ดำ | ได้ แต่**ชนกับเส้นในแบบ** | `--ink` — ต้องเตือนผู้ใช้ |
| 4 | ฟ้า | จาง แยกจากเส้นแบบยาก | `--teal` (เข้มกว่า cyan จริง) |
| 2 | เหลือง | **อ่านไม่ออก** บนพื้นขาว | ไม่ใส่ในถาด |
| 8, 9 | เทาเข้ม เทาอ่อน | ได้ แต่ค่าอ้างอิงไม่ตรงกันระหว่างแหล่ง | `--muted` เฉพาะ 9 |

ได้ **เจ็ดสีใช้งาน** (1 3 4 5 6 7 9) ซึ่งพอแยกงานสิบกว่าชั้นได้เมื่อรวมกับชื่อชั้น
ต้องเพิ่มโทเคนใหม่สองตัวในธีม (น้ำเงิน ม่วงแดง) และเทียบค่าคู่สีกับพื้นกระดาษให้ผ่านเกณฑ์อ่านออก

**ถ้าเจ้าของงานต้องการค่า ACI จริงเป๊ะ** ให้อ่านค่า RGB จากกล่อง Select Color ใน AutoCAD
ของเครื่องตัวเอง (เอาเมาส์ชี้สีแล้วเลขกับค่า RGB ขึ้นใต้ถาด) แล้วส่งค่ามาให้ — นั่นคือแหล่งปฐมภูมิ
ไม่ใช่ตารางที่คัดลอกกันบนเน็ต

## ห้า — สิ่งที่ยังไม่ได้ตัดสิน ต้องถามก่อนเขียนโค้ด

1. **การเลือก object เพื่อจัดเข้าชั้น** เครื่องมือเลือกวันนี้เลือกได้ทีละชิ้น (`selectedId` เดี่ยว)
   จะเพิ่มเลือกหลายชิ้น (Shift คลิก หรือลากกรอบ) ในรอบนี้ หรือใช้วิธีจัดจากแผงขวาทีละบรรทัด
2. **ของที่ซ่อนอยู่นับเข้ายอดรวมไหม** สเปกนี้เสนอว่า**นับ** เพราะการซ่อนคือเรื่องการมองเห็น
   ไม่ใช่การลบ แต่ถ้าเจ้าของงานต้องการใช้ layer เป็นเครื่องมือ "คิดเฉพาะงานชุดนี้" คำตอบจะกลับด้าน
   และต้องแสดงยอดสองชุดให้ชัดว่าอันไหนคือทั้งหมด
3. **แนวเสาเข้า layer ด้วยจริงไหม** เจ้าของงานเคาะว่าทุก object ที่เราวาดเอง ซึ่งรวมแนวเสา
   แต่แนวเสาเป็นโครงอ้างอิงไม่ใช่ปริมาณ ถ้าปิดชั้นแนวเสาแล้วการดูดจุดยังเกาะมันได้อยู่ไหม
4. **แผงจัดการชั้นวางที่ไหน** คอลัมน์ขวาวันนี้เป็นรายการที่วัดแล้ว และต้นแบบจองที่ตรงนั้นไว้ให้
   ผู้ช่วย AI (IP-187) ด้วย สามอย่างในคอลัมน์เดียวต้องมีวิธีสลับ

## หก — ที่ทางของงานผู้ช่วย AI ที่เกี่ยวกัน

ต้นแบบ `.design/estimeter-viewer/viewer-controls-prototype.html` บรรทัด 15 เขียนว่าคอลัมน์ขวาคือ
"รายการที่วัดแล้ว ยอดรวม **และผลจากผู้ช่วย**" และบรรทัด 258–276 มีแผง "ผู้ช่วย AI อ่านแบบ"
พร้อมข้อเสนอที่รับหรือปฏิเสธได้ทีละข้อ

วันนี้ยังไม่มีในแอปเพราะ **IP-187 (ผู้ช่วย ESTIMETR ของจริง) ยังเป็น planned** ส่วนที่ทำเสร็จแล้วคือ
IP-185 แผงผู้ช่วยของกลางใน AppShell ซึ่งออกมาเป็น**ปุ่มลอยมุมล่างซ้าย** ไม่ใช่คอลัมน์ขวาตามต้นแบบ

**ทางแยกที่ยังไม่มีใครเคาะ** จะย้ายผู้ช่วยเข้าคอลัมน์ขวาเฉพาะแอปนี้ตามต้นแบบ หรือคงปุ่มลอยของกลางไว้
แล้วให้ IP-187 ไปโผล่ในปุ่มนั้น — คำตอบนี้กำหนดว่าแผงจัดการชั้นในข้อ 5.4 มีที่ยืนแค่ไหน
