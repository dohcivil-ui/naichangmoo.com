# ผู้ช่วย AI ทุกแอป — เอกสารออกแบบ

**ออกแบบโดยพี่กร (วุฒิวิศวกรโยธา) 2026-08-27 ตามคำสั่งเจ้าของงาน "เพิ่ม AI เป็นผู้ช่วยกับทุกแอป
และหาจุดร่วมรอยต่อที่ AI จะเข้าไปช่วยในทุกแอป"** — จัดทำจากการอ่านโค้ดจริง · roadmap v0.67.0
สถานะ: **เจ้าของงานอนุมัติแล้ว 2026-08-27** — ทั้งสถาปัตยกรรม รอยต่อ 7 จังหวะ และ IP-180 ถึง IP-191
พร้อมคำวินิจฉัยสี่ข้อ: คำแถลงผู้ช่วยเป็นรายแอปในทะเบียน (IP-190) · land-acquisition ไม่ทำในรีโปนี้ ·
นับโควตาเป็นครั้ง · สมาชิกหมดอายุใช้ผู้ช่วยไม่ได้ · ยังไม่เพิ่มค่ายที่สามแต่ต้องต่อ failover ก่อน deploy ·
prompt เก็บแค่ hash

## 0. ข้อเท็จจริงที่ตรวจพบว่าต่างจากที่เข้าใจกัน

| แอป | ที่เข้าใจกัน | ของจริงในโค้ด |
|---|---|---|
| work-plan | มีผู้ช่วย 3 action | **ถูกต้อง** — ร่าง/แก้/ตรวจ เรียกแบบจำลองจริง (ตัวเดียวในแพลตฟอร์ม) |
| ESTIMETR | มี guidance assistant + AI Takeoff | **ข้อความคงที่ ไม่มีการเรียกแบบจำลอง** — และเป็นความตั้งใจตาม `docs/architecture/estimeter-operating-policy.md:42` ("first UI release intentionally has no LLM/API call") ซึ่งไล่เงื่อนไขของรุ่น AI จริงไว้ครบ · `takeoff_runs.runner` เขียนค่าเดียวคือ `"manual"` |
| PRICEMETR | มีผู้ช่วยที่ปิดใน production | **ไม่มีอะไรเลย** — `disabled_in_production` ทั้งรีโปอยู่ใน `work-plan-assistant.ts` เท่านั้น |
| escalation-k / rcopt / traffic-sign / land-acquisition | ยังไม่มีผู้ช่วย | ถูกต้อง — และสามตัวหลัง**ไม่มีแอปเลย** มีแค่การ์ดในทะเบียน |

**สรุป: ผู้ช่วย AI จริงมี 1 แอป ไม่ใช่ 3 · แอปที่ต้องสร้างผู้ช่วยใหม่คือ 6 · ในนั้นสามตัวยังไม่มีแอปให้เกาะ**

จุดที่กระทบเรื่องเงินโดยตรง: หลักตั้งราคาใหม่อ้าง "ทุกแอปมีผู้ช่วย AI" — นั่นคือคำแถลงเชิงพาณิชย์
ถ้าขึ้นหน้าราคาโดยที่สามแอปยังเป็นการ์ดเปล่า คือปัญหาเดียวกับที่ ADR 0015 เพิ่งปิด ต้องแก้ที่ทะเบียน (ข้อ 6.1)

## 1. จุดร่วมของงานวิศวกรรมโยธา — รอยต่อมาตรฐานเจ็ดจังหวะ

งานราชการไทยทุกชิ้นเริ่มจากเอกสารที่หน่วยงานออก จบที่เอกสารที่เราส่งกลับ ตรงกลางคือแปลงเอกสารเป็น
ตัวเลข ตรวจตัวเลข แล้วแปลงกลับเป็นเอกสาร — ถอดปริมาณ ค่า K กำแพงกันดิน ป้ายจราจร ค่าทดแทน
เปลี่ยนแค่ชื่อเอกสารกับสูตร จังหวะไม่เปลี่ยน

| # | จังหวะ | verb | สิ่งที่ผู้ช่วยทำ | โมเดลคืนตัวเลขไหม |
|---|---|---|---|---|
| 1 | อ่านเอกสารเป็นข้อมูล | `extract` | PDF สแกน รูป โฉนด ใบส่งของ → แถวข้อมูล | คืน แต่ต้องผ่านคนยืนยัน (IP-052) |
| 2 | ตรวจความครบของอินพุต | `preflight` | ขาดอะไร หน่วยขัดกันไหม ค่าหลุดพิสัย | **ไม่คืน** |
| 3 | ร่างผลลัพธ์แรก | `draft` | โครงรายการชุดแรกจากไม่กี่ค่า | เฉพาะสัดส่วน/จำนวน/รหัส |
| 4 | แก้ด้วยคำสั่งภาษาคน | `revise` | "งวด 3 รวมงานหลังคาด้วย" | เท่ากับ draft |
| 5 | ทักสิ่งที่ขัดกัน | `critique` | ลำดับงานขัด งวดหนักผิดปกติ รายการหาย | **ไม่คืน** |
| 6 | อธิบายที่มาของตัวเลข | `explain` | ค่านี้มาจากหนังสือไหน ทำไมใช้ได้ | **ไม่คืน** |
| 7 | เรียบเรียงข้อความส่งออก | `compose` | หมายเหตุ คำอธิบาย สรุปผู้บริหาร | **ไม่คืน** |

สี่ในเจ็ดจังหวะโมเดลไม่คืนตัวเลขเลย = ทำผิดทางการเงินไม่ได้ในทางโครงสร้าง

**จังหวะที่คุ้มสุดถ้าทำก่อน: `critique` แล้วต่อด้วย `explain`** — (1) ไม่ต้องต่อท่อข้อมูลใหม่ กินสิ่งที่
ระบบคำนวณเสร็จแล้วคืนเป็นข้อความ (แบบแผนพิสูจน์แล้วที่ `work-plan-assistant.ts:225-250`)
(2) ผิดทางการเงินไม่ได้ (3) คู่แข่ง "ไม่มี AI แม้แต่จุดเดียวในทั้งสิบเมนู"
(`docs/requirements/work-plan-app-how-we-beat-them.md:216`) — คนทำ draft ได้มีเยอะ
คนที่บอกได้ว่า*แผนนี้ผิดตรงไหน*ไม่มีเลย
**จังหวะที่ทำท้ายสุด: `extract`** เพราะ IP-052 บังคับด่านยืนยันของคนก่อนค่า OCR ถูกใช้คำนวณ

## 2. สถาปัตยกรรมผู้ช่วยกลาง

### 2.1 วันนี้กระจายอยู่ยังไง

| ชิ้น | ที่อยู่ | สภาพ |
|---|---|---|
| จุดต่อค่ายแบบจำลอง | `src/server/ai/provider.ts` | ดีอยู่แล้ว — 10 รุ่น 4 ค่าย บังคับ JSON schema เก็บทั้งดุ้น |
| prompt + schema | `src/server/ai/work-plan-prompt.ts` | ผูกแอปเดียวแต่รูปทรงถูก (แยกจาก Next ให้สคริปต์เทียบรุ่นใช้ตัวเดียวกับแอป) |
| กฎธุรกิจ (normalise เกลี่ยเงิน) | `work-plan-assistant.ts` | ปนกับ action ของแอป แอปอื่นก๊อปได้อย่างเดียว |
| ด่านสิทธิ์ | ไม่มี — เช็คแค่ NODE_ENV | `run_ai` มีใน `entitlement.ts:25,111` แต่ไม่มีใครเรียก |
| เพดานการใช้ | ไม่มี | `consumeRateLimit` (`rate-limit.ts:22`) ผู้เรียกเดียวคือฟอร์มใบเสนอราคา |
| audit | ไม่มี | `audit_events` 19 ชนิด ไม่มีชนิด AI · `before_hash`/`after_hash` ว่างทุกแถว |
| ค่าใช้จ่าย | คำนวณแล้วทิ้ง | `costBaht()` (`provider.ts:113`) ไม่มีใครเก็บ |

บททดสอบการลบ: ไม่มีชั้นกลาง = สิทธิ์/เพดาน/audit/ที่มาข้อมูล โผล่ซ้ำได้ถึง 7 แอป × 7 จังหวะ = 49 จุด

### 2.2 ประตูสองบาน

```
src/server/ai/
  provider.ts             มีแล้ว ไม่แตะ
  assistant-contract.ts   ชนิด request/response/citation/refusal
  assistant.ts            ประตู: runAssistant() / settleProposal()
  skill-registry.ts       ทะเบียนทักษะ แอป × จังหวะ (เพิ่มแอป = เพิ่มแถว ไม่แก้ประตู)
  assistant-quota.ts      เพดานที่เดียว
  assistant-audit.ts      เขียนร่องรอย
  skills/work-plan.ts  escalation-k.ts  estimeter.ts  pricemetr.ts ...
```

ข้างในซ่อน: session → `run_ai` → เพดานเดือน → แหล่งข้อมูลมีผู้รับรอง → ตัดข้อมูลส่วนเกิน →
เลือกรุ่น → `askForJson` → ตรวจ schema → เขียนแถวข้อเสนอ → audit
**"หนึ่ง adapter คือรอยต่อสมมติ สอง adapter คือรอยต่อจริง"** — ห้ามประกาศเสร็จจนกว่า work-plan
และ escalation-k เดินบนมันทั้งคู่

### 2.3 สัญญา (สาระสำคัญ)

- `AssistantRequest`: `app` (slug จาก platformApps เท่านั้น) · `verb` · `subject` (ลง audit ตรง ๆ) ·
  **`facts: string[]`** — ตัวเลขที่ระบบคำนวณเสร็จแล้ว ส่งเป็นข้อความให้โมเดล*อ้าง* แยกจาก `input`
  เพื่อเทสต์ได้ว่าโมเดลไม่เคยได้รับโจทย์คำนวณเงิน · `instruction` เฉพาะ revise
- `Citation`: `document/datasetId/datasetSha256/clause/page/reviewedBy/verified` —
  **`clause` คัดจากชุดข้อมูล ห้ามให้โมเดลเขียนเลขข้อ** (เลขข้อคือสิ่งที่โมเดลแต่งเนียนสุดตรวจยากสุด)
- `AssistantProposal`: `proposalId` (correlation ทั้งสาย) · `draft` (**ห้ามมีช่องเงิน** — G1) ·
  `assumptions` · `citations` · `model+promptHash` · `usage` · **`costMicroUsd`** (จำนวนเต็ม USD
  ไม่ใช่บาท เพราะ `BAHT_PER_USD=35` ตรึงตายตัว เก็บบาทคือแช่อัตราแลกเปลี่ยนลงประวัติ) · `quota`
- `AssistantRefusal`: `not_signed_in | not_entitled | over_monthly_cap | source_not_reviewed |
  input_incomplete | no_api_key | refused | unparsable | unavailable`

### 2.4 ทะเบียนทักษะ

`AssistantSkill = { app, verb, system, buildTask, schema, project (ตัดข้อมูลก่อนเข้า prompt),
citations, model, monthlyCap ต่อ EntitlementState }` — ความรู้รายแอปเป็นข้อมูลที่ลงทะเบียน
ไม่ใช่ if ที่แตกสาขา และเป็นสิ่งที่เทสต์ร่วม (ข้อ 4) เดินไล่ตรวจอัตโนมัติ

### 2.5 การเลือกรุ่น

ค่าเริ่มต้น `gpt-5.4-mini` จากการวัดจริง IP-131 (8.9 วิ · 0.22 บาท/ครั้ง) **ห้ามเลือกรุ่นจากความรู้สึก
หรือราคาต่อ token** (IP-131 พิสูจน์ว่าราคาต่อ token ทำนายต้นทุนจริงไม่ได้) — รุ่นต่อจังหวะต้องวัดด้วย
โจทย์จริงผ่านสคริปต์แบบ `compare-work-plan-models.ts` ที่ import prompt ตัวเดียวกับแอป ·
ประกาศ DeepSeek V4 Flash เป็นตัวสำรองอัตโนมัติเมื่อ OpenAI ล้ม (ช้ากว่าแต่ไม่ดับเจ็ดแอปพร้อมกัน)

### 2.6 เพดานต่อเดือน (ปิดฝั่งกลางของ IP-140)

ใช้ `rate_limit_counters` + `consumeRateLimit` ที่มีอยู่ (พกพา Vercel/VPS ไม่ต้องมี Redis ตรง ADR 0001)
**แต่มีบั๊กรอเกิด:** `currentWindowStart = floor(now/windowMs)*windowMs` ไม่ใช่เดือนปฏิทิน และรีเซ็ต
เที่ยงคืน UTC = **07:00 เช้าไทย กลางเวลางาน** → เพิ่มพารามิเตอร์ `windowStart` แล้วให้
`assistant-quota.ts` คำนวณต้นเดือนตาม Asia/Bangkok

เพดานสามชั้น: ต่อคนต่อเดือน (`ai:month:{app}:{verb}` — ตัวเลขที่ผู้ใช้เห็น) · ต่อคนต่อนาที (กันกดรัว) ·
**ทั้งแพลตฟอร์มต่อวัน (`ai:spend:platform`) = เบรกมือ** กันบั๊ก retry loop เผาเงินข้ามคืน — ทะลุแล้ว
ผู้ช่วยดับทั้งระบบพร้อมข้อความบอกผู้ใช้ ไม่ใช่เงียบ
**ลำดับ: ตรวจสิทธิ์ก่อนนับโควตา** — `canUseCapability(entitlement, "run_ai")` ใช้ได้ทันที และมันปิด
`expired_read_only` ให้แล้วตรง ADR 0003

### 2.7 audit — AI เสนออะไร คนกดรับอะไร

ตารางใหม่ **`assistant_proposals`** (id, app_slug, verb, actor, org, resource, model_id, prompt_hash,
draft/citations/assumptions jsonb, tokens, cost_micro_usd, elapsed_ms, decision
`proposed|accepted|rejected|partially_accepted|expired`, decided_at/by, changed_fields) +
เหตุการณ์ `ai.proposed / ai.accepted / ai.rejected / ai.partially_accepted` ใน `audit_events`
โดย `proposalId` เป็น correlation_id — และเป็นการใช้งานจริงครั้งแรกของ `before_hash`/`after_hash`
**หลักการห้ามพัง: เขียนแถวข้อเสนอก่อนคืนค่าให้หน้าจอ** — ไม่งั้นร่างที่ถูกปฏิเสธหายจากประวัติ แล้วเรา
จะไม่มีวันรู้ว่าผู้ช่วยเสนอผิดบ่อยแค่ไหน ซึ่งเป็นตัวเลขเดียวที่บอกว่าควรเปลี่ยนรุ่นหรือ prompt
(`takeoff_items.review_state` จำลองเรื่องนี้ไว้แล้วแต่เก็บแค่สถานะปัจจุบัน ไม่แยกค่าที่ AI เสนอ)

### 2.8 ตัดข้อมูลก่อนเข้า prompt

ทำนโยบาย `estimeter-operating-policy.md:40` ให้บังคับได้จริงด้วย `project()` ในทะเบียนทักษะ +
เทสต์ประกอบ prompt จริงยืนยันไม่มีอีเมล/userId/organizationId/storage_key — ตรวจที่ข้อความที่ส่งจริง

## 3. บทบาทผู้ช่วยรายแอป (สาระสำคัญต่อแอป)

หลักตัดสิน: **ผู้ช่วยที่ช่วยจริงทำงานน่าเบื่อที่คนพลาดบ่อย ไม่ใช่งานยากที่คนระวังอยู่แล้ว**

### ESTIMETR
- ช่วยจริงสี่อย่าง: (1) **เผื่อวัสดุพร้อมที่มา** — `waste_source_note` นั่งรอข้ออ้างอิงอยู่แล้วใน schema
  (2) อธิบายหน่วยขัดกับสูตร ต่อยอด `measurementMatchesUnit` (3) ทักรายการที่หายไปจากชุด
  (ของที่ลืมทั้งรายการคือสิ่งที่ทำให้ขาดทุน ไม่ใช่ตัวเลขคลาด 2%) (4) อธิบาย Factor F printed/interpolated
  ตาม IP-073 — `FactorFResolution.basis` มีรออยู่แล้ว
- ห้าม: สร้าง/แถลงราคา · เลือกแถว Factor F เอง · ยืนยันแทนผู้ใช้ · ปล่อยเอกสาร ปร.
- ข้อจำกัดจริง: `factor-f.ts` เสร็จแต่ไม่มีไฟล์ในแอป import และ `reviewedBy` ว่าง (IP-070) —
  ผู้ช่วยยังพูดเรื่อง Factor F ไม่ได้จนกว่ามีวิศวกรรับรอง

### PRICEMETR — รอยต่อ AI ที่คุ้มที่สุดในแพลตฟอร์ม
- **จับคู่ชื่อรายการเดียวกันข้ามสามแหล่ง** (สพฐ./สนค./ว809 สะกด-หมวด-หน่วยไม่เหมือนกัน คนเสียครึ่งบ่าย
  ต่อโครงการ จับผิดคู่ = ราคากลางผิดทั้งรายการ) — งานจับคู่ข้อความคือสิ่งที่โมเดลถนัดสุดและ**ปลอดภัยสุด
  เพราะสิ่งที่ข้ามรอยต่อกลับมาคือรหัสรายการ ไม่ใช่ราคา** ระบบไปหยิบราคาจริงของรหัสนั้นเอง
- เตือนสิ่งที่คนลืม: ราคาพาณิชย์รายจังหวัด*ยังไม่รวม VAT ไม่รวมค่าขนส่ง* (นิยามใน CONTEXT.md) —
  ทักตรงจังหวะกดหยิบรายการ
- ต้องรอ IP-162 + IP-164 ก่อน — เปิดผู้ช่วยบนแอปไม่มีด่านสิทธิ์ = เปิดให้ใครก็ได้ใช้เงินเรา

### ผู้ช่วยสร้างแผนงาน — ของเดิมที่ต้องซ่อมสองจุด
- **ไม่มีปุ่มปฏิเสธ**: `work-plan-workspace.tsx:419-421` ทับแผนทันทีที่โมเดลตอบ ไม่มีรับ/ปฏิเสธ/ย้อน
  (undo คือ IP-144 ยัง planned) — กติกา "ทุกคำแนะนำมีปุ่มปฏิเสธ" ผู้ช่วยตัวเดียวที่มียังไม่ผ่าน
- **ไม่ตรวจสิทธิ์**: เช็คแค่ NODE_ENV · `run_ai` ไม่เคยถูกเรียก
- ย้ายมาชั้นกลางปิดทั้งสองข้อ และกลายเป็นตัวอย่างอ้างอิงของอีกหกแอป

### ESCALATION K
- จุดที่คนพลาดจริง: (1) **เลือกสูตรผิดจาก 35 สูตร** — งานอ่านข้อความล้วน โมเดลคืนแค่*รหัสสูตร*
  สัมประสิทธิ์มาจากชุดข้อมูล (2) **กับดักสองวัน** ของมาตรการปี 2569: เกณฑ์ ±2% ทริกวันส่งมอบ
  แต่กฎเดือนฐานทริกวันลงนาม — การเลือกกฎเป็นโค้ด ผู้ช่วยทำ `explain` ให้เห็นว่าสัญญาตกตรงไหน
- ข้อจำกัดจริง: `reviewedBy: null` ทั้ง 5 หมวด → `computeK` ปฏิเสธทุกสูตรวันนี้ · เอกสารปี 2569
  `verified: false` (IP-096) และไม่มีโค้ดไหนอ่านธง `verified` เลย → ผู้ช่วยทำได้แค่ explain/preflight
  จนกว่า IP-096/097 เสร็จ — ถูกแล้ว: ร่างจากตารางที่ไม่มีใครเซ็น = เอาลายเซ็นผู้ใช้ไปค้ำตัวเลขที่ไม่มีใครค้ำ

### RCOPT · TRAFFIC SIGN · LAND ACQUISITION
- ทั้งสามมีแค่การ์ด ไม่มีโค้ด ไม่มีชุดข้อมูลมาตรฐาน (ไม่มี มยผ./ว.ส.ท./ACI/คู่มือป้าย ทล. ในรีโป)
- rcopt: ผู้ช่วยห้ามระบุค่าออกแบบทุกชนิด (**ค่าออกแบบโครงสร้างผิด = คนตาย**) ช่วยได้จริงคือ `explain`
  ว่า*อะไรคือตัวคุม*ของหน้าตัดที่ bisection หาได้ ซึ่งอัลกอริทึมบอกเองไม่ได้
- traffic-sign: ร่าง*รายการ*ป้ายได้ แต่ห้ามบอก*ขนาด/ชนิดแผ่นสะท้อน/ความสูง* จนมีชุดข้อมูลคู่มือ ทล.
  พร้อม reviewedBy
- land-acquisition: **แนะนำไม่ทำในรีโปนี้** — ค่าทดแทนคือสิทธิ์ตามกฎหมายของประชาชน ·
  ข้อมูลเจ้าของที่ดินคือข้อมูลส่วนบุคคลชั้นหนักสุด ห้ามเข้า prompt โดยไม่มีข้อตกลง · PROJECT.md
  ห้ามแตะ legacy อยู่แล้ว — ถ้ายืนยันทำ เริ่มได้แค่ extract/preflight และห้ามเข้าใกล้ค่าทดแทน

## 4. Guardrails ร่วม — กฎที่เทสต์คุมได้ (เดินไล่ทะเบียนทักษะ ไม่เขียนซ้ำต่อแอป)

- **G1 schema ห้ามมีช่องเงิน** — เดินทุก skill เรียก `z.toJSONSchema` ไล่ทุกคีย์ เจอ
  `satang|baht|price|cost|amount|total|sum` หรือ number ไร้หน่วยกำกับ = เทสต์ตก
  (เปลี่ยน "อย่าให้ AI คิดเงิน" จากวินัยเป็นโครงสร้าง — ข้อที่พี่กรเชียร์ที่สุด)
- **G2 เงินลงตัวเป๊ะ** — ยัดคำตอบปลอม (รวมน้ำหนักไม่ครบ/เกิน/ติดลบ/ศูนย์) ยอด satang ต้องเท่าสัญญา
  ทุกกรณี (ยก `normalise()` เดิมขึ้นชั้นกลาง)
- **G3 เทสต์ปนเปื้อน** — prompt จริงต้องไม่ขอให้โมเดล*คำนวณ*บาท/satang (อ้างผ่าน facts ได้)
- **G4 ทุกร่างผ่าน `AssistantProposal` + ปุ่ม รับ/ปฏิเสธ/รับบางส่วน** ปฏิเสธแล้วสถานะกลับเท่าเดิมทุกช่อง
- **G5 ห้ามมีเส้นทาง set ค่าจากโมเดลตรง ๆ โดยไม่ผ่าน `settleProposal`** (วันนี้ workspace:419 ทำอยู่ —
  IP-184 ปิด)
- **G6 `reviewedBy === null` → คืน `source_not_reviewed`** ล้อแบบ `computeK`/`findFactorFTable`
- **G7 Citation ทุกฟิลด์ประกอบจาก dataset ไม่ใช่จากโมเดล** และ sha256 ตรงไฟล์จริง
- **G8 `verified: false` ต้องขึ้นคำเตือนบนจอเสมอ** (วันนี้ไม่มีโค้ดไหนอ่านธงนี้)
- **G9 `run_ai` ก่อนเสมอ** — `expired_read_only` ได้ `not_entitled` และ**ไม่นับโควตา**
- **G10 เพดานเดือนฟังก์ชันเดียว** ถังรวมข้ามแอป หน้าต่างเดือนปฏิทินเวลาไทย
- **G11 เขียน `assistant_proposals` + `ai.proposed` ก่อนคืนค่าให้หน้าจอ**
- **G12 ใต้ `prefers-reduced-motion` ตัวบอก "กำลังคิด" ไม่มีอนิเมชัน**
- **G13 ภาษาไทย + ห้ามอีโมจิ** ทั้งใน system prompt และ**ตัวกรองขาออก**ตัดอีโมจิก่อนเรนเดอร์
  (prompt เป็นคำขอ ไม่ใช่การบังคับ)
- **G14 ห้ามชื่อฟิลด์อังกฤษในข้อความที่ผู้ใช้อ่าน** (ยกจาก WORK_PLAN_SYSTEM เป็นกฎร่วม)
- **G15 prompt จริงไม่มีอีเมล/userId/organizationId/storage_key**
