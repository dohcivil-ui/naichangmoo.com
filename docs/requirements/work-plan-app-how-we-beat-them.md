# แอปผู้ช่วยสร้างแผนงานและ S-Curve — แผนที่ทำให้เหนือกว่า

**Date:** 2026-08-26

เอกสารนี้ตอบสามคำถามของเจ้าของงาน: **เหมือนเขาตรงไหน · เหนือกว่าอย่างไร · ฉีกออกจากของเขาอย่างไรไม่ให้ดูเหมือนกัน**

## หลักสามข้อที่ใช้ตัดสินทุกหน้าจอในเอกสารนี้

1. **เท่าเขาก่อน แล้วค่อยเหนือ** — ฟีเจอร์ที่เขามีและตลาดไทยคาดหวังแล้ว (LINE, Excel, คลาวด์)
   ต้องมีก่อน ไม่ใช่ข้ามไปทำของเท่ ๆ ที่ไม่มีใครขอ
2. **เหนือด้วยของที่เขาตามไม่ทันในสามเดือน** ไม่ใช่เหนือด้วยของที่เขาก๊อปได้ในสัปดาห์เดียว
   AI ทั้งเส้น · ความแม่นระดับสตางค์ที่มี test ค้ำ · เอกสารที่ยื่นเบิกได้จริง — สามอย่างนี้ต้องรื้อสถาปัตยกรรมถึงจะตาม
3. **ฉีกที่โครงความคิด ไม่ใช่แค่ฉีกที่สี** เปลี่ยนสีแล้วยังเดินสิบขั้นเหมือนกันคือแอปเดียวกันคนละสี

### 2. แผนงาน (Gantt)

| | รายละเอียด |
|---|---|
| เขามี | CPM จริง · Total Float · Baseline · โหมดคำนวณวันอัตโนมัติ · WBS หลายระดับ Indent/Outdent · สเกล 4 ระดับ · เส้นโยงงาน · นำเข้า Excel · ส่งออก LINE |
| **เท่า** | ทั้งหมดข้างต้น — นี่คือช่องว่างที่ใหญ่ที่สุดของเราตอนนี้ ต้นแบบเรายังไม่มี Gantt เลย |
| **เหนือ** | **AI ทักลำดับงานที่ขัดกัน** เช่น ฉาบผนังก่อนติดตั้งวงกบ หรืองานที่ Float ติดลบ — ของเขาคำนวณ CPM ได้แต่ไม่เคยบอกว่า *แผนนี้ผิดตรงไหน* |
| **เหนือ** | **ปฏิทินวันทำงานไทยที่ตรวจย้อนได้** — เขามีปุ่มข้ามวันหยุดในตัวสร้างอัตโนมัติเท่านั้น ของเราให้ปฏิทินเป็นข้อมูลที่ผู้ใช้เห็นและแก้ได้ พร้อมบอกว่าวันไหนหายไปเพราะอะไร |
| **ฉีก** | แถบเวลาไม่ใช่ Gantt แบบ MS Project ที่ตารางกินครึ่งจอ — **ตารางกับแถบเวลาสลับเป็นมุมมองหลักได้** และแถบเวลาเน้น "งานที่ต้องตัดสินใจสัปดาห์นี้" ไม่ใช่โชว์ทั้งโครงการให้เลื่อนหา |

### 3. งบประมาณ (BOQ)

| **เหนือ** | **ต่อกับแอปถอดปริมาณของเราเองเป็นข้อมูล ไม่ใช่ไฟล์** — ของเขาส่งข้ามแอปด้วยไฟล์นามสกุลเฉพาะที่ต้องดาวน์โหลดแล้วอัปโหลด |
| **ฉีก** | ไม่ทำ BOQ เป็นเมนูของตัวเอง — **ค่างานอยู่ในรายการงานโดยตรง** เพราะแผนงานกับ BOQ คือของชิ้นเดียวกันในสายตาผู้รับเหมา การแยกสองหน้าคือเหตุที่ยอดสองหน้าไม่ตรงกัน |

### ปัญหาของกราฟเขา

เขาวาง **9 เส้นบนแกนเดียว เปิดปิดได้ทีละเส้น** ซึ่งฟังดูครบ แต่ผลที่เห็นจริงคือ
เส้นเจ็ดเส้นวิ่งชิดกันช่วงต้นโครงการจนแยกไม่ออก และผู้ใช้ต้องไปไล่ดูที่ตารางใต้กราฟแทน
กราฟจึงกลายเป็นของประดับ ส่วนของจริงคือตาราง

**เขาไม่มีระบบสี** — เป็นการหยิบสีมาใส่ทีละเส้น ไม่มีการตรวจว่าคนตาบอดสีแยกออกไหม
และไม่มีการตรวจว่าสองเส้นที่อยู่ติดกันในสายตาต่างกันพอหรือเปล่า

> **มติของเจ้าของงาน 2026-08-26: เส้นเงินเป็นเส้นโค้ง ไม่ใช่ขั้นบันได**
> รอบแรกผมเสนอขั้นบันไดโดยอ้างว่าเงินเข้าเป็นก้อน เจ้าของงานดูของจริงแล้วเลือกเส้นโค้ง
> **เงื่อนไขที่ตามมาและห้ามละเลย:** เมื่อเส้นเป็นโค้ง รูปทรงจะไม่บอกอีกต่อไปว่าเงินเข้าเป็นก้อนกี่ครั้ง
> จึงต้อง **มีหมุดจุดที่ทุกเหตุการณ์เงินเสมอ** (ยื่นเบิก / รับรอง / เงินเข้า) ห้ามตัดทิ้งเพื่อความเรียบ
> เพราะหมุดคือสิ่งเดียวที่เหลืออยู่ซึ่งบอกว่าค่าระหว่างสองหมุดเป็นการลากเส้นเชื่อม ไม่ใช่เงินที่ไหลเข้าทุกวัน
> โหมดขั้นบันไดยังเก็บไว้เป็นตัวเลือก สำหรับคนที่ต้องการอ่านเป็นเหตุการณ์ล้วน

ผลการตรวจ: ช่วงความสว่างผ่าน · ความสดผ่าน · **การแยกสีสำหรับตาบอดสี ΔE 15.0** (เกณฑ์ 8) ·

ซึ่งแก้ด้วยการติดป้ายชื่อเส้นตรงปลายเส้นและมีตารางใต้กราฟอยู่แล้ว

**สีเหล่านี้ใช้ในกราฟเท่านั้น** ตามข้อยกเว้นที่เจ้าของงานอนุญาต ธีมของหน้าจอยังเป็น teal/ส้ม/หมึกของเราเหมือนเดิม

### หกอย่างที่ทำให้กราฟเราอ่านออกกว่าของเขา

1. **แถบอนาคตหลังวันตัดข้อมูล** — พื้นที่หลัง Data Date ระบายจาง พร้อมเส้นแนวตั้งกำกับวันที่
   ทำให้เห็นทันทีว่า *ตรงไหนคือของจริง ตรงไหนคือแผน* ของเขาบอกด้วยขีด `—` ในตารางเท่านั้น
2. **ระบายช่องว่างระหว่างเส้นรับรองกับเส้นเงินเข้า** พร้อมตัวเลขกำกับกลางพื้นที่ว่า
   *"ทำแล้วยังไม่ได้รับ 1,240,000 บาท"* — นี่คือตัวเลขที่ผู้รับเหมาอยากรู้ที่สุดในชีวิตประจำวัน
   และกราฟ 9 เส้นของเขาบอกไม่ได้เลยเพราะไม่มีใครนั่งลบเส้นสองเส้นด้วยตา
3. **ป้ายชื่อเส้นที่ปลายเส้น** ไม่ต้องกวาดสายตาไปหา legend แล้วจำสีกลับมา
   (legend ยังมีเพราะเป็นตัวเปิดปิดเส้น แต่ไม่ใช่ทางเดียวที่จะรู้ว่าเส้นไหนคืออะไร)
4. **เส้นเงินเป็นขั้นบันได เส้นเนื้องานเป็นเส้นต่อเนื่อง** — รูปทรงบอกชนิดของข้อมูลโดยไม่ต้องพึ่งสี
   เงินเข้าเป็นก้อนเมื่อวางบิลผ่าน ไม่ได้ไหลทีละวันเหมือนเนื้องาน
5. **เส้นประคือเงินที่ยังไม่อยู่ในมือ** — ยอดขอเบิกเป็นเส้นประเพราะยังไม่มีใครรับรอง
   ยอดรับรองและเงินเข้าเป็นเส้นทึบ เป็นภาษาภาพที่อ่านได้โดยไม่ต้องอธิบาย
6. **แกนเดียวเป็นบาททั้งหมด** ห้ามแกนคู่เด็ดขาด และแกนตั้งเป็นเลขกลม
   ส่วนแกนนอนเป็นเดือนปฏิทินจริง ไม่ใช่รหัสช่วงเวลา (สองข้อหลังทำไปแล้วในต้นแบบ)

## ส่วนที่เจ็ด — ทุกปุ่มทุกการกระทำต้องมีปฏิกิริยา

คำสั่งของเจ้าของงาน: **ทุกปุ่ม ทุกการกระทำ ต้องมี animation ตอบกลับ**

### หลักที่ใช้ตัดสินว่า animation ตัวไหนควรมี

การเคลื่อนไหวที่ดีไม่ได้มีไว้ให้สวย แต่มีไว้ **ตอบคำถามที่ผู้ใช้ถามในหัวขณะกด**
คำถามมีอยู่สามแบบเท่านั้น และ animation แต่ละตัวต้องตอบข้อใดข้อหนึ่ง

| คำถามในหัวผู้ใช้ | ปฏิกิริยาที่ตอบ |
|---|---|
| "กดติดหรือเปล่า" | ปุ่มยุบลงทันทีที่กด 80–120 มิลลิวินาที |
| "ระบบกำลังทำอะไรอยู่" | สถานะกำลังทำงานที่บอกว่าทำอะไร ไม่ใช่วงกลมหมุนเปล่า |
| "อะไรเพิ่งเปลี่ยนไป" | ตัวเลขหรือแถวที่เปลี่ยนค่าเรืองขึ้นแล้วจางลง |

**ถ้า animation ตัวไหนไม่ตอบสามข้อนี้ ให้ตัดทิ้ง** เพราะมันคือของประดับที่ทำให้แอปช้าลง

### ของที่มีอยู่แล้วในเว็บและต้องใช้ต่อ ไม่สร้างซ้อน

- ตัวแปรจังหวะ `--ease-out` `--ease-reveal` `--ease-in-out` ใน `globals.css`
- `LiveNumber` ในต้นแบบ — ตัวเลขเรืองขึ้นเองเมื่อค่าเปลี่ยน ใช้กับมูลค่างานงวดนี้และเงินรับจริงอยู่แล้ว
- `work-plan-settle` และ `work-plan-thinking` สำหรับแถวใหม่ที่ AI ร่างมา และสถานะกำลังคิด
- `nav-settle` `app-reveal` จากระบบ motion ของหน้าเว็บหลัก
- **`prefers-reduced-motion` มีการรองรับอยู่แล้วทั้งไฟล์** — ทุก animation ที่เพิ่มต้องอยู่ใต้กฎนี้เสมอ
  ผู้ใช้ที่ตั้งค่าเครื่องไว้ว่าไม่เอาการเคลื่อนไหว ต้องได้แอปที่นิ่งสนิทและใช้งานได้ครบ

| สลับแท็บ | เนื้อหาเลื่อนขึ้นเล็กน้อยพร้อมจางเข้า และหมายเลขแท็บที่กำลังใช้ขยับรับ |
| กราฟ | **เส้นวาดตัวเองจากซ้ายไปขวาครั้งแรกที่แสดง** ด้วย `stroke-dashoffset` แบบเดียวกับ `hero-art-draw` ที่หน้าแรกใช้อยู่ · เปิดปิดเส้นแล้วเส้นจางเข้าออกไม่ใช่หายวับ · จุดบนเส้นขยายรับเมื่อชี้ |
| แถบเลื่อนความคืบหน้า | ตัวเลขเปอร์เซ็นต์และแถบวิ่งตามนิ้วแบบไม่มีดีเลย์ |
| ลบของ | แถวหดหายพร้อมปุ่มเรียกคืนที่ค้างไว้สักครู่ ไม่ใช่หายทันทีแล้วกู้ไม่ได้ |
| ข้อผิดพลาด | ช่องที่ผิดสั่นแนวนอนสั้น ๆ ครั้งเดียว พร้อมข้อความบอกว่าผิดอะไร |

### เพดานที่ห้ามข้าม

- ปฏิกิริยาการกด **ไม่เกิน 120 มิลลิวินาที** · การเปลี่ยนหน้าจอ **ไม่เกิน 240 มิลลิวินาที**
  ช้ากว่านี้แอปจะรู้สึกหน่วง ซึ่งแย่กว่าไม่มี animation เลย
- **ห้ามให้ animation ขวางการทำงาน** พิมพ์ต่อได้ทันทีระหว่างที่ยังเคลื่อนไหวอยู่
- **ห้าม animation ที่วนไม่จบ** ยกเว้นสถานะกำลังทำงานจริง ๆ
- ใช้เฉพาะ `transform` กับ `opacity` เท่านั้น เพื่อไม่ให้เบราว์เซอร์ต้องคำนวณผังใหม่
- **ห้าม emoji ในทุกสถานะ** รวมถึงสถานะสำเร็จและผิดพลาด ใช้ SVG จาก `platform-icons.tsx`

## ลำดับการทำที่เสนอ

| ลำดับ | งาน | เหตุผล |
|---|---|---|
| 1 | IP-135 บันทึกจริงต่องวด + Data Date + กราฟจานสีใหม่ | ทำให้เส้นบนกราฟเป็นของจริง และได้กราฟที่สวยกว่าไปพร้อมกัน |
| 2 | ปฏิทินวันทำงานไทย + เผื่อวันฝน | กระทบชั้นคำนวณเวลา ยิ่งทำช้ายิ่งแก้ยาก |
