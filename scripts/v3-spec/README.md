## สองความกว้าง ไม่ใช่ใบเดียว

`compare.mjs` กับ `overlay.mjs` ทำงานทั้ง **1280 และ 390** · กองที่สามต้องว่าง
**ทั้งสองใบ** ถึงจะพูดว่าบล็อกไหนเสร็จ

**ผืนมือถือเป็นคนละโครง ไม่ใช่ผืนเดสก์ท็อปที่ถูกบีบให้แคบ** นับคลาสในอาร์ตบอร์ด 390
แล้วไม่มี `.nl` `.nl-item` `.nl-icon` `.nl-tab` `.scp0` `.hcard` `.hline` เลยสักตัว ·
แบนเนอร์มือถือเป็น `.card` ไม่ใช่ `.card-hi` และไม่มีสไลด์ · นาฬิกาเป็นข้อความเดียว
ไม่ใช่สี่ช่อง · **ลำดับบล็อกก็ไม่ตรงกัน** ใบมือถือมีแถบประกาศบาง ๆ เป็นบล็อกแรก
ทุกอย่างจึงเลื่อนลงหนึ่ง

## เพิ่มบล็อกใหม่เข้าตัวเทียบ

แก้ `MAP` ใน `compare.mjs` เพิ่มบรรทัดละหนึ่งจุด

| ช่อง | ความหมาย |
|---|---|
| `canvas` | selector ในผืน **แยกต่อความกว้าง** เช่น `{ 1280: ".card-hi", 390: ".card" }` |
| `live` | selector ในหน้าจริง ใช้ตัวเดียวทั้งสองใบ เพราะหน้าจริงเป็น DOM เดียวที่เปลี่ยนด้วย CSS |
| `keys` | สิ่งที่ต้องเท่ากัน ไม่ใส่ = ทั้งกว้างและสูง |

**ไม่เขียนคีย์ของความกว้างไหน = ผืนใบนั้นไม่มีของชิ้นนี้** ซึ่งเป็นคำตอบที่ถูก ไม่ใช่ช่องที่ลืมกรอก
รายงานมีหัวข้อ "ผืนใบนี้ไม่มีของชิ้นนี้" แยกไว้ เพื่อไม่ให้แถวที่ข้ามหายไปเงียบ ๆ

ผืนกับโค้ดตั้งชื่อคนละแบบ ผืนใช้ `.nl` เราใช้ `.v3-nl` และของหลายชิ้นในผืนไม่มีคลาสเลย
เพราะเป็น inline style ล้วน · เปิด `out/canvas-1280.json` กับ `out/canvas-390.json` ดูก่อน
ว่ามีอะไรอยู่ตรงไหน

**จุดที่ต่างโดยตั้งใจ ต้องเข้าสมุดด้วยชื่อเดียวกับใน `MAP`** ไม่งั้นตัวเทียบรายงานเป็นบั๊กทุกรอบ

## สมุดข้อยกเว้นเน่าไม่ได้

**ทุกข้อต้องพิสูจน์ตัวเองได้ด้วยทางใดทางหนึ่ง ห้ามยืนยันด้วยประโยคเฉย ๆ** ประโยคยังยืนยันต่อไป
ในวันที่สิ่งที่มันอ้างถึงหายไปแล้ว ซึ่งเป็นการเน่าแบบเดียวกับข้อยกเว้นที่หมดอายุ แค่สูงขึ้นอีกชั้น

**ข้อยกเว้นผูกกับความกว้างด้วย** ช่อง `"widths"` บอกว่าข้อนั้นยกเว้นให้ที่ใบไหน ·
**ไม่เขียนไว้ = ยกเว้นเฉพาะ 1280** เพราะทุกข้อที่อยู่ในสมุดวันนี้เขียนขึ้นจากการวัดเดสก์ท็อปล้วน
ตอนที่ตัวเทียบยังมองไม่เห็น 390

รอบแรกที่ตัวเทียบเห็นสองความกว้าง มันยกเว้นข้ามใบให้ทันทีสามข้อ แล้วรายงานว่าแบนเนอร์มือถือ
ที่กว้างผิดไป 166 พิกเซล เป็น "ต่างแต่มีเหตุผล" โดยอ้างเหตุผลเรื่อง `align-items: stretch`
ของเดสก์ท็อป ซึ่งไม่ได้อธิบายอะไรเลยที่ความกว้างนั้น · **ข้อยกเว้นที่ยกเว้นให้เรื่องที่มัน
ไม่ได้พูดถึง อันตรายกว่าไม่มีข้อยกเว้น** เพราะมันกลบบั๊กจริงด้วยประโยคที่อ่านแล้วน่าเชื่อ

| ทาง | ความหมาย | ตัวเทียบล้มเมื่อ |
|---|---|---|
| ชื่ออยู่ใน `MAP` | วัดเป็นกล่องได้ | วัดแล้วไม่ต่างอีกแล้ว **ที่ความกว้างที่ข้อนั้นยกเว้นให้** แปลว่าเหตุผลตายไปแล้ว |
| `"checkedBy"` | มีตัวตรวจอยู่ที่อื่น เช่น `"motion.mjs"` หรือ `"compare.mjs:hitTarget"` | ไฟล์นั้นหายไป หรือตัวตรวจในตัวไม่ผ่าน |
| `"effectOf"` | เป็นผลของข้ออื่นในสมุด | ชื่อที่อ้างไม่มีในสมุดแล้ว หรือข้อนั้นวัดแล้วไม่ต่างแล้ว |
| `"dueWith"` + `"dueWhen"` | สัญญาว่าจะมีตัวตรวจตอนบล็อกนั้นลง | selector ใน `dueWhen` โผล่ในหน้าแล้ว แปลว่าครบกำหนด |
| `"unmeasured": true` | วัดไม่ได้จริง ๆ | ไม่มี `"unmeasuredWhy"` กำกับ |

`"dueWith"` มีเพื่อกันไม่ให้คำว่า "ตอนขั้นที่ 3" กลายเป็น "ไม่เคย" อย่างเงียบ ๆ
ซึ่งเป็นวิธีตายมาตรฐานของหนี้ทุกก้อน

## เหตุผลต้องพิสูจน์ได้ ไม่ใช่แค่ฟังดูน่าเชื่อ

**สมุดเน่าได้สองทาง** ทางแรกคือข้อที่เลิกต่างแล้ว ซึ่งตารางข้างบนจับได้ ·
**ทางที่สองคือข้อที่ยังต่างจริงแต่เหตุผลผิด** ซึ่งจับไม่ได้เลยด้วยตารางนั้น และอันตรายกว่า
เพราะข้อที่เหตุผลผิดจะพาคนไปแก้ผิดที่

เกิดขึ้นจริงแล้ว 2026-09-07 · สองข้อเขียนว่าต่างเพราะฟอนต์ พอเปลี่ยนฟอนต์ให้ตรงผืนแล้ว
ยังต่างเท่าเดิม เหตุจริงเป็นคนละเรื่อง

วิธีพิสูจน์คือ **การทดลองแทรกแซง** — ข้อไหนอ้างว่าต่างเพราะอะไร ต้องบอกมาว่าเปลี่ยน
สิ่งนั้นบนหน้าจริงอย่างไร แล้วช่องว่างต้องเปลี่ยนตาม · ถ้าเปลี่ยนแล้วช่องว่างเท่าเดิม
แปลว่าสิ่งที่มันชี้ไม่ใช่เหตุ ไม่ว่าประโยคจะเขียนไว้ดีแค่ไหน

```json
"provedBy": {
  "rules": [
    { "selector": ".v3-hslot__caption", "declare": "line-height: normal" },
    { "selector": ".v3-hslot__text", "declare": "row-gap: 0" }
  ],
  "expect": "ปิดช่องว่าง"
}
```

| `expect` | ผ่านเมื่อ |
|---|---|
| `ปิดช่องว่าง` | แทรกแซงแล้วเหลือต่างไม่เกินเกณฑ์ — เหตุนั้นอธิบายได้ทั้งหมด |
| `ช่องว่างขยับ` | แทรกแซงแล้วช่องว่างเปลี่ยน — เหตุนั้นมีส่วนจริง แต่ไม่ใช่ทั้งหมด |

เขียนกฎเดียวใช้ `selector` กับ `declare` ตรง ๆ ก็ได้ · **ตัวตรวจนี้ไม่บังคับทุกข้อ**
ข้อที่ไม่มี `provedBy` ยังผ่านได้ด้วยห้าทางเดิม เพราะบางข้อไม่ได้อ้างเหตุที่แทรกแซงได้
เช่นทะเบียนที่ยังว่าง · แต่ข้อไหนที่เขียน `provedBy` ไว้แล้วสอบตก คือข้อที่พูดผิด และต้องแดง

**มันจับได้จริง** ข้อ "ช่องสองบรรทัดในแถบบน" ตกสองรอบก่อนจะผ่าน รอบแรกอ้างความสูงบรรทัด
กฎเดียว ช่องว่างโตจาก 2.39 เป็น 10.2 รอบสองอ้างสองกฎ เหลือ 3 · ต้องวัดทีละบรรทัดจริง
จึงพบว่ามีสี่ตัวไม่ใช่สองตัว แล้วจึงปิดเหลือ 0

`hitTarget` เป็นตัวตรวจในตัวสำหรับเขตกดที่เป็น `::after` ซึ่งไม่โผล่ใน `getBoundingClientRect`
มันยิงสี่มุมของกล่องขนาดเกณฑ์ด้วย `elementFromPoint` แล้วดูว่าโดนปุ่มตัวเดิมไหม
ซึ่งตรงกับความหมายของเกณฑ์มากกว่าการอ่านตัวเลข `inset` — เป้ากดคือที่ที่กดแล้วโดน

ข้อยกเว้นที่หมดอายุคือรูของรั้ว ไม่ใช่บรรทัดที่ไม่มีพิษภัย · กฎเดียวกับที่
`palette-fence.test.ts` ใช้กับบัญชียกเว้นของมันเอง
