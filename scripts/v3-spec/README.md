# เครื่องมือเทียบหน้าแรกรุ่นสามกับผืนออกแบบ

**นิยามของคำว่าบล็อกเสร็จอยู่ที่นี่** — กอง "ต่างโดยไม่มีใครรู้" ของ `compare.mjs`
ต้องว่างก่อนจะบอกว่าบล็อกไหนเสร็จ ไม่ใช่ตรวจตอนท้ายรวบเดียว

เครื่องมือชุดนี้ **commit เข้าเรพอ** เหมือนสคริปต์อีกยี่สิบสองตัวใน `scripts/`
แต่ไม่ผูกใน `package.json` ไม่เข้า `devDependencies` และไม่อยู่ในชุดเทสต์
`numeric-font-fence.test.ts` เขียนไว้เองว่าการวัดในเบราว์เซอร์เป็นงานตอนตรวจ ไม่ใช่งานของด่าน

**สมุดข้อยกเว้นอยู่คนละที่** — `docs/design/v3-deliberate-differences.json`
เพราะเป็นคำตัดสิน ไม่ใช่เครื่องมือ

## ต้องมีอะไรก่อน

- `pnpm dev` ที่ `:3000`
- `node scripts/v3-spec/serve-canvas.mjs` ค้างไว้ที่ `:4173`
- `npx playwright@1.63.0` — เรียกผ่าน npx ทุกครั้ง ไม่ติดตั้งเข้าโปรเจกต์ ·
  ใช้ Edge ที่ติดตั้งในเครื่องผ่าน `channel: "msedge"` ไม่ดาวน์โหลด Chromium

## ลำดับการใช้

```
node scripts/v3-spec/serve-canvas.mjs     # เสิร์ฟผืนที่ :4173 — ค้างไว้
node scripts/v3-spec/extract-canvas.mjs   # ถอดผืนเป็น out/canvas-1280.json และ 390
node scripts/v3-spec/compare.mjs          # เทียบสามกอง + ตรวจว่าสมุดยังไม่เน่า
node scripts/v3-spec/overlay.mjs          # ถ่ายภาพผืนกับหน้าจริง แล้วซ้อนแบบ difference
node scripts/v3-spec/motion.mjs           # ตรวจว่าสไลด์หยุดหมุนถูกกรณี
node scripts/v3-spec/measure-home.mjs     # วัดหน้าจริงอย่างเดียว พร้อมคอนทราสต์
```

`compare.mjs` กับ `motion.mjs` คืนรหัสออก 1 เมื่อมีอะไรไม่ผ่าน จึงใส่ในลูกโซ่คำสั่งได้

## เพิ่มบล็อกใหม่เข้าตัวเทียบ

แก้ `MAP` ใน `compare.mjs` เพิ่มบรรทัดละหนึ่งจุด — `canvas` คือ selector ในผืน
`live` คือ selector ในหน้าจริง `keys` คือสิ่งที่ต้องเท่ากัน (ไม่ใส่ = ทั้งกว้างและสูง)

ผืนกับโค้ดตั้งชื่อคนละแบบ ผืนใช้ `.nl` เราใช้ `.v3-nl` และของหลายชิ้นในผืนไม่มีคลาสเลย
เพราะเป็น inline style ล้วน · เปิด `out/canvas-1280.json` ดูก่อนว่ามีอะไรอยู่ตรงไหน

**จุดที่ต่างโดยตั้งใจ ต้องเข้าสมุดด้วยชื่อเดียวกับใน `MAP`** ไม่งั้นตัวเทียบรายงานเป็นบั๊กทุกรอบ

## สมุดข้อยกเว้นเน่าไม่ได้

**ทุกข้อต้องพิสูจน์ตัวเองได้ด้วยทางใดทางหนึ่ง ห้ามยืนยันด้วยประโยคเฉย ๆ** ประโยคยังยืนยันต่อไป
ในวันที่สิ่งที่มันอ้างถึงหายไปแล้ว ซึ่งเป็นการเน่าแบบเดียวกับข้อยกเว้นที่หมดอายุ แค่สูงขึ้นอีกชั้น

| ทาง | ความหมาย | ตัวเทียบล้มเมื่อ |
|---|---|---|
| ชื่ออยู่ใน `MAP` | วัดเป็นกล่องได้ | วัดแล้วไม่ต่างอีกแล้ว แปลว่าเหตุผลตายไปแล้ว |
| `"checkedBy"` | มีตัวตรวจอยู่ที่อื่น เช่น `"motion.mjs"` หรือ `"compare.mjs:hitTarget"` | ไฟล์นั้นหายไป หรือตัวตรวจในตัวไม่ผ่าน |
| `"effectOf"` | เป็นผลของข้ออื่นในสมุด | ชื่อที่อ้างไม่มีในสมุดแล้ว หรือข้อนั้นวัดแล้วไม่ต่างแล้ว |
| `"dueWith"` + `"dueWhen"` | สัญญาว่าจะมีตัวตรวจตอนบล็อกนั้นลง | selector ใน `dueWhen` โผล่ในหน้าแล้ว แปลว่าครบกำหนด |
| `"unmeasured": true` | วัดไม่ได้จริง ๆ | ไม่มี `"unmeasuredWhy"` กำกับ |

`"dueWith"` มีเพื่อกันไม่ให้คำว่า "ตอนขั้นที่ 3" กลายเป็น "ไม่เคย" อย่างเงียบ ๆ
ซึ่งเป็นวิธีตายมาตรฐานของหนี้ทุกก้อน

`hitTarget` เป็นตัวตรวจในตัวสำหรับเขตกดที่เป็น `::after` ซึ่งไม่โผล่ใน `getBoundingClientRect`
มันยิงสี่มุมของกล่องขนาดเกณฑ์ด้วย `elementFromPoint` แล้วดูว่าโดนปุ่มตัวเดิมไหม
ซึ่งตรงกับความหมายของเกณฑ์มากกว่าการอ่านตัวเลข `inset` — เป้ากดคือที่ที่กดแล้วโดน

ข้อยกเว้นที่หมดอายุคือรูของรั้ว ไม่ใช่บรรทัดที่ไม่มีพิษภัย · กฎเดียวกับที่
`palette-fence.test.ts` ใช้กับบัญชียกเว้นของมันเอง
